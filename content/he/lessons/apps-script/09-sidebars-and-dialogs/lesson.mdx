# Sidebars ו-modal dialogs (HtmlService)

Custom functions חיות בתאים. Triggers יורים על events. **Sidebars** ו-**modal dialogs** הם משטח ה-UI השלישי: פאנלים מלאים של HTML מעוגנים ל-workbook, מתארחים על ידי Apps Script דרך ה-API של `HtmlService`. הם מאפשרים לבנות forms, אשפים רב-שלביים, dashboards, וזרימות אישור שחיות לצד הרשת ולא בתוכה.

השיעור הזה מכסה שלושה דברים: שלוש הדרכים לרנדר HTML בתוך Sheets (sidebar, modal, modeless), איך לבנות `HtmlOutput` מקובץ או ממחרוזת, ומודל ה-sandbox שמגביל מה ה-HTML שלכם יכול לעשות. בפעם הראשונה שאתם בונים sidebar אתם מגלים את חוקי ה-iframe (אין נתיבים יחסיים, CSP דביק, אין גישה ישירה לתאים) ומבזבזים שעה. השיעור הזה מעלה את החוקים האלה מראש.

שלוש צורות שאותו פלט HtmlService יכול לקבל:

| Method | מה הוא מפיק |
|---|---|
| `showSidebar(html)` | פאנל מתמיד ברוחב 300px מעוגן בצד ימין של הרשת. המשתמש יכול להמשיך לערוך את ה-sheet בזמן שה-sidebar פתוח. |
| `showModalDialog(html, title)` | חלון צף מרוכז. חוסם את שאר ה-sheet עד שסוגרים אותו. משתמשים ב-confirms ו-inputs של one-step. |
| `showModelessDialog(html, title)` | חלון צף מרוכז שלא חוסם את ה-sheet. פחות נפוץ; שימושי ל-inspectors שמתעדכנים בזמן שהמשתמש זז. |

כל השלושה נקראים על `SpreadsheetApp.getUi()`. כל השלושה מקבלים `HtmlOutput` שנבנה על ידי `HtmlService`.

## בניית HtmlOutput

שתי דרכים לבנות את הפלט:

```js
// מקובץ ב-Apps Script project. הכי נפוץ: שומר HTML
// נפרד מ-JS, מקבל הדגשת syntax בעורך.
const html = HtmlService.createHtmlOutputFromFile("Reports");

// ממחרוזת inline. שימושי ל-prompts מהירים של one-off; לא מתרחב.
const html = HtmlService.createHtmlOutput("<h2>Report</h2><p>...</p>");
```

הארגומנט ל-`createHtmlOutputFromFile` הוא **שם הקובץ כפי שמוצג בעורך Apps Script**, לא שם הקובץ בדיסק. העורך שומר קבצי HTML עם סיומת `.html` אוטומטית; אתם מפנים אליהם בלעדיה. `"Reports"` בקוד, `Reports.html` בבוחר הקבצים.

ואז משרשרים על הפלט כדי להגדיר את ה-title וה-dimensions:

```js
const html = HtmlService.createHtmlOutputFromFile("Reports")
  .setTitle("Reports")
  .setWidth(300)  // dialogs בלבד: sidebars מתעלמים מזה ותמיד 300px
  .setHeight(400); // dialogs בלבד
```

`setTitle` היא התווית הנראית בראש ה-sidebar או dialog. דילוג עליה והפאנל עדיין עובד, אבל הכותרת נקראת ריקה.

## הערה על ה-sidebar של הקורס הזה

ה-Apps Script project של הקורס הזה כבר כולל קובץ HTML שמור בשם `Sidebar`: זה ה-shell שמארח את ה-companion בתוך ה-sheet שאתם קוראים עכשיו. אתם לא יכולים להשתמש ב-`"Sidebar"` כשם קובץ לעבודה שלכם בשיעור הזה: ה-provisioner ישחרר בשקט כל seed file עם השם הזה, ו-`createHtmlOutputFromFile("Sidebar")` היה מכוון ל-shell של הקורס, לא לקוד שלכם. הקטע המעשי משתמש ב-**`"Reports"`** במקום. מחוץ לקורס הזה, ב-workbook שלכם, אתם יכולים לתת לקובץ HTML שלכם איזה שם שאתם רוצים.

## ה-sandbox

ה-HTML שאתם טוענים רץ בתוך **iframe** מוגש מ-`googleusercontent.com`, לא מ-domain ה-workbook שלכם. יש לזה כמה השלכות ששווה לדעת לפני שכותבים sidebar מורכב:

- **`<base target="_top">` שייך לכל `<head>`.** בלעדיו, לינקים בתוך ה-sidebar נפתחים בתוך ה-iframe (ושוברים, כי ה-iframe מבודד). איתו, הם נפתחים ב-tab של ה-parent. כל template של HtmlService ש-Google שולחת מתחיל עם ה-tag הזה.
- **אין גישה ישירה ל-spreadsheet מתוך ה-HTML.** ה-HTML לא יכול לקרוא או לכתוב תאים, לא יכול לקרוא ל-`SpreadsheetApp`. כדי לעשות את הדברים האלה, ה-JS בצד הלקוח קורא חזרה ל-server של Apps Script דרך `google.script.run`.
- **`position: fixed` ו-`position: sticky` לא עובדים** כמו שאתם מצפים בתוך ה-sandbox. הם מתנהגים כמו static positioning. אם אתם רוצים footer דביק, משתמשים ב-`position: absolute` בתוך container relatively-positioned שממלא את גובה ה-iframe.
- **משאבים חיצוניים כפופים ל-Content Security Policy של ה-iframe.** אתם יכולים לקשר ל-CDN של stylesheet או font ממארח CSP-allowed (Google Fonts עובד; CDNs שרירותיים אולי לא). `<style>` inline ו-`<script>` inline עובדים בסדר.
- **URLs יחסיים לשרת שלכם לא נפתרים.** ה-origin של ה-iframe הוא של Google, לא שלכם. תמונות, fonts, ו-scripts שאתם "מארחים" עובדים רק אם הם מוגשים מ-URL מוחלט https.

## קריאות client-to-server (preview)

קובץ ה-HTML יכול לכלול בלוקי `<script>`. כדי לקרוא חזרה לקוד ה-`.gs` שלכם, משתמשים ב-`google.script.run`:

```html
<script>
  function refresh() {
    google.script.run
      .withSuccessHandler(function(spend) {
        document.getElementById("spend").innerText = spend;
      })
      .getTodaysSpend();
  }
  refresh();
</script>
```

`getTodaysSpend` היא function שמוצהרת ברמת ה-top של כל קובץ `.gs` בפרויקט. Apps Script מגשר על הקריאה מעבר לגבול ה-sandbox. אנחנו מזכירים את זה כאן כי רוב ה-sidebars שאינם טריוויאליים צריכים את זה; Track מאוחר יותר מכסה את מחזור החיים המלא של client-server.

## מתי לפנות לאיזו צורה

- **Sidebar**: זרימות רב-שלביות, UI מתמיד שהמשתמש רוצה לשמור פתוח בזמן עבודה ברשת. ה-"Campaign builder" של הצוות הוא sidebar: שדות form מלווים את ה-buyer דרך מתן שם לקמפיין חדש, בחירת vertical מהרשימה הקנונית, בחירת פלטפורמה, יצירת מחרוזת שם הקמפיין. הוא נשאר פתוח בין עריכות sheet.
- **Modal dialog**: confirms של one-shot ו-inputs של one-step. "Bulk-archive 47 paused campaigns? [Cancel] [Archive]." הטבע החוסם הוא ה-feature: הוא מונע מהמשתמש ללחוץ במקום אחר באמצע אישור.
- **Modeless dialog**: נדיר. פאנלי inspector שמתעדכנים על בחירה הם השימוש העיקרי. בפועל, sidebars מטפלים ברוב אותן עבודות בצורה אלגנטית יותר.

ה-starter project יש שני קבצים לעריכה:

1. **`Lesson.gs`**: מצהיר על `showReportsSidebar()` עם body ריק. ממלאים אותו כך שיעשה:
   - בונה `HtmlOutput` מקובץ ה-HTML `Reports` של הפרויקט באמצעות `HtmlService.createHtmlOutputFromFile("Reports")`.
   - מגדיר את ה-title של הפאנל ל-`"Reports"` עם `.setTitle("Reports")`.
   - פותח אותו עם `SpreadsheetApp.getUi().showSidebar(html)`.
2. **`Reports.html`**: כרגע stub עם פסקת placeholder. מחליפים את ה-stub במarkup אמיתי: כותרת (`<h2>Spend report`), פסקה שמזכירה מה הפאנל מציג. שומרים את ה-`<base target="_top">` ב-head.

שומרים את הפרויקט. עוברים חזרה ל-sheet. מהעורך Apps Script, מריצים `showReportsSidebar` פעם אחת. הריצה הראשונה מבקשת auth על UI scope; מקבלים אותו. אחרי זה, ה-sidebar נפתח מיד בכל ריצה.

ה-grader בודק: ה-function קיימת, ה-body של ה-function משתמש ב-HtmlService נכון עם שם הקובץ `"Reports"`, קובץ ה-HTML של Reports קיים עם body אמיתי וכותרת, והקובץ מפנה ל-`"Reports"` (לא לשם ה-shell השמור `"Sidebar"`) ב-`createHtmlOutputFromFile`.

## נפוץ בשטח

שני patterns מהצוות:

- **Campaign builder sidebar.** form רב-שלבי: בוחרים את ה-buyer, בוחרים את ה-vertical מרשימת PR הקנונית, בוחרים את הפלטפורמה, בוחרים את המדינה, בוחרים את סוג הקמפיין (`permax`, `rsoc`, `s1d`, `tc`). ב-submit, ה-sidebar קורא ל-server function שבונה את מחרוזת שם הקמפיין מהחלקים ומוסיף שורה חדשה ללוג הקמפיינים. ה-form המלא חי ב-`Sidebar.html` (ב-workbook שלהם, לא של הקורס הזה: הם לא משתפים את השם השמור) וההוספה של שורה בצד השרת היא ב-`Code.gs`.
- **Bulk-archive confirm dialog.** כשה-buyer בוחר 50+ שורות ולוחץ "Archive selected", modal dialog נפתח עם ספירת השורות, טווח התאריכים, וה-spend הכולל המכוסה. שני כפתורים: Cancel ו-Archive. התנהגות חוסמת קריטית כאן: בחירת השורות שורדת את ה-modal, כך שהמשתמש לא יכול לאבד את ההקשר באמצע אישור.

## מלכודות מקצועיות

- **ה-tab של ה-sidebar לא שורד reload.** מרעננים את ה-workbook וה-sidebar נסגר בשקט. אם יש לכם רשומת "Show sidebar" בתפריט מותאם, המשתמש פשוט לוחץ שוב. לא שמים state קריטי ב-sidebar: שומרים אותו בתאים או ב-`PropertiesService` (שיעור 15) של ה-script כך ש-reload לא יאבד אותו.
- **modal dialogs חוסמים את כל ה-sheet.** אין עריכה, אין גלילה, אין לחיצה במקום אחר עד שהמשתמש סוגר את ה-dialog. משתמשים בהם במשורה: הם שוברים זרימה אם משתמשים בהם בכל דבר מעבר ל-confirm של one-step.
- **`setTitle` על sidebar היא הכותרת הנראית בראש הפאנל.** אם מגדירים אותה למחרוזת ריקה, הכותרת ריקה אבל לפאנל עדיין יש top bar.
- **שם הקובץ של HTML רגיש לרישיות.** `createHtmlOutputFromFile("reports")` לא מוצא את `Reports.html`. בוחר הקבצים של העורך מציג את הרישיות הקנונית.
- **נתיבים יחסיים לא עובדים לתמונות ו-fonts.** ה-iframe מוגש מ-`googleusercontent.com`, לא מ-domain ה-workbook שלכם. משתמשים ב-URLs מוחלטים https למארח שאתם שולטים בו.
- **`position: fixed` מתעלמים ממנו בשקט בתוך ה-iframe.** footers דביקים ו-toolbars צריכים markup שונה: בדרך כלל flex container עם `flex-direction: column` ו-footer שלוקח את הגובה הטבעי שלו בתחתית.
- **scripts חיצוניים פוגעים בקיר ה-CSP.** `<script src="https://some-cdn/jquery.js">` יכול להיטען (Google Fonts מורשה; חלק מה-CDNs לא): זה תלוי ב-allowlist של Google, שמשתנה. ה-pattern החזק: inline את ה-JS שאתם צריכים, או לוקחים אותו לתוך בלוק ה-`<script>` של קובץ ה-HTML.
- **ל-Sidebar HTML אין גישה לתאים.** אתם לא יכולים לכתוב `document.getElementById("a1").innerText = spreadsheet.getRange("A1").getValue()`. קריאות וכתיבות עוברות דרך `google.script.run` מהלקוח חזרה ל-`.gs` function. ה-sandbox הוא הקיר.
- **שם הקובץ השמור `"Sidebar"` בקורס הזה.** אם תשימו `"Sidebar"` ב-`createHtmlOutputFromFile(...)`, או תקבלו את ה-shell של הקורס (לא את הקוד שלכם) או שגיאת "file not found" אם ה-shell לא מקושר. הקטע המעשי משתמש ב-`"Reports"` כדי להימנע מההתנגשות.
- **`google.script.run` exceptions בצד השרת הופכים לכשלים שקטים בצד הלקוח.** תמיד מצמידים `.withSuccessHandler(fn)` עם `.withFailureHandler(err => console.error(err))` כך שהלקוח ידע כשה-function בצד השרת זורקת.
