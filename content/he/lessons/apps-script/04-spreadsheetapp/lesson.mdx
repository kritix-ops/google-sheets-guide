# SpreadsheetApp: קריאה וכתיבה ל-workbook מתוך הקוד

שיעור 3 הראה איך custom function קוראת את הארגומנטים שלה מתא. זה המסלול הזול והמהיר: ה-function לא יודעת כלום על שאר ה-workbook ולא יכולה לכתוב חזרה. ברגע שצריכים לעדכן תאים, להעתיק ערכים בין tabs, או לעבור על גיליון שלם, יוצאים מה-sandbox של custom function ועוברים לעבוד ישירות מול **`SpreadsheetApp`**. זה השירות ששאר Track 3 נשען עליו עבור menus, macros ו-triggers, אז הצורה של ה-API שלו ומודל הביצועים שלו חשובים.

המודל המנטלי: `SpreadsheetApp` הוא עץ של שלושה סוגי objects. יורדים מה-spreadsheet (הקובץ), ל-sheet (tab אחד), לטווח (מלבן של תאים). כל method שאתם קוראים שולח בקשה לשרתי Google, אז ההרגלים מודעי-העלות שאתם בונים בשיעור הזה רלוונטיים כל הדרך עד ל-playbook של ה-batching בשיעור 16. ה-trigger הלילי של 50,000 שורות וה-auto-fill של on-edit על 5 תאים נכתבים באותה צורה: מנווטים לטווח הנכון, קוראים או כותבים פעם אחת.

## ההיררכיה של שלושת ה-objects

`SpreadsheetApp` היא נקודת הכניסה. קריאה אליה מחזירה objects במורד העץ:

```js
const ss     = SpreadsheetApp.getActiveSpreadsheet(); // Spreadsheet (כל הקובץ)
const sheet  = ss.getSheetByName("Campaigns");         // Sheet (tab אחד)
const range  = sheet.getRange("F2:F61");               // Range (מלבן של תאים)
const values = range.getValues();                      // מערך דו-ממדי של CellValue
```

| Object | מה הוא מייצג | מה עושים איתו |
|---|---|---|
| `Spreadsheet` | כל הקובץ (זה שיש לו URL ב-Drive). | מציגים sheets, מוסיפים sheet, מגדירים את שם ה-spreadsheet. |
| `Sheet` | tab אחד בקובץ. | מקבלים את כמות השורות, freeze rows, קובעים את ה-active sheet, מקבלים range מה-tab הזה. |
| `Range` | מלבן של תאים ב-sheet. | קוראים או כותבים ערכים, קובעים פורמט מספרי, מיישמים conditional formatting, מנקים תוכן. |

לערבב ביניהם זו הטעות הראשונה של מתחילים. `sheet.setValue(...)` לא קיים; רק ל-`Range` יש `setValue`. `range.getSheetByName(...)` גם לא קיים; `getSheetByName` שייך ל-`Spreadsheet`. הודעת השגיאה ("TypeError: sheet.setValue is not a function") מצביעה על ה-object הלא נכון, לא על הלוגיקה השגויה.

## קריאה וכתיבה של תא אחד

ה-round-trip הקטן ביותר האפשרי:

```js
const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName("Campaigns");
const cell  = sheet.getRange("J1");
cell.setValue(12345);            // כותב
const back = cell.getValue();    // קורא, מחזיר 12345
```

שתי עובדות שיעקצו אתכם בהמשך:

1. **כל קריאת method הולכת לשרתי Google.** Apps Script לא רץ מקומית ליד ה-spreadsheet שלכם. ה-script חי על תשתית של Google, ה-spreadsheet חי על תשתית של Google, וכל `getValue` / `setValue` הוא קריאת רשת ביניהם. פר-תא על מאה תאים זה מאה round-trips. על אלף זה freeze מורגש.
2. **`getValue()` מחזיר את מה שיש בתא.** מספרים חוזרים כמספרי JS, מחרוזות כמחרוזות, תאריכים כ-`Date` objects, booleans כ-booleans, תאים ריקים כמחרוזת ריקה. האחרון זה ההפתעה: תא ריק הוא `""`, לא `null` או `undefined`.

## batch reads ו-writes

הדרך הנכונה לקרוא או לכתוב יותר מתא אחד בבת אחת היא להשיג **`Range`** שמכסה את כולם ולהשתמש בצורות הרבים:

```js
const range  = sheet.getRange("F2:F61");      // 60 תאים, עמודה F
const values = range.getValues();              // round-trip אחד
// values הוא מערך דו-ממדי בצורת [60][1]:
// [[412.5], [285.3], [612.0], ...]

let total = 0;
for (const row of values) total += row[0];

sheet.getRange("J1").setValue(total);          // round-trip אחד
```

זהו. שני round-trips לעשות את העבודה של 120 (`getValue` × 60 קריאות + `setValue` × 60 כתיבות אם הייתם כותבים את זה בצורה הנאיבית). על sheet עם 50,000 שורות, ההבדל הוא script שמסיים תוך שלוש שניות מול timeout בשש דקות.

## `getRange` וה-overloads שלו

`getRange` מקבל או מחרוזת A1 או ארבעה מספרים שלמים:

```js
sheet.getRange("F2:F61");        // צורת A1
sheet.getRange(2, 6, 60, 1);     // (startRow, startCol, numRows, numCols)
```

שניהם מתייחסים לאותה חתיכה של 60 תאים בעמודה. **הצורה של המספרים השלמים היא 1-indexed.** `getRange(2, 6, ...)` מתחיל בשורה 2, עמודה 6 (F). המוסכמה של 1-indexed תואמת לאותיות העמודה בכתובות התאים (A = 1, B = 2, ...) אבל היא לא תואמת לשאר JavaScript, שבו מערכים הם 0-indexed. טעות נפוצה היא לכתוב `sheet.getRange(0, 0, ...)` ולקבל exception על range לא חוקי.

הצורה של ארבעת המספרים השלמים משתלמת כשמחשבים את הגבולות באופן דינמי:

```js
const lastRow = sheet.getLastRow();             // השורה האחרונה שיש בה תוכן
const lastCol = sheet.getLastColumn();          // העמודה האחרונה שיש בה תוכן
const all = sheet.getRange(2, 1, lastRow - 1, lastCol).getValues();
```

זה קורא כל תא מאוכלס חוץ מה-header ב-round-trip אחד. ה-function של האגרגטור הלילי של הצוות היא בדיוק בצורה הזו: `getValues()` אחד פר-tab מקור, מנרמלים ומחברים בזיכרון JavaScript, `setValues()` אחד ל-tab הפלט.

## `getLastRow`, `getLastColumn`, ומלכודת השורות הריקות הנגררות

`getLastRow()` מחזיר את מספר השורה של התא האחרון שיש בו תוכן כלשהו. המלכודת: "יש בו תוכן" דביק. אם אי פעם הקלדתם משהו לשורה 5000 ומחקתם, ה-sheet זוכר, ו-`getLastRow()` יכול להחזיר 5000 גם כשהנתונים הנראים מסתיימים בשורה 200.

שתי דרכים שבהן זה עוקץ:

```js
// אתם מצפים ל-60 שורות נתונים אבל ה-sheet "זוכר" שורה 5000 ישנה:
const range = sheet.getRange(2, 1, sheet.getLastRow() - 1, 7);
const values = range.getValues();
// values עכשיו הוא 4999 שורות, רובן [""].
```

התיקון הוא אחד מהשניים:

1. **קוראים את עמודת הנתונים האמיתית כדי למצוא את השורה האחרונה האמיתית שלה** (למשל, סורקים את עמודה A לתא הלא-ריק האחרון), או
2. **מקצצים שורות ghost על ידי בחירה שלהן, קליק ימני ואז Delete rows.** זה באמת מסיר אותן מספירת השורות של ה-sheet, לא רק מנקה אותן.

ב-workbook מרובה-sheets שמושך נתונים דרך `IMPORTRANGE` מ-workbook שותף, `getLastRow` ב-sheet המייבא יכול להחזיר יותר ממה ש-IMPORTRANGE הפיק אם ה-sheet היעד היה גדול יותר בעבר. תמיד מאמתים מול עמודת הנתונים שאתם באמת מעוניינים בה, לא מול `getLastRow()` לבד.

## function שנייה מעובדת: לתייג שורות עם המייל של העורך

צורה שונה מהדוגמה של סכימת ה-spend: לכתוב עמודת ערכים שמחושבת מעמודה אחרת, פלוס ערך runtime (המייל של המשתמש הפעיל). זה אותו pattern שה-trigger של on-edit של הצוות משתמש בו כדי לחתום את העורך של כל שורת קמפיין חדשה, רק ארוז כפעולה ידנית של one-shot כאן.

```js
function tagEditorOnEachRow() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName("Campaigns");
  const editor = Session.getActiveUser().getEmail();
  const lastRow = sheet.getLastRow();
  if (lastRow < 2) return;                                  // אין שורות נתונים
  const buyers = sheet.getRange(2, 2, lastRow - 1, 1).getValues();  // עמודה B
  const tags = buyers.map(function(row) {
    return [row[0] ? row[0] : editor];                       // ברירת מחדל לעורך
  });
  sheet.getRange(2, 11, tags.length, 1).setValues(tags);    // כותבים לעמודה K
}
```

ארבעה חלקים ששווה להוציא:

| חלק | מה זה עושה |
|---|---|
| `Session.getActiveUser().getEmail()` | קורא את המייל של המשתמש שמריץ. ב-custom function זה היה ריק (cell-context auth צר מדי); מ-handler של menu או trigger זה מחזיר את הכתובת. |
| הבדיקה `lastRow < 2` | מונעת `getRange(2, 2, -1, 1)`, שזורק. תמיד בודקים לפני חישוב מימדי range מספירת שורות. |
| `.map(row => [row[0] ? row[0] : editor])` | map על המערך הדו-ממדי ומפיק מערך דו-ממדי באותה צורה. כתיבה לתא יחיד דורשת `[value]`, לא `value`. |
| `setValues(tags)` עם צורה תואמת | Range הוא `lastRow - 1` שורות × עמודה אחת; `tags` תואם את הצורה הזו. צורות שלא תואמות זורקות "The number of rows in the data does not match the number of rows in the range". |

ה-function הזו עובדת רק כשקוראים לה מ-menu item או מ-trigger, לא מתא. מתא, `Session.getActiveUser()` מחזיר משתמש ריק ו-`setValues` אסור. שיעור 5 מכסה menus, שיעור 7 מכסה triggers.

## נפוץ בשטח

ה-function של האגרגטור הלילי של הצוות היא הדוגמה הקנונית:

```js
function aggregateNightly() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const sources = ["Taboola raw", "Outbrain raw", "MediaGo raw", "TikTok raw"];
  const rows = [];
  for (const name of sources) {
    const sheet = ss.getSheetByName(name);
    const lastRow = sheet.getLastRow();
    if (lastRow < 2) continue;
    const data = sheet.getRange(2, 1, lastRow - 1, 8).getValues();
    for (const row of data) rows.push([...row, name]);  // תיוג עם פלטפורמה
  }
  const out = ss.getSheetByName("Aggregator");
  out.getRange(2, 1, rows.length, rows[0].length).setValues(rows);  // כתיבה אחת
}
```

ארבע קריאות `getValues()` (אחת פר-מקור) פלוס קריאת `setValues()` אחת סך הכל. חמישה round-trips, בלי קשר לכמה שורות יש למקורות יחד, 100 או 100,000. גרסה של זה שנכתבה תא-תא הייתה עושה timeout ברגע שהנתונים חצו בערך 20,000 שורות.

אותה צורה מופיעה ב:

- **המאקרו "copy from staging to production"** שה-buyer לוחץ עליו בימי שני אחרי סקירת נתוני סוף השבוע.
- **ה-batch job של מנרמל ה-verticals** שקורא כל שם קמפיין, מקצץ whitespace, מתקן casing, מוודא את הסיומת ` PR`, וכותב את הערכים הנקיים בחזרה.
- **הארכוב של סוף החודש** שמעתיק את ה-tab של Aggregator של החודש הנוכחי ל-sheet גיבוי שמתויג בתאריך.
- **מיגרציית ה-`IMPORTRANGE`-replacement** (שיעור 1.27 מכסה את החלופה החיה שהצוות עובר ממנה), כש-workbook עם `IMPORTRANGE` איטי ממקור של 100k שורות עובר ל-pull יומי של Apps Script: `getValues` אחד מהמקור, `setValues` אחד למראה המקומית, וה-dashboard קורא מהמקומית לשאר היום.

## מלכודות מקצועיות

- **`getValues` מחזיר `Date` objects לתאי תאריך, לא מחרוזות.** אם אז עושים `setValues` של אותו מערך חזרה ל-sheet אחר וה-format של תא היעד הוא "טקסט רגיל", התאריך מגיע בצורת ה-`toString()` של JS Date (`"Tue May 11 2026 00:00:00 GMT+0300"`), לא ה-`2026-05-11` המקורי. מפרמטים את עמודת היעד כתאריך קודם, או ממירים עם `Utilities.formatDate(...)` לפני הכתיבה.
- **off-by-one עם `getLastRow`.** רוצים את כל שורות הנתונים חוץ מה-header? זה `getRange(2, 1, lastRow - 1, lastCol)`. ה-`- 1` הוא כאב הראש. שוכחים אותו והשורה האחרונה נכללת פעמיים עם שורה ריקה בתחתית הפלט שלכם.
- **`setValue` עם מערך מציב בשקט את צורת המחרוזת של המערך בתא אחד.** תא בסוף קורא `"412.5,285.3,612"`. ה-method שרציתם הוא `setValues` (רבים), והצורה של המערך חייבת להתאים למימדי ה-range.
- **`setValues` שנכשל עם "The number of rows in the data does not match".** הצורה של המערך הדו-ממדי והצורה של ה-range לא תואמות. כותבים את המימדים הצפויים של ה-range בהערה ליד הקריאה (`// expects 60x1`); ה-bug מתגלה מהר יותר.
- **`SpreadsheetApp.getActive()` מחזיר `null` בתוך custom function.** custom functions רצות ב-auth context מצומצם שאין לו גישה ל-spreadsheet הפעיל לכתיבה. ה-exception שאתם רואים מטעה; התיקון הוא להעביר את הקוד ל-function רגילה שנקראת מ-menu או trigger.
- **שורות מקור של `IMPORTRANGE` שמשתנות מתחת ל-script שלכם.** אם ה-script קורא את `Aggregator!A2:H` והתוכן של אותו sheet מגיע מ-`IMPORTRANGE`, ספירת השורות יכולה לזוז בין הרגע שאתם קוראים `getLastRow()` לרגע שאתם קוראים `getValues()`. לקריאות קריטיות, לוקחים snapshot אחד של `getValues()` בראש ה-function ועובדים מה-snapshot.
- **שורות ghost נסתרות מעריכות עבר שמנפחות את `getLastRow`.** שורה 5000 שפעם היה לה תוכן (שמאז נמחק) שומרת את `getLastRow` להחזיר 5000. או מוחקים את השורות באמת (קליק ימני → Delete rows) או סורקים עמודת נתונים ספציפית לגבול האמיתי.
- **References בין tabs שנשברות בשינוי שם.** `ss.getSheetByName("Taboola raw")` מחזיר `null` אם ה-tab שונה ל-`"Taboola"`. תמיד בודקים את ההחזרה מול null לפני שקוראים methods נוספים עליה; אחרת השורה הבאה זורקת "Cannot read property 'getRange' of null".
