# Custom functions: כתיבה, שמות, ו-metadata להשלמה אוטומטית

שני השיעורים הקודמים כיסו את עורך Apps Script ואת מודל ההרצה. עכשיו תכתבו קוד שרץ מתוך ה-spreadsheet עצמו. **custom function** היא function ב-JavaScript שמוגדרת בפרויקט המקושר, ושה-spreadsheet יכול לקרוא לה מתא בדיוק כמו `=SUM` או `=VLOOKUP`. נותנים לה שם, שולחים פעם אחת, ומאותו רגע כל תא ב-workbook יכול לפנות לאותה לוגיקה.

ה-workbooks של הצוות בעולם האדטק נשענים על custom functions כל הזמן: המרת USD ל-ILS לפי שער היום, נרמול שמות vertical (משמעת הסיומת ` PR`), bucketing של ROI (`"loss"` / `"flat"` / `"profitable"` / `"hero"`), מיפוי country code לאזור. הגדרה אחת של function; שלושים נוסחאות שונות שקוראות לה. ברגע שכלל עסקי משתנה (אזור חדש משיק, ספי ה-bucket זזים) עורכים שורה אחת ב-`Code.gs` וכל תא שתלוי בה קולט את ההתנהגות החדשה ב-recalc הבא.

השיעור הזה מכסה ארבעה דברים: הצורה ש-Apps Script מקבל כ-custom function, ה-JSDoc שמחבר אותה ל-tooltip של autocomplete של התא, איך ארגומנטים של טווח מגיעים ל-body של ה-function, וחוזה ה-caching שמפתיע כל לומד בפעם הראשונה שהוא פונה ל-`new Date()`. הסעיף האחרון מגדיר את הגבול: דברים ש-custom functions לא יכולות לעשות, ולמה.

## הצורה

custom function היא function ברמה העליונה ב-`Code.gs` (או בכל קובץ `.gs` בפרויקט):

```js
function usdToILS(usd, rate) {
  return usd * rate;
}
```

זהו. שומרים את הפרויקט. עכשיו בכל תא אפשר להקליד:

```
=usdToILS(F2, $K$1)
```

שם ה-function בתא תואם ל-JS identifier. רישיות לא משנה בתא: `=USDTOILS(...)` עובד גם הוא. אבל הצהרת ה-JS רגישה לרישיות. `function USDtoILS` ו-`function usdToILS` הן שתי functions שונות מבחינת העורך.

Apps Script מתייחס רק ל-**function declarations ברמת ה-top** כ-custom functions. ה-Compare הבא מראה את הכלל בדוגמה.

סט ה-functions שעורך Apps Script בונה כששומרים הוא מה שה-spreadsheet רואה. אם שם לא מופיע ב-tooltip של autocomplete כשמתחילים להקליד `=usd...` בתא, העורך לא ראה הצהרה ברמת ה-top. פותחים את `Code.gs`, מתקנים את צורת ההצהרה, שומרים, וה-autocomplete מתעדכן תוך שנייה.

## ה-JSDoc שהופך ל-tooltip

הצורה למעלה עובדת, אבל אם חבר צוות מרחף עם העכבר על `=usdToILS(...)` בתא, כל מה שהוא רואה זה שם ה-function. מוסיפים JSDoc עם `@customfunction` וה-tooltip של התא מתחיל להציג את רשימת הפרמטרים והתיאור: אותו hint כמו ב-`=SUM`:

```js
/**
 * המרה של סכום בדולרים ל-ILS לפי שער נתון.
 *
 * @param {number} usd  הסכום בדולרים.
 * @param {number} rate שער ה-USD-to-ILS.
 * @return {number} הסכום המומר ל-ILS.
 * @customfunction
 */
function usdToILS(usd, rate) {
  return usd * rate;
}
```

ארבעה tags, כולם שווים את הכתיבה ביום ששולחים את ה-function:

| Tag | מה זה עושה |
|---|---|
| תיאור (פסקה ראשונה) | ה-body של ה-tooltip. משפט אחד. |
| `@param {type} name desc` | מופיע כעזרה לפרמטר כשהסמן על הארגומנט הזה. |
| `@return {type} desc` | מתועד אבל לא מוצג ב-tooltip; שימושי לקורא הבא של המקור. |
| `@customfunction` | חובה כדי שההצעה של autocomplete תצוף בתאים. בלעדיו, ה-function עדיין עובדת אבל היא לא תופיע כשמקלידים `=usd...`. |

ל-workbook של אדם בודד ה-JSDoc אופציונלי. ל-workbook של צוות זה תיעוד חינמי שיושב ליד הקוד ומופיע בתא שבו צריך אותו.

## קריאת ארגומנט של טווח

ארגומנט של custom function הוא מה שהתא מעביר:

| נוסחת תא | מה <code>usd</code> בתוך ה-function |
|---|---|
| `=usdToILS(F2, 3.7)` | המספר ב-F2 |
| `=usdToILS(F2:F10, 3.7)` | מערך דו-ממדי של תשעה מספרים |
| `=usdToILS("80.50", 3.7)` | המחרוזת `"80.50"` (Sheets לא ממיר אוטומטית) |
| `=usdToILS(, 3.7)` | `undefined` |

למקרה הפשוט של תא יחיד `usd * rate` עובד. ברגע שה-caller מעביר טווח, האופרטור `*` של JavaScript עושה בשקט את הדבר הלא נכון על המערך הדו-ממדי (`NaN`) והתא מציג `#NUM!`. הצורה החסינה עוברת איטרציה במפורש:

```js
function usdToILS(usd, rate) {
  if (Array.isArray(usd)) {
    return usd.map(function(row) {
      return row.map(function(v) { return v * rate; });
    });
  }
  return usd * rate;
}
```

function שכתובה ככה מטפלת ב-`=usdToILS(F2, $K$1)` בנוסחאות פר-שורה **וגם** ב-`=usdToILS(F2:F61, $K$1)` כ-spill של נוסחה אחת ל-60 שורות. הקטע המעשי של השיעור דורש רק את מסלול התא היחיד; את מסלול המערך אפשר לשלוח יום אחרי.

## Caching: אותם args, אותה תוצאה

custom functions שמורות ב-cache **לפי רשימת הארגומנטים שלהן**. הקריאה הראשונה ל-`=usdToILS(F2, $K$1)` מריצה את ה-function וזוכרת את התשובה. אם F2 ו-K1 לא משתנים, פתיחת ה-workbook מחר לא תריץ מחדש את ה-function: הערך שב-cache מוצג. זו תכונה (workbooks נפתחים מהר אפילו עם מאות תאי custom function) וזו מלכודת (function שקוראת את הזמן הנוכחי, את המשתמש הנוכחי, או ערך אקראי, קופאת בשקט ברגע שה-inputs שלה יציבים).

שלושה patterns להימנע מהם ב-custom function:

- **`new Date()` או `Date.now()`.** ב-cache. שני תאים שקוראים לאותה function באותו זמן יכולים להחזיר חותמות זמן שונות; פתיחה מחדש של הקובץ מחזירה את זו שב-cache.
- **`Math.random()`.** אותה בעיה. השתמשו ב-`RAND()` native אם אתם צריכים אקראיות בתא; הוא volatile ומתגלגל מחדש כמו שצריך.
- **`UrlFetchApp.fetch(...)` לנתונים חיים.** פוגע במכסה בכל recalc ונכנס ל-cache. אם הנתונים אמורים להיות חיים, השתמשו ב-trigger מבוסס-זמן (שיעור 8) שכותב לתא, לא ב-custom function שקוראת מ-URL.

כלל אצבע: custom function צריכה להיות **function טהורה של הארגומנטים שלה**. אם שתי קריאות עם אותם ארגומנטים יכולות באופן לגיטימי להחזיר דברים שונים, זה לא שייך כ-custom function.

## function שנייה מעובדת: מנרמל vertical

הדוגמה של USD-to-ILS היא הצורה המינימלית. הנה זו שהצוות באמת נשען עליה יותר: `normalizeVertical(name)`. המוסכמה של הצוות היא שכל שם vertical מסתיים ב-` PR`, בלי רווחים מובילים או נגררים, ב-title case. נתוני המקור מ-Taboola ומ-Outbrain מפרים את שלושת הכללים כל הזמן: `"used cars pr"`, `" Reverse Mortgage PR "`, `"Lingerie"` (בלי סיומת). זו המקבילה ב-Apps Script למתכוני הניקוי מבוססי-הנוסחה משיעור 2.14: אותה עבודה, גרסה ב-script, ניתנת לשימוש חוזר על פני כל workbook שמייבא את ה-library.

```js
/**
 * נרמול שם vertical למוסכמת הצוות: title-case, מקוצץ,
 * עם סיומת " PR" נגררת.
 *
 * @param {string} name  שם ה-vertical הגולמי מ-export של פלטפורמה.
 * @return {string} הצורה הקנונית, למשל "Car Deals PR".
 * @customfunction
 */
function normalizeVertical(name) {
  if (name === null || name === undefined || name === "") return "";
  const trimmed = String(name).trim();
  const titled = trimmed.replace(/\b\w/g, function(c) {
    return c.toUpperCase();
  }).replace(/\bPr\b/, "PR");
  if (titled.endsWith(" PR")) return titled;
  return titled + " PR";
}
```

אותה צורת function (function טהורה של הארגומנטים שלה, מטפלת ב-null/empty, מחזירה מחרוזת) משמשת שוב גם עבור `normalizeBuyer`, `countryToRegion`, `roiBucket`. שלושה דברים שכדאי להוציא מהדוגמה הזו:

1. **בדיקת הגנה בראש.** תא יכול להעביר מחרוזת ריקה (התא ריק), `null`, או `undefined` (הארגומנט הושמט). בלי הבדיקה, `String(null).trim()` זורק שגיאה והתא מציג `#ERROR!`.
2. **`String(name)` במקום `name.toString()`.** אם `name` הוא מספר (Sheets לפעמים מטפס עמודה כמספרית כשהנתונים מעורבים), `name.toString()` עובד אבל `String(name)` בטוח יותר כי הוא לא מניח שיש method.
3. **regex על word boundaries.** `\b\w` תופס את התו הראשון של כל מילה; ההחלפה ממירה לאות גדולה. ה-`\bPr\b → PR` שאחריו מטפל במקרה הקיצון שבו המקור כבר היה עם סיומת " PR" עם רישיות נכונה ש-title-casing היה אחרת משכתב ל-" Pr".

## מה custom functions לא יכולות לעשות

ה-auth context ש-custom functions רצות תחתיו צר בכוונה. הן יכולות:

- לקרוא ל-`Utilities.*` ל-parsing ולפורמט
- להריץ JS טהור

הן **לא יכולות**:

- לקרוא ל-`SpreadsheetApp.getActiveSpreadsheet()`. custom functions רצות ב-auth context מצומצם שמחזיר `null` לקריאות active-spreadsheet. כדי לקרוא נתוני sheet, מקבלים אותם כארגומנט של range מהתא הקורא (למשל `=fn(A1:B10)` מגיע כמערך דו-ממדי). שיעור 4 מאשר את זה מצד `SpreadsheetApp`.
- להציג dialog או sidebar (`showSidebar`, `alert`: אלה דורשים UI context פעיל)
- לכתוב ל-spreadsheet (`setValue`, `setFormula`)
- לשלוח מייל, לערוך Calendar, או כל דבר אחר שצריך OAuth scopes שה-cell context לא נושא
- לקחת יותר מ-30 שניות (timeout של custom function)
- לקרוא ל-`SpreadsheetApp.openById` (אין גישה לאף קובץ, כולל זה המארח)

אם ה-function שלכם צריכה משהו מאלה, זה macro או handler שמופעל מ-trigger, לא custom function. שיעורים 4 עד 8 ב-Track 3 מכסים את הצד הזה.

## נפוץ בשטח

ב-workbooks האמיתיים של הצוות, custom functions מופיעות כ-helpers קטנים של lookup-and-format:

- **`normalizeVertical(name)`**: מסיר whitespace נגרר, מתקן casing, מוודא את הסיומת ` PR`. רץ על כל שורה נכנסת מ-sheets של export של פלטפורמות.
- **`countryToRegion(iso2)`**: ממפה `"DE"` ל-`"EU"`, `"US"` ל-`"NA"`, `"BR"` ל-`"LATAM"`. switch statement של 200 שורות ב-Apps Script מנצח טבלת lookup של 200 תאים שצריך לתחזק inline.
- **`roiBucket(roi)`**: מחלק ROI ל-`"loss"`, `"flat"`, `"profitable"`, `"hero"`. בשימוש ב-dashboards וב-custom formulas של חוקי conditional-formatting.
- **`parseAdtechCampaignName(name)`**: מפצל את שם הקמפיין המובנה של הצוות (`"YC.CarDealsPR.US.permax.2026-05-11"`) ל-buyer, vertical, country, type ותאריך. מחזיר שורה של 5 תאים, כך שקריאה אחת ל-`=parseAdtechCampaignName(A2)` יכולה למלא את B2:F2.

כל אחת מאלה היא באותה צורה: function טהורה של הארגומנטים שלה, מחזירה ערך יחיד (או שורה קטנה), נקראת מהרבה תאים. הספרייה המשותפת שמארחת אותן היא הפוקוס של שיעור 12.

## מלכודות מקצועיות

- **ה-function מופיעה ב-autocomplete אבל מחזירה `#NAME?` בתא.** ה-function נשמרה אבל ה-cache של ה-autocomplete של ה-spreadsheet מיושן. מקלידים את הקריאה במלואה ולוחצים Enter; אינדקס ה-autocomplete מתעדכן תוך כמה שניות והתא מתבצע.
- **`#ERROR!` בלי פירוט נוסף.** או שה-function זרקה שגיאה או שהיא החזירה `undefined`. מוסיפים קריאות `console.log(usd, rate)` בתוך ה-body ובודקים את ה-Executions panel של עורך Apps Script ב-recalculation הבא. שיעור 14 מכסה את סיפור ה-logging מקצה לקצה.
- **ה-function רצה פעם אחת ולא מתעדכנת.** Caching. ה-function רצה עם ה-args המקוריים, ה-args לא השתנו, הערך ב-cache מוחזר. עורכים את אחד מתאי הקלט ועושים recalc; ה-function רצה שוב.
- **`=usdToILS(F2:F61, $K$1)` מחזיר תא אחד במקום spill.** ה-function לא מטפלת במקרה של מערך. או שכותבים את הגרסה שמודעת למערך למעלה או קוראים פר-שורה (`=usdToILS(F2, $K$1)` ואז fill down).
- **`function usdToILS` מוגדרת אבל תאים מציגים `#NAME?` ל-`=usdToILS(...)`.** ה-script המקושר לא קיבל הרשאה אחרי העריכה האחרונה. פותחים Apps Script, לוחצים Run על כל function פעם אחת, מאשרים את ה-auth prompt, והתא מתבצע ב-recalc הבא.
- **custom function שקוראת ל-`SpreadsheetApp.getActiveSpreadsheet().getRange(...)` זורקת שגיאה או מחזירה `#REF!`.** custom functions מקבלות auth context מצומצם: `getActiveSpreadsheet()` מחזיר `null` וה-`.getRange(...)` שאחריו קורס על ה-null. אם רציתם לחפש שורה ב-tab אחר דרך custom function, אורזים את טבלת ה-lookup בנוסחת התא (`=lookup(A2, Buyers!A:B)`) ונותנים ל-function לקבל את הטווח כארגומנט.
- **`String.prototype.replaceAll` לא נמצא.** ה-V8 של Apps Script תומך ב-`replaceAll`, אבל אם ייבאתם ספרייה שנכתבה על runtime legacy, ייתכן שלא. אם יש ספק, השתמשו ב-`replace(/.../g, ...)` (regex גלובלי), שעובד על שניהם.
- **custom function עם side effects ש"נראתה לא מזיקה".** function שכותבת שורת לוג ל-sheet דרך `appendRow` תיכשל (אין scope של כתיבה מ-custom function) והתא מציג `#REF!` עם שגיאה חסרת תועלת. מעבירים את ה-logging ל-function רגילה שנקראת מ-menu או trigger.
