# PropertiesService ו-CacheService: אחסון קבוע ואחסון קצר-טווח

Apps Script רץ ב-sandbox בלי disk מקומי. כל מה שהסקריפט רוצה לזכור בין ריצות חייב לחיות איפשהו ש-Google מנהלת. שני ה-surfaces לזה הם **`PropertiesService`** (אחסון key/value קבוע שנשאר לתמיד) ו-**`CacheService`** (אחסון מהיר קצר-טווח שמתפנה אחרי שש שעות לכל היותר). כל trigger בפרודקשן שהצוות כותב משתמש באחד מהם: API tokens ב-Properties כדי שה-trigger לא ישלח אותם במקור, שער החליפין היומי ב-Cache כדי ש-200 תאים לא יפנו כולם ל-FX API.

## שלושה scopes, שני services

שני ה-services חושפים את אותם שלושה scopes:

| Scope | מה משותף | משתמשים בשביל |
|---|---|---|
| **Script** | כל המשתמשים של פרויקט הסקריפט הזה. | קונפיגורציה לכל הצוות: API endpoints, טבלאות שערים ברירת מחדל, ID של תיקיית Drive שאליה הולכים ה-exports. |
| **Document** | הסקריפט הזה מקושר ל-spreadsheet הזה. קבצים שונים מקבלים stores נפרדים. | state ספציפי ל-workbook: זמני refresh אחרון, שער FX קנוני לתקופת הדיווח של הקובץ הזה. |
| **User** | המשתמש הנוכחי. חברי צוות שונים מקבלים stores נפרדים. | העדפות לכל משתמש: איזה view של dashboard מישהו מעדיף, ה-API token האישי שלו. |

ה-getters משקפים את שמות ה-scopes:

```js
const scriptProps = PropertiesService.getScriptProperties();
const docProps    = PropertiesService.getDocumentProperties();
const userProps   = PropertiesService.getUserProperties();

const scriptCache = CacheService.getScriptCache();
const docCache    = CacheService.getDocumentCache();
const userCache   = CacheService.getUserCache();
```

בוחרים את ה-scope שמתאים למחזור החיים של הנתונים. הבחירה הלא נכונה היא הבאג שנושך שלושה חודשים אחר כך כש"איכשהו" Maya רואה שער אחד ו-Yoav רואה אחר.

## שני ה-services ב-60 שניות

```js
// PropertiesService: קבוע, write-and-forget.
const props = PropertiesService.getDocumentProperties();
props.setProperty("usdIlsRate", "3.72");        // הערכים חייבים להיות מחרוזות
const rate = props.getProperty("usdIlsRate");    // מחזיר "3.72" או null

// CacheService: קצר-טווח, TTL בשניות.
const cache = CacheService.getDocumentCache();
cache.put("usdIlsRate", "3.72", 3600);           // פג תוקף בעוד שעה
const cached = cache.get("usdIlsRate");           // מחזיר "3.72" או null
```

שלושה פרטים שנושכים:

- **ערכים ב-Properties הם מחרוזות.** `setProperty` כופה המרה של מה שמעבירים למחרוזת. `getProperty` מחזיר את המחרוזת. ההמרה חזרה למספר / boolean / JSON נופלת עליכם.
- **TTL של Cache הוא בשניות, לא במילישניות.** `cache.put(k, v, 60)` חי דקה. `cache.put(k, v, 60000)` חי לאורך מקסימום זמן ה-cache (שש שעות, מוגבל); ה-function לא זורקת והבאג צף רק כשפריטים נעלמים מוקדם מדי או מאוחר מדי.
- **גם `get` וגם `getProperty` מחזירים `null` במקרה של miss.** תמיד בודקים על `null` לפני שקוראים ל-`.length` או עושים חשבון על הערך.

## דפוס שלושה ה-tiers

הדפוס שכל trigger של הצוות משתמש בו כדי "להשיג את שער ה-FX":

```js
function getOrFetchRate() {
  const cache = CacheService.getDocumentCache();
  const cached = cache.get("usdIlsRate");
  if (cached !== null) return Number(cached);

  const props = PropertiesService.getDocumentProperties();
  const stored = props.getProperty("usdIlsRate");
  if (stored !== null) {
    cache.put("usdIlsRate", stored, 3600);
    return Number(stored);
  }

  return 3.7;
}
```

קוראים מלמעלה למטה: cache קודם (lookup במיקרו-שניות), Properties שני (מספר מילישניות, קבוע), default אחרון (ה-function עדיין עובדת ביום הראשון לפני שכלום נכתב). כשיש hit ב-Properties, ה-function מחממת את ה-cache כך שהקריאה הבאה בתוך השעה היא cache hit. כל קריאה מחזירה מספר, הקורא לא צריך להתמודד עם המקרה של null.

הצורה הזו מתכלילת. מחליפים "rate" ב-"API token", "buyer list", "last refresh", כל ערך שמשיגים שוב ושוב. המחיר של שכחת tier אחד הוא trigger איטי. המחיר של שכחת tier שלוש הוא `TypeError: cannot convert null to number`.

## מגבלות שכדאי לזכור

| Surface | מגבלה לערך | מגבלה כוללת | TTL |
|---|---|---|---|
| ערך Properties | 9 KB | 500 KB ל-store של Properties | לתמיד |
| ערך Cache | 100 KB | (לא מתועד) | מקסימום 6 שעות |

מלכודת נפוצה: השלכת JSON blob גדול ל-Properties. "רשימת ה-buyers הפעילה" של הצוות גדלה מ-8 שמות ל-240 לאורך שנתיים; הקוד המקורי עשה `props.setProperty("buyers", JSON.stringify(list))` ויום אחד נחתך בשקט באמצע מחרוזת. התיקון הוא פיצול למספר keys (`buyers_chunk_0`, `buyers_chunk_1`) או מעבר לקובץ Drive שמיוצג ב-ID, Properties הוא store של קונפיגורציה, לא בסיס נתונים.

ערכי Cache יכולים להיות גדולים יותר (100 KB) אבל הם מתפנים על זמן ועל לחץ זיכרון. ערך cache בגודל של CSV קטן בסדר; בגודל של dataset שלם לא.

## Properties הוא לא בשביל secrets

כל מי שיכול לערוך את הסקריפט המקושר יכול לקרוא כל key ב-`getScriptProperties` וב-`getDocumentProperties`. המחרוזת `Authorization: Bearer XYZ123` חיה ב-plain text. אם ה-secret דולף, ה-API מאחוריו חשוף.

ל-secrets אמיתיים הצוות משתמש ב-Google Cloud Secret Manager, מושג ב-runtime דרך `UrlFetchApp.fetch` עם token של service account. הסטאפ הזה overkill ל-dashboard של צוות בלי PII, אבל זו הצורה הנכונה ברגע ש-API key אמיתי מעורב. Properties הוא בשביל **קונפיגורציה שלא צריכה להיות מוסתרת**, endpoints, IDs של גיליונות, שער ה-FX.

## כותבים בו-זמנית מתחרים

שני triggers שרצים באותו זמן שניהם קוראים ל-`setProperty` על אותו key. כתיבה אחת מנצחת; השנייה נדרסת בשקט. עבור נתונים מסוג "last-write-wins" (שער ה-FX האחרון) זה בסדר. עבור counters שמתעדכנים ב-1 ורשימות מסוג append זה באג של איבוד נתונים.

התיקון הוא `LockService.getScriptLock()`:

```js
const lock = LockService.getScriptLock();
lock.waitLock(5000);
try {
  const props = PropertiesService.getScriptProperties();
  const current = Number(props.getProperty("runCount") || 0);
  props.setProperty("runCount", String(current + 1));
} finally {
  lock.releaseLock();
}
```

שני triggers יכולים שניהם לנסות לתפוס את ה-lock; אחד מחכה עד חמש שניות שהשני ישחרר. ה-increment עכשיו בטוח. אותו דפוס lock עובד ל-Cache, ל-spreadsheet עצמו, או לכל store משותף אחר.

2. קוראים ל-`PropertiesService.getDocumentProperties()`. אם `"usdIlsRate"` שם, מחממים את ה-cache (TTL של שעה) ומחזירים אותו כמספר.

## נפוץ בשטח

- **API tokens ב-script properties.** ה-trigger של Taboola pull בצוות קורא את ה-API key שלו עם `PropertiesService.getScriptProperties().getProperty("TABOOLA_TOKEN")` ומשתמש בו בכותרת `Authorization`. רוטציה של ה-key היא עדכון של שורה אחת דרך **Project Settings** (אייקון גלגל השיניים בסרגל השמאלי) **→ Script Properties → Add script property** בעורך, בלי שינוי קוד. שימו לב שרק ל-Script Properties יש UI; Document Properties ו-User Properties נקבעים רק מהקוד.
- **שער FX יומי שמור ב-cache לאורך היום.** ה-trigger של הבוקר משיג את השער מ-API של בנק לאומי, כותב אותו ל-Properties (קבוע, שורד eviction של cache), ומחמם את ה-cache לשעה. כל קריאת `=usdToILS(F2, getOrFetchRate())` ב-spreadsheet במהלך היום היא אז cache hit.
- **העדפות dashboard לכל משתמש.** כשה-sidebar נותן למשתמש לעבור בין views של "by buyer" ל-"by vertical", הבחירה נכנסת ל-`UserProperties` כך שפתיחה מחדש של ה-sidebar מחר תרים מאיפה שהפסיק.
- **חותמת ה-refresh האחרון של ה-workbook המקושר.** `DocumentProperties.setProperty("lastRefresh", new Date().toISOString())` בסוף כל pull מוצלח. ה-sidebar קורא אותה ומציג "Refreshed 4 minutes ago" כך שהצוות סומך על זה ש-ה-dashboard לא ישן.

## מלכודות מקצועיות

- **התייחסות ל-Properties כאחסון של secrets.** כל מי שיש לו גישת עריכה לפרויקט הסקריפט יכול לקרוא כל key. secrets אמיתיים (API tokens שמעניקים גישה לנתונים, PII של לקוחות) שייכים ל-Google Cloud Secret Manager, לא ל-Properties. השימוש של "API token" בסדר כש-ה-API פנימי והסקריפט מאחורי workspace SSO; הוא לא בסדר ל-API key ציבורי.
- **TTL של CacheService במילישניות.** טעות נפוצה שמועברת מעולם ה-JS. הארגומנט השלישי ל-`cache.put` הוא **שניות**. `cache.put(k, v, 60 * 60 * 1000)` לא נכשל, הוא נחתך למקסימום של 6 שעות, והבאג מציג את עצמו כ-"ה-cache שורד הרבה יותר ממה שציפיתי".
- **בלבול בין "אין ערך" ל-"פג תוקף" ב-cache miss.** שניהם מחזירים `null`. אי אפשר לדעת מהערך המוחזר אם ה-key מעולם לא נכתב או שנכתב ואז התפנה. אם הלוגיקה צריכה להבדיל (נדיר), הבדיקה השנייה מול Properties היא מה שאומרת לכם.
- **מגבלת 9 KB לכל property חותכת בשקט.** Properties שומר JSON-stringified blobs בלי תלונות; ארוכים נחתכים באמצע מחרוזת ופירוק ה-JSON בדרך חזרה נכשל. לכל דבר שיכול לגדול (רשימת buyers, לוג עריכות אחרון), משתמשים בקובץ Drive שמיוצג ב-ID וקוראים אותו דרך `DriveApp.getFileById(id).getBlob().getDataAsString()`.
- **כותבים בו-זמנית מאבדים increments.** שני triggers שכותבים את אותו counter בלי `LockService` ידרסו בשקט אחת מהכתיבות. ה-reader של דפוס שלושה ה-tiers בשיעור הוא read-only ובטוח; ברגע שמתחילים לכתוב חזרה, עוטפים את הכתיבה ב-`LockService.getScriptLock()`.
- **שכחה להמיר ערכי Properties חזרה לטיפוס.** `props.getProperty("usdIlsRate")` מחזיר את המחרוזת `"3.7"`, לא את המספר `3.7`. `+rate` או `Number(rate)` עושה את ההמרה. מדלגים על זה והכפל במורד הזרם עושה שכפול מחרוזת (`"3.7" * 412.5` → מספר, במקרה, כי JS) או גרוע מזה, בפינות מסוימות, NaN.
