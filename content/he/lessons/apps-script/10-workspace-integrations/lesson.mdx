# אינטגרציות Workspace: Drive, Calendar, Gmail

Apps Script project מסוג bound לא רואה רק את ה-spreadsheet שהוא חי בתוכו. אותו script יכול לקרוא ולכתוב קבצים ב-Drive, לשלוח מייל דרך חשבון Gmail שלכם, וליצור events ביומן שלכם, הכל מאותו קוד JavaScript שכבר רץ על edit-triggers ועל לחיצות תפריט. ה-catch הוא שלכל שירות יש OAuth scope משלו, ו-Apps Script יבקש מהמשתמש אישור פעם אחת לכל scope חדש בפעם הראשונה שה-function רצה. שיעור 4 כיסה את המשטח של `SpreadsheetApp`; השיעור הזה עוסק בשלושת השירותים שנוגעים בכל השאר ב-workspace.

השיעור הזה עובר דרך DriveApp (חיפוש, קריאה, העתקת קבצים), CalendarApp (יצירה וקריאה של events), הפיצול בין MailApp ל-GmailApp (מתי לבחור איזה), ו-function אחת שמשתמשת בארבעה שירותים ומבצעת ingest יומי. האגרגטור הלילי של הצוות הוא בדיוק ה-pattern הבין-שירותי שמופיע בסוף: חיפוש Drive אחד, כתיבת Sheets אחת, event אחד ב-Calendar, מייל אישור אחד. ברגע שראיתם את כל הארבעה משורשרים, שאר Track 3 לא מציג שירותים חדשים.

## DriveApp: חיפוש, קריאה, כתיבת קבצים

`DriveApp` היא נקודת הכניסה ל-Google Drive. שלוש צורות צצות ב-scripts אמיתיים של הצוות:

```js
// מקבל קובץ לפי ID. ה-ID מגיע מה-URL: drive.google.com/file/d/<ID>/view
const file = DriveApp.getFileById("1abc...");
const csvText = file.getBlob().getDataAsString();   // bytes גולמיים כמחרוזת

// חיפוש לפי שם או לפי query. searchFiles מחזיר iterator, לא מערך.
const iter = DriveApp.searchFiles('title contains "Taboola export"');
while (iter.hasNext()) {
  const f = iter.next();
  Logger.log(f.getName() + " -> " + f.getId());
}

// העתקת קובץ. makeCopy מחזיר את ה-File object החדש; שינוי שם או הזזה אחרי.
const copy = file.makeCopy("Taboola export 2026-05-11", DriveApp.getFolderById("0folder..."));
```

ה-iterator הוא המלכודת הקלה. גם `searchFiles` וגם `getFolders` מחזירים Drive iterators, לא מערכים. `.map` ו-`.filter` לא קיימים עליהם: חייבים להניע אותם עם `.hasNext()` ו-`.next()`. לומד שכותב `DriveApp.searchFiles(q).forEach(...)` מקבל שגיאת runtime על "forEach is not a function", וה-bug הוא ה-iterator, לא ה-query.

`DriveApp` צריך את ה-scope `https://www.googleapis.com/auth/drive`. יש scope צר יותר, `https://www.googleapis.com/auth/drive.file`, שרואה רק קבצים שהמשתמש מסר במפורש ל-app שלכם (דרך picker או קבצים שה-script עצמו יצר). ה-scope הצר הוא ברירת המחדל הנכונה ל-scripts שנוגעים רק בקבצי הפלט שלהם; מרחיבים רק כשבאמת צריכים לקרוא נתוני משתמש קיימים.

## CalendarApp: קריאה ויצירה של events

```js
const cal = CalendarApp.getDefaultCalendar();   // הקלנדר הראשי של המשתמש
const event = cal.createEvent(
  "Campaign launch: Reverse Mortgage PR (UK)",
  new Date("2026-05-12T09:00:00+03:00"),
  new Date("2026-05-12T09:30:00+03:00"),
  {
    description: "Buyer: Ben Nahum. First $200 of spend goes to LP testing.",
    guests: "ben.nahum@flexelent.com,info@flexelent.com",
    sendInvites: true,
  }
);
```

CalendarApp הוא הקל ביותר מבין השלושה. מקבלים Calendar, קוראים ל-`createEvent` (חד-פעמי) או ל-`createAllDayEvent` או ל-`createEventSeries` (חוזר), וה-event נוחת ביומן עם הזמנות אורחים אופציונליות. קריאות עובדות באותה דרך: `cal.getEventsForDay(new Date())` מחזיר מערך (זה כן מערך, לא iterator), וכל Event חושף `getTitle`, `getStartTime`, `getEndTime`, `getDescription`, וכן הלאה.

ה-scope הוא `https://www.googleapis.com/auth/calendar`. script שיוצר events רק למשתמש שמריץ אותו (בלי נגיעה ביומנים אחרים) מסתפק ב-`calendar.events` הצר יותר: שווה להגדיר ב-manifest אם ה-script הולך להיות משותף בהרחבה.

## MailApp מול GmailApp: פשוט מול עשיר

שני שירותים שולחים מייל. הם נראים דומים באתר הקריאה אבל שונים במה שהם יכולים לעשות ובאיזה scope הם צריכים.

| | `MailApp` | `GmailApp` |
|---|---|---|
| שליחת מייל | כן | כן |
| קריאת inbox / threads | לא | כן |
| צירוף קבצים | כן | כן |
| שינוי drafts, labels, threads | לא | כן |
| Scope נדרש | `script.send_mail` (שליחה בלבד) | `gmail.modify` או `mail.google.com` |
| מכסה יומית (חשבונות consumer) | 100 מיילים / יום | 100 מיילים / יום |
| מכסה יומית (Workspace) | 1,500 מיילים / יום | 1,500 מיילים / יום |

אם ה-script צריך רק לשלוח הודעה יוצאת אחת לכל ריצה, משתמשים ב-`MailApp`. ה-scope צר יותר (לא תיתנו בטעות ל-script גישת קריאה ל-inbox שלכם), ה-API קטן יותר, והמכסה זהה. ה-mailer היומי של ה-spend של הצוות משתמש ב-`MailApp` בדיוק מהסיבה הזאת.

```js
MailApp.sendEmail({
  to: "info@flexelent.com",
  subject: "Daily spend report: 2026-05-11",
  body: "Total spend yesterday: $32,418.20\n\nFull breakdown: https://docs.google.com/spreadsheets/...",
});
```

ה-options bag חשוב. הצורות עם ארגומנט יחיד (`MailApp.sendEmail(to, subject, body)`) עובדות אבל נועלות אתכם מחוץ ל-features כמו `htmlBody`, `cc`, `bcc`, `attachments`, `replyTo`, ו-`name` (שם התצוגה של From, לא הנמען: ראו את המלכודות למטה). תתחילו עם צורת ה-object מהיום הראשון ולא תצטרכו לכתוב את הקריאה מחדש כשהצוות יבקש פורמט HTML.

### מתי GmailApp באמת שווה את ה-scope הרחב יותר

ברגע שאתם צריכים *לקרוא* מייל (לא רק לשלוח), `MailApp` יוצא מהמשחק. ה-job הלילי של הצוות שמסנכרן את ה-attachments של חשבוניות Tonic ל-Drive הוא המקרה הקנוני: מחפשים ב-inbox את ה-thread היומי של החשבונית, עוברים על ההודעות, מושכים כל PDF attachment, שומרים אותו לתיקיית Drive כדי שגיליון הפיננסים יוכל להרים אותו.

```js
function archiveTonicInvoices() {
  const threads = GmailApp.search('from:billing@tonic.com has:attachment newer_than:2d');
  const folder = DriveApp.getFolderById("0folder...");
  for (const thread of threads) {
    for (const msg of thread.getMessages()) {
      for (const att of msg.getAttachments()) {
        if (att.getContentType() !== "application/pdf") continue;
        folder.createFile(att.copyBlob()).setName(
          msg.getDate().toISOString().slice(0, 10) + " " + att.getName()
        );
      }
    }
    thread.addLabel(GmailApp.getUserLabelByName("archived-to-drive"));
  }
}
```

שלוש יכולות של GmailApp מופיעות כאן ש-`MailApp` לא מסוגל להתחרות בהן: `GmailApp.search` (אותו syntax של query כמו בסרגל החיפוש של ממשק Gmail), איטרציה על threads והודעות, ושינוי labels על ה-thread ברגע שהעבודה נגמרה. שלב ה-label הוא הטריק הזול ל-idempotency: הריצה של מחר מחפשת `newer_than:2d -label:archived-to-drive` ומדלגת על threads שכבר עובדו.

## Patterns בין-שירותיים

הכוח המלא של scripts של Workspace מתגלה כש-function אחת משרשרת את כל השלושה:

```js
function ingestDailyTaboolaCsv() {
  // 1. Drive: מאתרים את ה-CSV export של היום
  const iter = DriveApp.searchFiles(
    'title contains "Taboola export 2026-05-11" and mimeType = "text/csv"'
  );
  if (!iter.hasNext()) {
    MailApp.sendEmail({
      to: "info@flexelent.com",
      subject: "Taboola export missing for 2026-05-11",
      body: "No CSV found in Drive. The Taboola scheduled export probably failed; check the platform dashboard.",
    });
    return;
  }
  const csv = Utilities.parseCsv(iter.next().getBlob().getDataAsString());

  // 2. SpreadsheetApp: כותבים את השורות
  const sheet = SpreadsheetApp.getActive().getSheetByName("Taboola raw");
  sheet.clear();
  sheet.getRange(1, 1, csv.length, csv[0].length).setValues(csv);

  // 3. Calendar: מתזמנים את פגישת הסקירה
  CalendarApp.getDefaultCalendar().createEvent(
    "Taboola data review",
    new Date("2026-05-11T17:00:00+03:00"),
    new Date("2026-05-11T17:30:00+03:00"),
    { description: "Review newly ingested Taboola rows in the Aggregator tab." }
  );

  // 4. MailApp: מאשרים שה-ingest נחת
  MailApp.sendEmail({
    to: "info@flexelent.com",
    subject: "Taboola export ingested: " + (csv.length - 1) + " rows",
    body: "Review meeting on the calendar at 17:00.",
  });
}
```

ארבעה שירותים, function אחת, trigger אחד. בפעם הראשונה שראש הצוות מריץ אותה, Apps Script מבקש את ה-scopes של Drive, Sheets, Calendar, ו-Gmail בבת אחת. מאז זה רץ בשקט.

## נפוץ בשטח

לצוות יש שלושה scripts שנוגעים ב-Workspace שרצים כל יום:

- **התקציר היומי של ה-spend.** trigger מבוסס-זמן קורא ל-`emailSpendReport` ב-09:00 עם הסכום של היום הקודם, שלוש ה-verticals הגבוהות ביותר, ושלוש הנמוכות ביותר. נשלח לכל media buyer פעיל.
- **ניקוי Drive של יום שישי.** query של `searchFiles` מוצא כל קובץ "raw export" שישן יותר מ-30 יום, מעתיק אותם לתיקיית ארכיון, ומוחק את המקורות. חוסך את מכסת ה-Drive של הצוות ל-exports של השבוע הנוכחי.
- **יצירת events של launch קמפיין ביומן.** כש-buyer לוחץ "Launch" ב-sidebar מותאם (שיעור 9 מכסה את ה-pattern של ה-sidebar), ה-script יוצר event ב-Calendar 24 שעות קדימה כ-check-in סקירה placeholder.

## מלכודות מקצועיות

- **שדה `name` של `MailApp.sendEmail` הוא שם התצוגה של ה-FROM, לא הנמען.** קוד מתחיל שכותב `MailApp.sendEmail({ to: "info@flexelent.com", name: "info@flexelent.com", ... })` שולח הודעה מ-"info@flexelent.com" (תצוגה) ל-"info@flexelent.com": זה עובד, אבל לא מה שהכותב חשב שהוא עושה. הנמען הוא תמיד `to:` (או `bcc:` / `cc:`).
- **`DriveApp.searchFiles` מחזיר iterator, לא מערך.** אין `.map`, אין `.forEach`, אין `.length`. Drive iterators הם streams; עוברים עליהם עם `.hasNext()` / `.next()` ואוספים למערך בעצמכם אם צריך אחד.
- **מכסות השליחה של Gmail מחמירות יותר ממה שהן נראות** (שיעור 16 מכסה מכסות פר-שירות ואסטרטגיות batching לעומק). 100 ליום לחשבונות consumer, 1,500 ליום ל-Workspace, והן מתאפסות בחלון מתגלגל של 24 שעות, לא בחצות. script שעושה לולאה של `sendEmail` 100 פעמים בדקה אחת יפגע במגבלת קצב השליחה הפר-דקתית לפני שיפגע במגבלה היומית ויתחיל לזרוק שגיאות. אוספים להודעה אחת עם body ארוך יותר, או מגבילים קצב עם `Utilities.sleep(1000)` בין שליחות.
- **`DriveApp.createFile` ב-bound script שם את הקובץ ב-Drive של בעל ה-SCRIPT, לא ב-Drive של המשתמש שמריץ.** אם ה-script שלכם בבעלות יואב ודינה מריצה אותו, הקובץ נוחת ב-Drive של יואב עם דינה כעורכת (אם זכרתם לשתף לה אותו). כדי ליצור ב-Drive של המשתמש שמריץ, משתמשים ב-`Drive.Files.create(...)` עם ה-Drive advanced service: הוא רץ כמשתמש.
- **`CalendarApp.getDefaultCalendar()` מחזיר את היומן של מי שמריץ את ה-script, לא של בעל ה-script.** ב-script עם "Execute as me" בעל ה-script הוא "me", אז הריצה של דינה עדיין יוצרת events ביומן של יואב. שני מצבי ההרצה ("as me" מול "as the user accessing") חשובים כאן בדיוק כמו ב-web apps בשיעור 13.
- **בקשת `https://mail.google.com/` (גישת Gmail מלאה) כשרק שולחים מייל.** ה-prompt של ההרשאה של Apps Script מציג את התיאור המלא של ה-scope, וההודעה "Read, compose, send, and permanently delete all your email" מבריחה משתמשים מהרצת ה-script. יורדים ל-`script.send_mail` אם כל מה שאתם עושים זה לשלוח.
- **`Utilities.parseCsv` לא מכבד delimiters מותאמים אישית.** כברירת מחדל הוא מפצל בפסיק. ל-TSV (חלק מהפלטפורמות מייצאות מופרד-tab), מעבירים `Utilities.parseCsv(str, "\t")`. bug נפוץ הוא ניתוח TSV עם ה-delimiter ברירת המחדל של פסיק וקבלת עמודה אחת עם הכל מודבק ב-tab.
- **timezones של event ב-Calendar שנסחפים.** `new Date("2026-05-12T09:00:00")` מנותח לפי ה-timezone של ה-script אם אין offset; מעבירים `+03:00` (ישראל) או `-04:00` (NYC) במפורש כדי שה-event ינחת בזמן השעון הנכון בלי קשר לאיזה משתמש מריץ את ה-function.
