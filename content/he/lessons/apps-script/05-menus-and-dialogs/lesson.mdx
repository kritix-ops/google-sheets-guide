# תפריטים מותאמים ו-dialogs

spreadsheet שמריץ את הקוד שלכם רק כשפותחים את עורך Apps Script לא ממש שימושי לשאר הצוות. תפריטים מותאמים הם הדרך לחשוף function כפעולה של לחיצה אחת בסרגל הכלים של ה-spreadsheet: ה-media buyer פותח את ה-spreadsheet, רואה תפריט "Reports" ליד Help, לוחץ "Email weekly summary", והסקריפט רץ. Dialogs הם הדרך שבה הסקריפטים האלה עונים בחזרה: alert כשמשהו הסתיים, prompt כשהסקריפט צריך מספר, sidebar כשיש פאנל שלם של בקרות להציג.

השיעור הזה מכסה את ארבעת המשטחים. **`onOpen`** הוא ה-trigger שבונה מחדש את התפריט בכל טעינה של workbook. **`createMenu` ו-`addItem`** הם שרשרת ה-builder. **`ui.alert`** הוא ה-popup של one-shot להצגת מידע, עם וריאציות ל-confirms. **`ui.prompt`** הוא ה-input של one-shot. ל-sidebars יש שיעור משלהם (שיעור 9, `HtmlService`) כי הם HTML, לא רק הודעה יחידה.

## ה-trigger `onOpen`

תפריט מותאם חי רק כל זמן שה-spreadsheet פתוח. בכל פעם שה-workbook נטען בדפדפן של מישהו, Apps Script מפעיל את ה-trigger המיוחד `onOpen` והתפריט צריך להיבנות מחדש:

```js
function onOpen() {
  SpreadsheetApp.getUi()
    .createMenu("Reports")
    .addItem("Show spend total", "alertSpend")
    .addItem("Email weekly summary", "emailWeeklySummary")
    .addToUi();
}
```

`onOpen` הוא **simple trigger** (שיעור 7 מכסה את הסט המלא). Apps Script מפעיל אותו אוטומטית בכל פעם שהקובץ נפתח, ללא צעד התקנה וללא בקשת הרשאה. ה-catch הוא ש-simple triggers רצים ב-auth context מצומצם: הם יכולים לקרוא את ה-spreadsheet ולבנות UI, אבל הם לא יכולים לשלוח מייל, לקרוא ל-`UrlFetchApp`, או לעשות שום דבר שצריך OAuth scopes מלאים. ה-handlers של פריטי התפריט (`alertSpend`, `emailWeeklySummary`) רצים כשהמשתמש לוחץ עליהם, ובאותה נקודה יש להם את ה-auth context המלא.

**הערת קורס.** ה-bound project בקורס הזה כבר מצהיר על `onOpen()` למטרותיו (הקמת ה-sidebar). JavaScript שומר רק הצהרה אחת לזיהוי, אז `function onOpen()` שני ב-`Lesson.gs` שלכם יחליף בשקט את זה ששלחנו או יוחלף על ידו. כדי לעקוף את זה, הקטע המעשי מבקש מכם לכתוב function רגילה בשם `addReportsMenu()` ולהריץ אותה ידנית מ-Run dropdown של עורך Apps Script. הצורה של ה-body זהה למה ש-`onOpen` אמיתי היה מכיל. בכל workbook שאתם בונים מחוץ לקורס הזה, ה-pattern של production הוא מה שלמעלה: מצהירים על `onOpen`, בונים את התפריט בתוכו, והתפריט מופיע אוטומטית בכל טעינה.

## `createMenu` ו-`addItem`

ה-builder של התפריט הוא שרשרת. קוראים אותו מלמעלה למטה:

```js
SpreadsheetApp.getUi()       // משיג את ה-UI object של ה-spreadsheet
  .createMenu("Reports")      // מתחיל top-level menu חדש
  .addItem("Refresh Taboola", "refreshTaboola")
  .addItem("Mark dead campaigns", "markDeadCampaigns")
  .addSeparator()
  .addItem("Email weekly summary", "emailWeeklySummary")
  .addToUi();                 // מצרף לסרגל הכלים
```

שלושה דברים ששווה לדעת על `addItem`:

1. **הארגומנט השני הוא שם ה-function כמחרוזת.** Apps Script לא מאמת אותו בזמן השמירה. typo `"emaiWeeklySummary"`, שומרים, לוחצים על הפריט, התפריט פשוט לא עושה כלום. ה-bug צץ בזמן הקליק, לא בזמן השמירה.
2. **הארגומנט הראשון הוא התווית של פריט התפריט שהמשתמש רואה.** משאירים אותה קצרה. ה-dropdown של סרגל הכלים חותך שמות ארוכים.
3. **`addToUi()` חובה.** בלעדיה, התפריט נבנה בזיכרון JavaScript ולעולם לא מתחבר לסרגל הכלים.

`createMenu` תומך גם בתפריטי משנה דרך `addSubMenu(otherMenu)`, שימושי כשלצוות יש שישה פריטי "Refresh X" שאחרת היו עומסים על ה-top level.

## `ui.alert` והווריאציות שלו

ה-dialog הפשוט ביותר הוא `alert`. הוא עוצר את ה-script, מציג חלון מודאלי עם הודעה וכפתור OK, וממשיך כשהמשתמש לוחץ OK:

```js
const ui = SpreadsheetApp.getUi();
ui.alert("Refresh complete. 248 new rows pulled.");
```

עוד שתי צורות מכסות את שאר משטח ה-alert:

```js
// עם title וסט כפתורים מותאם:
ui.alert(
  "Confirm refresh",
  "This will overwrite rows 2 to 500 of the Aggregator tab. Continue?",
  ui.ButtonSet.YES_NO,
);

// ערך ההחזרה אומר לכם איזה כפתור המשתמש לחץ:
const response = ui.alert(
  "Confirm refresh",
  "This will overwrite rows 2 to 500 of the Aggregator tab. Continue?",
  ui.ButtonSet.YES_NO,
);
if (response === ui.Button.YES) {
  refreshAggregator();
} else {
  ui.alert("Refresh cancelled.");
}
```

הקבועים של סט הכפתורים (`OK`, `OK_CANCEL`, `YES_NO`, `YES_NO_CANCEL`) וקבועי הכפתור (`OK`, `CANCEL`, `YES`, `NO`, `CLOSE`) חיים על ה-`ui` object עצמו, לא כמחרוזות חופשיות.

## `ui.prompt` לקבלת ערך

כשה-script צריך שהמשתמש יקליד משהו (טווח תאריכים, שם buyer, ROI יעד), משתמשים ב-`prompt`:

```js
const response = ui.prompt(
  "Bulk-edit ROI threshold",
  "Enter the new threshold (e.g. 1.25):",
  ui.ButtonSet.OK_CANCEL,
);

if (response.getSelectedButton() === ui.Button.OK) {
  const text = response.getResponseText();
  const value = parseFloat(text);
  if (Number.isFinite(value)) {
    applyThreshold(value);
  } else {
    ui.alert(`"${text}" isn't a number.`);
  }
}
```

ערך ההחזרה הוא `PromptResponse` object, לא מחרוזת. שתי methods לזכור: `getSelectedButton()` (איזה כפתור המשתמש לחץ, כולל CLOSE אם לחץ על X) ו-`getResponseText()` (ה-input שהוקלד בפועל). מתחילים נופלים במלכודת של התייחסות לערך ההחזרה כמחרוזת עצמה ומקבלים `[object PromptResponse]` בלוגיקה שאחרי זה.

## מתי לבחור sidebar במקום

תפריטים ו-dialogs מכסים פעולות one-shot ו-inputs של one-shot. ברגע שאתם צריכים פאנל מתמשך (טופס עם חמישה שדות, תצוגת סטטוס שמתעדכנת בזמן ש-script ארוך רץ, בוחר טווח תאריכים שנשאר גלוי בזמן שהמשתמש עובד), הכלי הנכון הוא **sidebar**. Sidebars הם פאנלי HTML שמעוגנים בצד ימין של ה-spreadsheet. ככה ה-sidebar של הקורס שמדרג את השיעורים האלה מציג את רשימת ה-checks שלו.

שיעור 9 מכסה sidebars מקצה לקצה. הגרסה הקצרה: `ui.showSidebar(HtmlService.createHtmlOutputFromFile("Sidebar"))` פותח פאנל, ה-HTML בפנים מדבר עם ה-server functions שלכם דרך `google.script.run`. לעת עתה, צריך רק לדעת שפריט תפריט שפותח sidebar הוא ה-pattern הסטנדרטי כש-dialogs של one-shot לא מספיקים.

## נפוץ בשטח

ל-workbooks האמיתיים של הצוות יש תפריט Reports שנראה משהו כזה:

| פריט תפריט | Handler | מה זה עושה |
|---|---|---|
| Refresh Taboola | `refreshTaboola` | מפעיל את ה-pull הלילי לפי דרישה במקום לחכות ל-trigger. |
| Refresh Outbrain | `refreshOutbrain` | אותו דבר, ל-Outbrain. |
| Mark dead campaigns | `markDeadCampaigns` | מציב את ה-kill switch על כל שורה שבה ROI ירד מתחת ל-0.5 שלושה ימים ברצף. |
| Email weekly summary | `emailWeeklySummary` | `MailApp.sendEmail` עם נתוני Aggregator של שבעת הימים האחרונים מצורפים. |
| Create month-end backup | `archiveMonth` | משכפל את ה-tab של Aggregator ל-sheet שמתויג בתאריך. |

כל פריט הוא function ב-JavaScript ב-bound project. התפריט הוא משטח ה-API של הצוות: ה-buyer לעולם לא פותח את עורך Apps Script; הוא לוחץ על פריטים בסרגל הכלים.

השימוש הכבד הנוסף ב-dialogs:

- **`ui.alert` בסוף scripts ארוכים** כדי שה-buyer יידע שה-script סיים. בלי ה-alert, script שרץ במשך שתי דקות נראה כאילו שום דבר לא קרה.
- **`ui.prompt` ל-script אינטראקטיבי נדיר.** המאקרו "rename a buyer across all tabs" מבקש את השם הישן ואת השם החדש דרך שתי קריאות `prompt` ברצף, ואז עושה את שינוי השמות ב-batch אחד.
- **`ui.alert(..., ButtonSet.YES_NO)` לפני פעולות הרסניות.** כל script שדורס טווח תאים מקבל gate של YES_NO כך שקליק שגוי לא הורס יום עבודה.

## מלכודות מקצועיות

- **פריטי תפריט לוקחים את שם ה-function כמחרוזת, ו-typos נכשלים בשקט.** `.addItem("Run", "RunCampaign")` עובד בזמן שמירה אבל לא עושה כלום בזמן קליק אם ה-JS function היא `runCampaign` (r באות קטנה). תמיד מעתיקים-מדביקים את שם ה-function מהצהרת ה-function, לעולם לא מקלידים מחדש.
- **`ui.alert` חוסם את ה-script.** ה-script עוצר עד שהמשתמש לוחץ על הכפתור. trigger לילי שקורא ל-`ui.alert` ייתקע ובסופו של דבר יעשה timeout. `ui.alert` הוא לריצות שיזמו על ידי משתמש בלבד, לא ל-triggers מתוזמנים. scripts שמופעלים מ-trigger רושמים log ל-sheet או שולחים מייל במקום זה.
- **`ui.prompt` מחזיר `PromptResponse`, לא מחרוזת.** `const x = ui.prompt("name"); doSomething(x)` לא מעביר את הטקסט שהוקלד; הוא מעביר את ה-response object. השתמשו ב-`x.getResponseText()` כדי לחלץ את ה-input האמיתי, ובודקים `x.getSelectedButton()` כדי לראות אם המשתמש לחץ OK, Cancel, או ה-X.
- **תפריט מותאם שנעלם.** המשתמש פתח את ה-spreadsheet אבל התפריט לא שם. שלוש סיבות: ה-script לא קיבל הרשאה (פותחים Apps Script, לוחצים Run על כל function, מאשרים את ה-auth prompt); `onOpen` זרק exception (בודקים את ה-Execution log); ה-script מקושר לעותק שונה של הקובץ (לכל עותק של spreadsheet יש bound project משלו: משכפלים את הקובץ ושכפלתם גם את ה-script, אבל את העותק החדש עדיין צריך להרשות בפתיחה הראשונה).
- **שני scripts שכל אחד מצהיר על `onOpen`.** workbook עם כמה ספריות bound פלוס קוד inline יכול להגיע לשני `onOpen` functions; זה שנטען שני מנצח, התפריט של הראשון נעלם. התיקון הוא לאחד את כל הקמת התפריט ל-`onOpen` אחד שקורא ל-helper functions לפי עניין.
- **פריט תפריט שפותח sidebar מ-simple-trigger context.** `ui.showSidebar` דורש את ה-scope `script.container.ui` ו-auth context מלא. בתוך `onOpen` הפשוט זה עובד כי `onOpen` נמצא ב-whitelist ל-UI; מ-trigger מבוסס-זמן זה זורק. אם אתם צריכים לפתוח sidebar מ-job מתוזמן, ה-pattern הנכון הוא לכתוב שורת סטטוס ל-spreadsheet ושה-`onOpen` של הפתיחה הידנית הבאה ישים לב לזה ויפתח את ה-sidebar אז.
- **הרצה מחדש של `onOpen` לא מרעננת את התפריט.** Apps Script בונה את התפריט פעם אחת לכל session. כדי לראות שינויים במהלך פיתוח, טוענים מחדש את ה-tab של ה-workbook. (`Ctrl+R` או סגירה ופתיחה מחדש.)
- **עבודה אסינכרונית אחרי `ui.alert`.** קוד אחרי `ui.alert(...)` רץ רק אחרי שהמשתמש סוגר את ה-modal. אם אתם משגרים-ושוכחים `UrlFetchApp` בין שני alerts, המשתמש בוהה ב-alert הראשון בזמן שה-fetch רץ; מתכננים בהתאם.
