# Apps Script + ה-Sheets advanced service: כש-SpreadsheetApp לא מספיק

`SpreadsheetApp` הוא ה-surface הידידותי שרוב Track 3 השתמש בו: objects ברמה גבוהה, ברירות מחדל שפויות, OAcuth מטופל implicitly. הוא מכסה בערך 80% ממה שהצוות עושה בסקריפט המקושר. ה-20% הנותרים, יצירת Pivot tables תכנותית, conditional formatting בכמויות, copy-paste בין spreadsheets, כל דבר שנוגע ב-Sheets v4 REST API ישירות, צריך את ה-**Sheets advanced service**. זה global דק שנקרא `Sheets` שממופה 1:1 ל-endpoints של Sheets v4 REST, חושף יותר עוצמה, ומחליף קצת נוחות בשליטה.

## מתי להושיט יד ל-advanced service

| משימה | `SpreadsheetApp` | Advanced service |
|---|---|---|
| לקרוא מספר תאים, להציב ערך | ✓ שורה אחת | overkill |
| iteration על גיליון של 5,000 שורות | ✓ עם batching | ✓ אותו רעיון, קצת יותר מהיר |
| יצירת Pivot table תכנותית | ✗ לא נתמך | ✓ `Sheets.Spreadsheets.batchUpdate` עם בקשת `addPivotTable` |
| הוספת 20 כללי conditional-format בבת אחת | איטי (קריאה לכלל) | ✓ `batchUpdate` אחד עם 20 פריטי `addConditionalFormatRule` |
| העתקת עיצוב מגיליון A לגיליון B (spreadsheets שונים) | מסורבל | ✓ `batchUpdate` עם בקשות `copyPaste` |
| הרצת בקשת Sheets API כמו שמתועד ב-REST docs | ✗ surface לא תואם | ✓ משקף את צורת ה-REST |

אם קראתם פעם את [הפניית Sheets API REST](https://developers.google.com/sheets/api) וחשבתם "הלוואי שיכולתי לקרוא לזה מ-Apps Script", ה-advanced service הוא מה שמגשר על הפער. לכל דבר ב-REST docs יש מקבילה ב-Sheets advanced service.

## הפעלה (ריקוד ה-manifest)

צריך opt in ל-advanced service בכל סקריפט. שתי דרכים:

1. **ה-UI של העורך**: בסרגל השמאלי של עורך Apps Script, לוחצים **Services** → **+** → **Google Sheets API** → **Add**. העורך מוסיף רשומה ל-manifest שלכם אוטומטית וזהו.
2. **עריכת manifest**: פותחים את `appsscript.json` (Project Settings → סימון "Show appsscript.json manifest file in editor") ומוסיפים את הרשומה `dependencies.enabledAdvancedServices` בעצמכם:

```json
{
  "timeZone": "America/New_York",
  "dependencies": {
    "enabledAdvancedServices": [
      {
        "userSymbol": "Sheets",
        "serviceId": "sheets",
        "version": "v4"
      }
    ]
  }
}
```

השדות:

| שדה | מה הוא עושה |
|---|---|
| `userSymbol` | שם ה-global שהעורך יוצר. בקונבנציה `Sheets` כך שהקוד שלכם קורא ל-`Sheets.Spreadsheets.values.get(...)`. אפשר לשנות שם; אף אחד לא עושה. |
| `serviceId` | ה-service ID הפנימי של Google. עבור Sheets זה `"sheets"`. advanced services אחרים: `"drive"`, `"gmail"`, `"calendar"`. |
| `version` | גרסת API. Sheets ב-`v4`. |

אחרי השמירה, העורך מפעיל את ה-API המתאים בפרויקט GCP מתחת אוטומטית (לפרויקטים "ברירת מחדל"), כשמריצים את ה-function בפעם הראשונה, התראת ה-OAuth consent כוללת עכשיו את ה-scope הרחב שה-advanced service צריך.

## צורת קריאות ה-advanced service

שתי השיטות שמכסות את רוב עבודת ה-adtech:

```js
function readSheetValues() {
  const spreadsheetId = SpreadsheetApp.getActiveSpreadsheet().getId();
  const response = Sheets.Spreadsheets.values.get(
    spreadsheetId,
    "Campaigns!F2:G61"
  );
  // response = { range: "Campaigns!F2:G61", majorDimension: "ROWS", values: [[412.5, 587.4], ...] }
  const rows = response.values || [];
  return rows;
}

function writeOneCell() {
  const spreadsheetId = SpreadsheetApp.getActiveSpreadsheet().getId();
  Sheets.Spreadsheets.values.update(
    { values: [[12345]] },         // request body
    spreadsheetId,
    "Campaigns!J1",                // A1 range (כולל שם הגיליון)
    { valueInputOption: "RAW" }    // query parameters
  );
}
```

שלושה דברים שכדאי להבהיר:

- **סדר הארגומנטים תואם ל-REST.** Body קודם (כשיש), אז path params, אז query params. שיטות read אין להן body ומתחילות ב-path params.
- **ה-ranges כוללים את שם הגיליון.** `"Campaigns!F2:G61"`, לא `"F2:G61"`. ה-advanced service לא יודע את הגיליון הפעיל כמו `SpreadsheetApp.getActiveSheet()`.
- **`valueInputOption` חשוב.** `"RAW"` כותב את הערך כמו שהוא. `"USER_ENTERED"` מנתח אותו כאילו משתמש הקליד אותו (אז `"=SUM(...)"` הופך לנוסחה, `"5/12/2026"` הופך לתאריך). ברירת המחדל ב-REST API היא ה-`"RAW"` השמרני יותר, אבל שווה להציב את זה במפורש.

## `batchUpdate` הוא סוס העבודה

ה-surface השני הוא `Sheets.Spreadsheets.batchUpdate`, שמקבל מערך של **requests** בקריאה אחת. ה-requests יכולים לעשות הכול, להוסיף גיליון, להוסיף Pivot table, להציב conditional formats, להקפיא שורות, להסתיר עמודות, להעתיק/להדביק בין ranges. דוגמה:

```js
Sheets.Spreadsheets.batchUpdate(
  {
    requests: [
      { addSheet: { properties: { title: "Monthly Rollup" } } },
      { addConditionalFormatRule: { rule: { ... } } },
      { repeatCell: { range: { ... }, cell: { ... }, fields: "userEnteredFormat" } },
    ],
  },
  spreadsheetId,
);
```

round-trip אחד מבצע את שלושת ה-requests atomically. מוסיפים 20 כללי conditional-format עם 20 רשומות במערך; מקבלים קריאת רשת אחת במקום 20. סקריפט בונה ה-pivots של הצוות שפעם לקח 90 שניות (יוצר גיליונות אחד אחרי השני, מציב פורמטים אחד אחרי השני) עכשיו לוקח 4 שניות עם הכול ב-`batchUpdate` אחד.

## קריאת התשובה

כל קריאת advanced-service מחזירה JS object רגיל שתואם לצורת ה-REST response. `values.get` מחזיר `{ range, majorDimension, values }`. `batchUpdate` מחזיר `{ spreadsheetId, replies, updatedSpreadsheet? }`, `replies` הוא מערך התוצאות לכל request (התשובה של request `addSheet` כוללת את ה-`sheetId` של הגיליון החדש, שאפשר לשרשר ל-request עוקב).

זה החלק שעושה את ה-advanced service חזק. ה-reply object נושא את ה-IDs ואת ה-metadata שצריך כדי לשרשר עבודה נוספת, בצורה ש-`Sheet` objects של `SpreadsheetApp` לא יכולים.

## נפוץ בשטח

- **מחולל Pivot tables תכנותי.** הצוות צריך pivot per-buyer-per-platform שמיוצר מחדש בכל יום שני על הנתונים של השבוע הנוכחי. ל-`SpreadsheetApp` אין שיטה ליצירת pivot; `Sheets.Spreadsheets.batchUpdate` עם request `updateCells` שמספק שדה `pivotTable` כן יש. trigger אחד של בוקר יום שני, קריאת batchUpdate אחת, pivot טרי.
- **העתקת עיצוב בין-workbooks.** כשגיליון dashboard חודשי חדש נוצר (מ-template), העיצוב מהגיליון של החודש שעבר חייב להיות מועתק: conditional formats, שורות מוקפאות, רוחבי עמודות. `batchUpdate` אחד עם requests `copyPaste` (`pasteType: "PASTE_FORMAT"`) מטפל בכול; עם `SpreadsheetApp` זה היה עשר קריאות נפרדות.
- **Conditional formatting בכמויות על עמודות חודשיות חדשות.** בכל חודש נוספת עמודה חדשה של spend / revenue / ROI לגיליון לכל buyer. עשרים כללי conditional-format לתחזק (ירוק אם ROI > 1.5, צהוב אם 1.0-1.5, אדום מתחת). `batchUpdate` אחד עם עשרים רשומות `addConditionalFormatRule`; לוקח 2 שניות במקום 40 עם המסלול של `SpreadsheetApp` לכל כלל.
- **Pagination של Sheets API על ranges ענקיים.** range של 500,000 תאים חורג ממגבלת גודל התשובה של Apps Script כשקוראים אותו דרך `SpreadsheetApp`. ה-advanced service תומך ב-paging דרך ranges ב-chunks (`A1:A50000`, `A50001:A100000`, ...), כל קריאה מקבלת תשובה בגודל ניהולי.

## מלכודות מקצועיות

- **`Sheets is not defined`** בגוף ה-function אומר שהרשומה ב-manifest עדיין לא שם. הפאנל Services בעורך מוסיף אותה; שמירת ה-manifest ביד גם עובדת. השגיאה לא מופיעה עד שה-function רץ, אז לא סומכים על "זה compiles", מריצים פעם אחת כדי לאמת.
- **`valueInputOption: "USER_ENTERED"` מנתח בלהיטות.** כתיבת המחרוזת `"5/12/2026"` כ-`USER_ENTERED` מתפרשת כתאריך (12 במאי ב-US locale, 5 בדצמבר ב-EU locale, תלוי ב-workbook). לטקסט גולמי ולמספרים מחושבים מראש, `"RAW"` בטוח יותר. לערכים שאמורים להתנהג כאילו הוקלדו (נוסחאות כמו `"=SUM(F2:F61)"`), `"USER_ENTERED"` נדרש.
- **Advanced services נספרים מול אותם quotas יומיים של `SpreadsheetApp` ועוד quotas של Sheets API.** ל-Sheets API יש quota פר-פרויקט משלו (300 בקשות read לדקה, 60 בקשות write לדקה, tier חינמי). trigger ש-batchUpdates 100 פעמים בשעה יכול לפגוע במגבלת ה-write; ה-API מחזיר 429 והסקריפט קורס עם `Quota exceeded for quota metric 'Write requests'`. משתמשים ב-`batchUpdate` עם מספר requests במקום במספר קריאות `batchUpdate`.
- **גופי request של batch update גדולים ומחרוזתיים.** כשמשהו משתבש, הודעת השגיאה מציינת index של request אבל בלי פירוט. התיקון הוא `console.log(JSON.stringify(requests, null, 2))` לפני הקריאה כך שאפשר לראות את ה-payload המדויק. הדבקתו לסנדבוקס "Try it" של Sheets API לעיתים קרובות מציפה את אי-התאמת ה-schema מהר יותר מהרצה מחודשת ב-Apps Script.
- **Drive advanced service אפילו יותר יקר מ-Sheets.** כשמפעילים את ה-advanced service של Drive כדי לחצות תיקיות או לשנות metadata של קבצים, כל קריאה מחזירה payload כבד של metadata כברירת מחדל. משתמשים בפרמטר `fields` (`{ fields: "id, name" }`) כדי לרזות את התשובה. בלעדיו, iteration על 500 קבצים יכול לפגוע במגבלות גודל תשובה.
- **הפעלת advanced service מרחיבה OAuth scopes.** מסך ההרשאות של הסקריפט מבקש עכשיו גישה רחבה יותר (למשל "See and modify your Sheets"). על פרויקט סקריפט משותף, כל משתמש חייב לאשר מחדש בריצה הבאה. לא מפעילים advanced services באופן רגיל על סקריפטים בפרודקשן שכל הצוות משתמש בהם; מתאמים את ה-rollout.
- **ה-`userSymbol` שלכם אבל בקונבנציה תואם ל-API.** אפשר לכתוב `"userSymbol": "MySheets"` ואז לקרוא ל-`MySheets.Spreadsheets.values.get(...)`, אבל זה מבלבל. שומרים אותו כ-`"Sheets"` כדי שהקוד שלכם יתאים לתיעוד ולתשובות ב-Stack Overflow.
