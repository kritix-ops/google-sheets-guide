# Apps Script + ה-Sheets advanced service: כש-SpreadsheetApp לא מספיק

`SpreadsheetApp` הוא ה-surface הידידותי שרוב Track 3 השתמש בו: objects ברמה גבוהה, ברירות מחדל שפויות, OAuth מטופל implicitly. הוא מכסה בערך 80% ממה שהצוות עושה ב-bound script. ה-20% הנותרים (יצירת pivot tables באופן תכנותי, conditional formatting בכמויות, copy-paste בין spreadsheets, כל דבר שנוגע ב-Sheets v4 REST API ישירות) צריך את ה-**Sheets advanced service**. זה global דק שנקרא `Sheets` שממפה 1:1 ל-endpoints של Sheets v4 REST, חושף יותר עוצמה, ומחליף קצת נוחות בשליטה.

השיעור הזה מכסה מתי להושיט יד ל-advanced service מול `SpreadsheetApp` רגיל, איך לאפשר אותו (רשומה ב-manifest), הצורה של `Sheets.Spreadsheets.values.get` ו-`update`, ה-`batchUpdate` עבור כל דבר שאין לו קיצור `values.*`, וצורות ה-response שמאפשרות לכם לשרשר עבודת המשך. אחרי השיעור הזה Track 3 גמור: יש לכם את המשטח המלא של Apps Script כדי לחבר כל אוטומציה של workbook שהצוות צריך.

## מתי להושיט יד ל-advanced service

| משימה | `SpreadsheetApp` | Advanced service |
|---|---|---|
| לקרוא כמה תאים, להגדיר ערך | שורה אחת | מוגזם |
| לעבור על sheet של 5,000 שורות | עם batching | אותו רעיון, מעט מהיר יותר |
| ליצור pivot table באופן תכנותי | לא נתמך | `Sheets.Spreadsheets.batchUpdate` עם request של `addPivotTable` |
| להוסיף 20 חוקי conditional-format בבת אחת | איטי (קריאה אחת לחוק) | `batchUpdate` אחד עם 20 איברי `addConditionalFormatRule` |
| להעתיק פורמט מ-sheet A ל-sheet B (workbooks שונים) | מסורבל | `batchUpdate` עם requests של `copyPaste` |
| להריץ request של Sheets API בדרך שה-REST docs מתעדים | משטח לא תואם | משקף את הצורה של REST |

אם אי פעם קראתם את [Sheets API REST reference](https://developers.google.com/sheets/api) וחשבתם "הלוואי שיכולתי לקרוא לזה מ-Apps Script", ה-advanced service הוא מה שמגשר על הפער. לכל דבר ב-REST docs יש מקבילה ב-Sheets advanced service.

## הפעלה (ריקוד manifest)

ה-advanced service חייב להיות מופעל פר-script. שתי דרכים לעשות את זה:

1. **UI של העורך**: ברצועה השמאלית של עורך Apps Script, לוחצים **Services then + then Google Sheets API then Add**. העורך מוסיף רשומה ל-manifest שלכם אוטומטית וסיימתם.
2. **עריכת manifest**: פותחים את `appsscript.json` (Project Settings then מסמנים "Show appsscript.json manifest file in editor") ומוסיפים את הרשומה `dependencies.enabledAdvancedServices` בעצמכם:

```json
{
  "timeZone": "America/New_York",
  "dependencies": {
    "enabledAdvancedServices": [
      {
        "userSymbol": "Sheets",
        "serviceId": "sheets",
        "version": "v4"
      }
    ]
  }
}
```

השדות:

| שדה | מה זה עושה |
|---|---|
| `userSymbol` | שם ה-global שהעורך יוצר. לפי מוסכמה `Sheets` כך שהקוד שלכם קורא `Sheets.Spreadsheets.values.get(...)`. אפשר לשנות; אף אחד לא משנה. |
| `serviceId` | ה-service ID הפנימי של Google. ל-Sheets זה `"sheets"`. שירותים advanced אחרים: `"drive"`, `"gmail"`, `"calendar"`. |
| `version` | גרסת API. Sheets ב-`v4`. |

אחרי שמירה, העורך מפעיל את ה-API התואם ב-GCP project הבסיסי אוטומטית (עבור projects של "default"). כשאתם מריצים את ה-function בפעם הראשונה, ה-OAuth consent prompt כולל עכשיו את ה-scope הרחב יותר שה-advanced service צריך.

## הצורה של קריאות advanced-service

שתי ה-methods שמכסות את רוב עבודת האדטק:

```js
function readSheetValues() {
  const spreadsheetId = SpreadsheetApp.getActiveSpreadsheet().getId();
  const response = Sheets.Spreadsheets.values.get(
    spreadsheetId,
    "Campaigns!F2:G61"
  );
  // response = { range: "Campaigns!F2:G61", majorDimension: "ROWS", values: [[412.5, 587.4], ...] }
  const rows = response.values || [];
  return rows;
}

function writeOneCell() {
  const spreadsheetId = SpreadsheetApp.getActiveSpreadsheet().getId();
  Sheets.Spreadsheets.values.update(
    { values: [[12345]] },         // body של request
    spreadsheetId,
    "Campaigns!J1",                // A1 range (כולל שם ה-sheet)
    { valueInputOption: "RAW" }    // פרמטרי query
  );
}
```

שלושה דברים ששווה להצמיד:

- **סדר הארגומנטים תואם ל-REST.** body קודם (כשיש), אז path params, אז query params. ל-methods של קריאה אין body והם מתחילים עם path params.
- **Ranges כוללים את שם ה-sheet.** `"Campaigns!F2:G61"`, לא `"F2:G61"`. ה-advanced service לא יודע על ה-active sheet בדרך ש-`SpreadsheetApp.getActiveSheet()` יודע.
- **`valueInputOption` חשוב.** `"RAW"` כותב את הערך כמו שהוא. `"USER_ENTERED"` מפרסר אותו כאילו משתמש הקליד אותו (אז `"=SUM(...)"` הופך לנוסחה, `"5/12/2026"` הופך לתאריך). ברירת המחדל ב-REST API היא ה-`"RAW"` השמרני יותר, אבל שווה להגדיר אותו במפורש.

## `batchUpdate` הוא הסוס העובד

ה-surface האחר הוא `Sheets.Spreadsheets.batchUpdate`, שמקבל מערך של **requests** בקריאה אחת. ה-requests יכולים לעשות הכל: להוסיף sheet, להוסיף pivot table, להגדיר conditional formats, להקפיא שורות, להסתיר עמודות, לעשות copy/paste בין ranges. דוגמה:

```js
Sheets.Spreadsheets.batchUpdate(
  {
    requests: [
      { addSheet: { properties: { title: "Monthly Rollup" } } },
      { addConditionalFormatRule: { rule: { /* ... */ } } },
      { repeatCell: { range: { /* ... */ }, cell: { /* ... */ }, fields: "userEnteredFormat" } },
    ],
  },
  spreadsheetId,
);
```

round-trip אחד מיישם את כל שלושת ה-requests באופן אטומי. מוסיפים 20 חוקי conditional-format עם 20 רשומות במערך; מקבלים קריאת רשת אחת במקום 20. ה-script של בונה ה-pivot של הצוות שנהג לקחת 90 שניות (יצירת sheets אחד בכל פעם, הגדרת פורמטים אחד בכל פעם) עכשיו לוקח 4 שניות עם הכל ב-`batchUpdate` יחיד.

## קריאת ה-response

כל קריאה של advanced-service מחזירה JS object רגיל שתואם לצורת ה-response של REST. `values.get` מחזיר `{ range, majorDimension, values }`. `batchUpdate` מחזיר `{ spreadsheetId, replies, updatedSpreadsheet? }`, כאשר `replies` הוא מערך של תוצאות פר-request (ה-reply של request `addSheet` כולל את ה-`sheetId` של ה-sheet החדש, שאתם יכולים לשרשר ל-request של המשך).

זה החלק שהופך את ה-advanced service לחזק. ה-reply object נושא את ה-IDs ואת ה-metadata שאתם צריכים כדי לשרשר עבודה נוספת, בדרך ש-`Sheet` objects של `SpreadsheetApp` לא יכולים.

## נפוץ בשטח

- **מחולל pivot תכנותי** (שיעורים 2.2 ו-2.3 מכסים את אותם מנגנוני pivot מצד ה-UI). הצוות צריך pivot פר-buyer-פר-platform שנבנה מחדש כל יום שני על נתוני השבוע הנוכחי. ל-`SpreadsheetApp` אין method ליצירת pivot; ל-`Sheets.Spreadsheets.batchUpdate` עם request של `updateCells` שמספק שדה `pivotTable` יש. trigger אחד של בוקר יום שני, קריאת batchUpdate אחת, pivot טרי.
- **העתקת פורמט בין-workbooks.** כשנוצר sheet חדש של dashboard חודשי (מ-template), הפורמט של ה-sheet של חודש שעבר חייב להיות מועתק: conditional formats, frozen rows, רוחבי עמודות. `batchUpdate` יחיד עם requests של `copyPaste` (`pasteType: "PASTE_FORMAT"`) מטפל בכל זה; עם `SpreadsheetApp` זה היה עשר קריאות נפרדות.
- **Conditional formatting בכמויות על עמודות חודשיות חדשות** (שיעור 2.6 מכסה את בונה החוקים ב-UI). כל חודש מוסיפים עמודה חדשה של spend / revenue / ROI ל-sheet פר-buyer. 20 חוקי conditional-format לתחזק (ירוק אם ROI > 1.5, צהוב אם 1.0-1.5, אדום מתחת). `batchUpdate` יחיד עם 20 רשומות `addConditionalFormatRule`; לוקח 2 שניות מול 40 במסלול פר-חוק של `SpreadsheetApp`.
- **Sheets API pagination על ranges ענקיים.** range של 500,000 תאים חושף את מגבלת גודל ה-response של Apps Script כשהוא נקרא דרך `SpreadsheetApp`. ה-advanced service תומך ב-paging דרך ranges בחלקים (`A1:A50000`, `A50001:A100000`, ...); כל קריאה מקבלת response בגודל סביר.
- **Vertex AI advanced service לקריאות Gemini.** Apps Script הוסיף **Vertex AI advanced service** ב-12 בינואר 2026 ([release notes](https://developers.google.com/apps-script/release-notes)). הוא קורא ל-Vertex AI API ישירות, עם OAuth שמטופל על ידי ה-wrapper של ה-advanced-service, כך ש-bound script יכול לבקש מ-Gemini טקסט או תמונות בלי לכתוב ידנית `UrlFetchApp` + auth tokens (שיעור 11 מכסה את המסלול הידני). לעבודה רגישה ל-audit-trail, זה המסלול ששיעור 5.6 ב-Track 5 מצביע עליו כחלופה הידידותית ל-`=AI()`: ריצה מתוזמנת כותבת ערכים literals ל-sheet, ה-script רושם את ה-prompt ואת ה-response, והתאים ניתנים לשחזור כי הם כבר לא נוסחאות. מפעילים את השירות באותה דרך כמו Sheets: פאנל **Services** בעורך, בוחרים **Vertex AI API**.

## מלכודות מקצועיות

- **`Sheets is not defined`** בגוף ה-function אומר שהרשומה ב-manifest עדיין לא שם. פאנל ה-Services של העורך מוסיף אותה; שמירת ה-manifest ביד גם עובדת. השגיאה לא נזרקת עד שה-function רצה, אז לא בוטחים ב-"זה מתקמפל"; מריצים פעם אחת לאימות.
- **`valueInputOption: "USER_ENTERED"` מפרסר באגרסיביות.** כתיבת המחרוזת `"5/12/2026"` כ-`USER_ENTERED` מתפרשת כתאריך (12 במאי ב-locale של ארה"ב, 5 בדצמבר ב-locale אירופי, תלוי ב-workbook). עבור טקסט גולמי ומספרים מחושבים מראש, `"RAW"` בטוח יותר. עבור ערכים שאמורים להתנהג כאילו הוקלדו (נוסחאות כמו `"=SUM(F2:F61)"`), `"USER_ENTERED"` נדרש.
- **Advanced services נספרים מול אותן מכסות פר-יום כמו `SpreadsheetApp` פלוס המכסות של Sheets API.** ל-Sheets API יש מכסה פר-project משלו (300 read requests/דקה, 60 write requests/דקה, free tier). trigger שעושה batchUpdates 100 פעמים בשעה יכול לפגוע במגבלת ה-write; ה-API מחזיר 429 וה-script שוגה עם `Quota exceeded for quota metric 'Write requests'`. משתמשים ב-`batchUpdate` עם מספר requests במקום בקריאות `batchUpdate` מרובות.
- **ה-bodies של request של batchUpdate גדולים ומחרוזתיים.** כשמשהו משתבש, הודעת השגיאה מזכירה אינדקס של request אבל ללא פירוט. התיקון הוא `console.log(JSON.stringify(requests, null, 2))` לפני הקריאה כך שתוכלו לראות את ה-payload המדויק. הדבקה ב-sandbox של "Try it" ב-Sheets API לרוב מציפה את אי-התאמת ה-schema מהר יותר מהרצה מחדש ב-Apps Script.
- **ה-advanced service של Drive יותר יקר מזה של Sheets.** כשמפעילים את ה-advanced service של Drive כדי לעבור על תיקיות או לשנות metadata של קבצים, כל קריאה מחזירה payload metadata כבד כברירת מחדל. משתמשים בפרמטר `fields` (`{ fields: "id, name" }`) כדי להקטין את ה-response. בלעדיו, איטרציה של 500 קבצים יכולה לפגוע במגבלות גודל response.
- **הפעלת advanced service מרחיבה OAuth scopes.** מסך ההרשאה של ה-script עכשיו מבקש גישה רחבה יותר (למשל, "See and modify your Sheets"). ב-script project משותף, כל משתמש חייב לתת consent מחדש בריצה הבאה. לא מפעילים advanced services בקלילות על scripts של production שכל הצוות משתמש בהם; מתאמים את ה-rollout.
- **ה-`userSymbol` שלכם אבל לפי מוסכמה תואם את ה-API.** אתם יכולים לכתוב `"userSymbol": "MySheets"` ואז לקרוא `MySheets.Spreadsheets.values.get(...)`, אבל זה מבלבל. משאירים אותו כ-`"Sheets"` כך שהקוד שלכם יתאים ל-docs ולתשובות ב-stack overflow.
- **`values.get` מחזיר `undefined` עבור `response.values`.** כשה-range המבוקש ריק לחלוטין, ה-response משמיט את שדה ה-`values` לחלוטין. תמיד מגדירים default עם `response.values || []` כדי שהקוד במורד לא יתפוצץ במקרה של sheet ריק.
