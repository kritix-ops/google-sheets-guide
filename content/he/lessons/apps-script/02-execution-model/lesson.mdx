# מודל ההרצה: V8, שירותים, מכסות, scopes

Apps Script נראה כמו JavaScript ורובו גם כן. מה ששונה זה סביבת ה-runtime: המנוע שמריץ את הקוד, הספריות שהוא חושף, המגבלות שהוא אוכף, ומערכת ההרשאות ששומרת על הכל. תקבלו תחושה לזה בשיעור 2 ושאר ה-Track יפסיק להפתיע אתכם.

המודל המנטלי שכדאי להחזיק בראש מההתחלה: כשאתם לוחצים Run בעורך, הקוד לא מתבצע בדפדפן שלכם. הוא נשלח ל-data center של Google, מתבצע שם על ידי runtime של Apps Script, והתוצאה נשלחת בחזרה. כל קריאה לשירות Sheets, Drive, Gmail, או כל שירות Workspace אחר היא קפיצה נוספת ברשת **בתוך** ה-data center הזה, אבל עדיין קפיצה. שתי ההשלכות (latency ומכסה) מעצבות את הדרך שבה כל function ריאליסטית של Apps Script נכתבת. שיעור 16 מבוסס על זה עם ה-playbook המלא של batching; השיעור הזה הוא על למה batching חשוב מלכתחילה.

## V8 vs Rhino

ל-Apps Script יש שני מנועים:

| Runtime | תקופה | מה מקבלים |
|---|---|---|
| Rhino | 2009-2020 | ניב ישן של ECMAScript 5.x. בלי `let`/`const`, בלי arrow functions, בלי template literals, בלי destructuring, בלי `async`/`await`. |
| V8 | 2020-היום | אותו מנוע שמריץ את Chrome. ECMAScript מודרני עם כל מה ששאר ה-ecosystem של JavaScript מניח. |

השדה `runtimeVersion` ב-manifest בוחר. **V8 הוא ברירת המחדל והבחירה הנכונה היחידה ל-projects חדשים.** הסיבה ש-Rhino עדיין קיים היא תאימות לאחור עם workbooks שיש להם triggers בני עשור שעדיין רצים. אם ירשתם project Rhino, המעבר הוא עריכה אחת ב-manifest (`"runtimeVersion": "V8"`) ובדיקה: אי-התאימות הנדירה היא סביב binding של `this` בתוך callbacks וכמה סמלים גלובליים מורשתיים ש-Rhino חשף (`importPackage`, וכו').

בפועל, V8 אומר שאתם כותבים Apps Script באותו JavaScript שאתם כותבים בכל מקום אחר:

```js
// Template literals, destructuring, optional chaining, הכל native:
function summarize(campaign) {
  const { buyer, vertical, spend } = campaign;
  return `${buyer} on ${vertical}: $${spend?.toFixed(2) ?? "0.00"}`;
}
```

מצאי קטן אבל שימושי של מה ש-V8 פותח שב-Rhino לא היה:

| תכונת V8 | חלופת Rhino |
|---|---|
| `let`, `const`, block scope | רק `var`, function scope |
| Arrow functions | ביטויי `function(){}` |
| Template literals `` `${x}` `` | שרשור מחרוזות עם `+` |
| Destructuring `const { a, b } = obj` | `var a = obj.a; var b = obj.b;` |
| פרמטרים עם default | `if (x === undefined) x = ...` ידני |
| `for...of` על מערכים | `for (var i = 0; ...)` קלאסי |
| `Array.from`, `Array.of`, spread `...` | טריקים של `Array.prototype.slice.call(...)` |
| Classes | פונקציות constructor + prototype |
| Optional chaining `a?.b` | `a && a.b` |
| Nullish coalescing `x ?? y` | `(x === null \|\| x === undefined) ? y : x` |
| `async/await` | שרשרות callback |

הקטע המעשי של השיעור הזה מאלץ אתכם להשתמש ב-template literal מפורש: זו תכונת V8-only שהכי סביר שתעקוץ אתכם אם תיפלו ב-project Rhino בטעות.

## שירותים

הספרייה הסטנדרטית של Apps Script מאורגנת ל-**שירותים**: top-level objects שמפעילים עליהם methods. אלה שב-workbook אדטק טיפוסי משתמשים בהם:

| שירות | בשביל מה |
|---|---|
| `SpreadsheetApp` | קריאה וכתיבה של תאים, טווחים, sheets. השירות הכי נוגעים בו. שיעור 4 מכסה לעומק. |
| `DriveApp` | רישום, יצירה, הזזה, שיתוף קבצים. הדרך למצוא sheets ל-IMPORTRANGE. שיעור 10 מכסה. |
| `UrlFetchApp` | HTTP יוצא. ככה pulls לילים של Taboola/Outbrain קורים (החלופה מצד ה-script לזרימה החיה של `IMPORTRANGE` משיעור 1.27). שיעור 11 מכסה. |
| `MailApp` / `GmailApp` | שליחת מייל. ה-mailer של "spend exceeded budget". שיעור 10. |
| `CalendarApp` | קריאה וכתיבה של events ביומן. פחות נפוץ באדטק. שיעור 10. |
| `ScriptApp` | ניהול triggers, deployments, ה-metadata של ה-script עצמו. שיעור 8. |
| `Session` | המשתמש הפעיל. `Session.getActiveUser().getEmail()` מחזיר מי מריץ. |
| `Utilities` | פורמט תאריכים, base64, טיפול ב-blob, sleep. עוזרים שלא מתאימים בשום מקום אחר. |
| `CacheService` / `PropertiesService` | אחסון key/value פר-script. Cache קצר-מועד; Properties קבוע. שיעור 15. |
| `LockService` | mutex כשני ריצות trigger יכולות להתחרות. חובה למשרות batch לילים. |
| `HtmlService` | רנדור של sidebar ו-dialog. שיעור 9. |
| `ContentService` | תגובות plain-text ו-JSON מ-web apps. שיעור 13. |
| `UserService` | deprecated. לא להשתמש. |

יש עוד (ה-"Advanced services" שאתם מפעילים ב-Resources מאפשרים לקרוא ל-Sheets API ברמה נמוכה יותר, ל-BigQuery API, ל-Admin SDK; שיעור 17 מכסה את Sheets advanced service בפירוט). עבור 90% של קוד workbook אתם חיים בטבלה שלמעלה.

קריאה לשירות היא שרשרת methods:

```js
const sheet = SpreadsheetApp.getActiveSpreadsheet()
  .getSheetByName("Aggregator");
const lastRow = sheet.getLastRow();
const data = sheet.getRange(2, 1, lastRow - 1, 7).getValues();
```

כל קריאת method היא round-trip לשרתי Google. השיעור על `SpreadsheetApp` (שיעור 4) מכסה איך לעשות batch של reads ו-writes כך שלא משלמים round-trip פר-תא. שיעור 16 מכסה batching בין שירותים.

## מכסות

Apps Script אוכף שלושה סוגי מגבלות:

**timeout פר-execution.** ריצה אחת של script לא יכולה להימשך לנצח:

| סוג חשבון | זמן ריצה מקסימלי |
|---|---|
| Consumer (gmail.com) | 6 דקות |
| Workspace | 30 דקות |

script שמגיע לזה נהרג באמצע כתיבה. התיקון הוא לשבור משרות ארוכות לחתיכות ולהפעיל מחדש דרך `ScriptApp.newTrigger(...).timeBased().at(...)` (מכוסה בשיעור 8): המתכון לעיבוד 200,000 שורות קמפיין הוא חתיכה של 50,000 שורות על trigger שמחמש את עצמו מחדש.

**מכסות יומיות פר-שירות.** לכל שירות יש cap יומי משלו. אלה שהכי כואבות:

| שירות | מכסה חינמית | מכסת Workspace |
|---|---|---|
| `UrlFetchApp` | 20,000/יום | 100,000/יום |
| `MailApp.sendEmail` | 100/יום | 1,500/יום |
| זמן ריצה כולל של trigger | 90 דקות/יום | 6 שעות/יום |
| קריאות Sheets API מ-custom functions | 30,000/יום | 30,000/יום (אותו דבר) |

המספרים זזים עם הזמן; הנוכחיים נמצאים ב-`developers.google.com/apps-script/guides/services/quotas`. שני pattern רלוונטיים:

- **trigger לילי אחד שעושה 20,000 קריאות UrlFetchApp רווה את המכסה החינמית.** אם אתם צריכים יותר, מקבילים בין כמה projects של Apps Script (לכל אחד יש דלי מכסה משלו) או עוברים לחשבון Workspace בתשלום.
- **המגבלה של MailApp של 100/יום היא פר-script, לא פר-משתמש.** script יחיד ששולח לכל חבר צוות יומית על הקמפיינים שלהם רווה מהר. משתמשים ב-`GmailApp.sendEmail` (1,500/יום בחינם, 10,000 ב-Workspace) ל-mailing בנפח גבוה יותר.

**מגבלות קצב פר-דקה.** לרוב השירותים יש גם מגבלת burst פר-דקה: `UrlFetchApp` מאפשר בערך 600/דקה. נוגעים בזה ומקבלים exception `Service invoked too many times in a short time`. החוכמה של Apps Script היא `Utilities.sleep(100)` בין קריאות ב-batch: ביטוח זול.

## OAuth scopes

לכל קריאת שירות נדרשת הענקת הרשאה. ה-manifest מצהיר על scopes במפורש:

```json
"oauthScopes": [
  "https://www.googleapis.com/auth/spreadsheets.currentonly",
  "https://www.googleapis.com/auth/script.container.ui",
  "https://www.googleapis.com/auth/script.external_request"
]
```

| Scope | מה זה פותח |
|---|---|
| `spreadsheets.currentonly` | קריאה/כתיבה רק ב-spreadsheet הפעיל. ה-scope הצר השימושי. |
| `spreadsheets` | קריאה/כתיבה בכל spreadsheet שהמשתמש יכול לגשת. |
| `drive.file` | קריאה/כתיבה של קבצים שה-app הזה יצר או שהמשתמש פתח איתו במפורש. |
| `drive` | גישה מלאה ל-Drive. ה-scope הכי מפחיד לבקש. |
| `script.container.ui` | הצגת sidebars, dialogs, custom menus. |
| `script.external_request` | קריאה ל-`UrlFetchApp`. |
| `script.send_mail` | קריאה ל-`MailApp.sendEmail`. רק שליחה, אין גישה ל-inbox. |
| `gmail.modify` | קריאה ל-`GmailApp.*`. כולל קריאה ושינוי של threads. |
| `calendar` | קריאה/כתיבה מלאה של Calendar. |
| `userinfo.email` | קריאת המייל של המשתמש הפעיל. |
| `script.scriptapp` | רישום ומחיקה של triggers (שיעור 8). |

**תמיד מעדיפים scopes צרים.** script bound שרק צריך את ה-workbook הפעיל צריך להשתמש ב-`spreadsheets.currentonly`, אף פעם לא ב-`spreadsheets`. שתי סיבות:

1. **ה-auth prompt נראה פחות מפחיד.** משתמשים נוטשים scripts שמבקשים "Manage your spreadsheets in Drive" כש-"Manage just this spreadsheet" זה מה שהם באמת עושים.
2. **הנזק אם ה-script נפרץ מוגבל.** script עם scope `drive` שנפרץ יכול לחלץ כל קובץ. script עם `drive.file` יכול לגעת רק בקבצים שהוא יצר.

בהרצה הראשונה, המשתמש רואה מסך consent שמפרט כל scope. הוא מקבל או מסרב. מוסיפים קריאת שירות חדשה מאוחר יותר? Apps Script מרחיב אוטומטית את רשימת ה-scopes, ההרצה הבאה תבקש שוב. זה מעצבן את המשתמש אבל זה איך שחוזה ההרשאות נשאר מפורש.

## עכשיו לעבודה אמיתית

ל-project המקושר של השיעור הזה יש קובץ `Lesson.gs` עם stub של `quotaSummary(perDay, perMinute)`. שתי משימות:

1. עורכים את ה-body כדי להחזיר את ה-template literal `` `${perDay} per day, ${perMinute} per minute` ``. Template literals הם V8-only: זה ה-hook של השיעור.
2. בתא **A1**, קוראים ל-`=quotaSummary(20000, 600)`. אלה המכסה הצרכנית של UrlFetchApp והקצב פר-דקה, אז התא מציג בסוף "20000 per day, 600 per minute": המגבלות בפועל שתתכננו סביבן כשתכתבו pulls לילים בשיעור 11.

## נפוץ בשטח

projects אמיתיים של Apps Script ב-workbooks של הצוות:

- **`appsscript.json` נושא 4-6 scopes מקסימום.** כל יותר זה או overscoping או עושים יותר מדי דברים ב-project אחד: מפצלים ל-script פר-עניין.
- **`Utilities.sleep(100)` בין כל `UrlFetchApp.fetch`.** חגורה ושלייקעס נגד ה-throttle פר-דקה.
- **mailer של סיכום לילי שמפוצל לשתי functions.** אחד שאילתה את ה-workbook לנתונים; השני מפרמט ושולח. המכסה ל-`MailApp.sendEmail` נבדקת בתחילת ה-function השני: אם מומצה, לוג ל-Aggregator ודולגים על mailing לליל הזה.
- **ניקוי Drive יומי שמשתמש ב-`DriveApp.searchFiles` פעם אחת ומעבד את התוצאה בזיכרון.** הגרסה הנאיבית הייתה קוראת ל-`getFileById` פר-שורה של גיליון רשימת מועמדים; גרסת הצוות קוראת את כל המועמדים בשאילתה אחת ומחברת אותם מול הגיליון ב-JavaScript. חוסך כ-200 round-trips פר-ריצה.
- **`UrlFetchApp.fetchAll` לכל pull שפוגע ביותר מקומץ endpoints.** שיעור 11 מכסה את הצורה; ה-punchline הוא ש-fetchAll מריץ requests במקביל מקריאת Apps Script אחת, מה שגם חוסך מכסה וגם מסיים פי 5 עד פי 10 מהר יותר מ-loop טורי.

## מלכודות מקצועיות

- **"ה-script שלי רץ אתמול אבל היום מבקש הרשאה שוב."** הוספתם קריאת שירות חדשה שצריכה scope חדש. Apps Script הרחיב אוטומטית את סט ה-scopes; ההרצה הבאה תבקש שוב. התיקון הוא או להצהיר על scopes במפורש ב-manifest (כך שתוספות מכוונות) או להזהיר את הצוות לפני כל rollout שיראו prompt טרי אחד.
- **ה-timeout של 6 דקות שמתחבא מאחורי triggers.** trigger לילי שמצליח חודשים על נתונים קטנים מתחיל בשקט להיכשל ביום שהנתונים גדלים מעבר למגבלה. רושמים את זמן ההתחלה בראש כל function ארוכה ואת זמן הסיום בתחתית; כשהפער מתקרב ל-5 דקות, אתם יודעים לעשות refactor.
- **`UrlFetchApp.fetch` שמחזיר את אותה תגובה פעמיים.** ה-cache לקריאות `muteHttpExceptions: false` אגרסיבי. מעבירים `muteHttpExceptions: true` וקוראים את קוד התגובה בעצמכם, או מצמידים פרמטר cache-busting ל-URL.
- **custom function שצורכת מכסת UrlFetchApp.** שיעור 3 מכסה caching מצד התא; הנה הצד של המכסה. כל tuple ארגומנטים שונה ל-`=fetchSomething(x, y)` הוא קריאה אחת. spreadsheet עם 50,000 תאים שקורא ל-custom function מבוססת `UrlFetchApp` ירווה את המכסה היומית בפתיחה אחת.
- **triggers מרובים מתחרים על אותם נתונים.** trigger A לליל ראשון רץ שוב כי הריצה הקודמת קרסה; ריצה ידנית B נורית ביום שני בבוקר ל-backfill. שניהם כותבים ל-Aggregator במקביל. השתמשו ב-`LockService.getScriptLock().tryLock(30 * 1000)` בראש כל trigger שמשנה state משותף.
- **Timeout פר-execution שמתערב עם `fetchAll`.** batch של `fetchAll` של 100 requests חוסם על האיטי ביותר. אם endpoint אחד עובר דקה רעה, כל ה-batch מחכה. מפצלים ל-batches פר-שירות; כך שירות איטי אחד לא חוסם מהירים.
- **קוד בסגנון Rhino שנשלח בטעות ל-project V8.** חבר צוות מדביק תשובה מ-Stack Overflow מ-2014 עם `var` ו-`Array.prototype.forEach.call(...)`. זה רץ, אבל מתנהג מוזר סביב `this` binding ומפריע ל-patterns שניתן לחפש שאר ה-codebase משתמש בהם. סטנדרטיזציה על `const`/`let`, callbacks של arrow, ו-array methods מודרניות.
- **התרחבות scope אוטומטית כשובר שקט.** הוספת `GmailApp.search` ל-script שהיה מורשה בעבר רק ל-`spreadsheets.currentonly` לא זורקת; היא מרחיבה את סט ה-scopes וההרצה הבאה מציגה auth prompt חדש. חבר הצוות שמריץ אותו לפני שמייל ה-rollout מגיע רואה prompt לא מוסבר ונעשה עצבני.
