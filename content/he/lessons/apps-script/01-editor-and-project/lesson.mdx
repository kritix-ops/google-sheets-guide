# עורך Apps Script ומבנה הפרויקט

Apps Script הוא JavaScript שרץ בתוך Google Workspace. הוא לא plug-in, לא שפת מאקרו עם syntax משלה, ולא VBA של Excel עם זקן. הוא JavaScript רגיל (הניב של V8, שיעור 2) שרץ על שרתי Google, עם ספרייה סטנדרטית שממופה ל-Sheets, Drive, Gmail, Calendar, Docs ועוד עשרות שירותי Workspace. אם אתם יכולים לכתוב לולאת `for` בכל קוד JavaScript אחר, אתם יכולים לכתוב Apps Script.

הקוד יושב ב-**project**, תיקייה של קבצים ש-Google מארחת, מצורפת או למסמך מסוים ("bound") או לשום דבר ("standalone"). השיעורים ב-Track הזה משתמשים כולם ב-projects מסוג bound. לכל workbook שאתם פותחים בקורס יש project מצורף תחת Extensions → Apps Script. ה-sidebar שאתם קוראים עכשיו הוא קובץ אחד באותו project. ה-custom functions שתכתבו בשיעור 3 יהיו קובץ נוסף. ה-triggers בשיעורים 7 ו-8 יהיו השלישי. הכל במקום אחד, עם version control של Google, נגיש רק מתוך ה-workbook.

השיעור הראשון הזה עוסק במפת השטח: איפה העורך גר, אילו קבצים יש בפרויקט, איך ה-manifest עובד, וסט קטן של הרגלים ששומרים על פרויקט נווט ככל שהוא גדל משלושה קבצים לשלושים. ה-APIs העמוקים יותר (`SpreadsheetApp`, triggers, libraries) מתחילים בשיעור 2.

## פותחים את העורך

מתוך Google Sheet פתוח:

1. **Extensions → Apps Script.** העורך נפתח בטאב חדש.
2. **מחכים שעץ הקבצים בצד יטען.** הפתיחה הראשונה של project bound חדש לוקחת שתי שניות בזמן ש-Google מקצה את ה-storage.
3. **הפריסה המוגדרת:** עץ קבצים בצד, עורך קוד במרכז, פאנל של execution log/output למטה, סרגל Run/Debug למעלה, ואייקוני הרצועה השמאלית (Files, Triggers, Executions, Project Settings, Editor, Libraries, Services) בקצה.

בפעם הראשונה שהעורך נפתח עבור workbook שלא בבעלותכם, Google עלולה לבקש שתאשרו את ה-auth scopes של הפרויקט. ה-prompt עוין בכוונה ("Sheets Guide isn't verified: proceed anyway?"). עבור ה-bound projects של הקורס, לוחצים "Advanced → Go to Sheets Guide (unsafe)". זה ה-bound script שלכם; "unsafe" כאן רק אומר ש-Google לא סקרה אותו כי אף אחד לא מפרסם script פר-workbook.

אותה נקודת כניסה Extensions → Apps Script עובדת גם מתוך Google Doc, Form או Slide. העורך משותף בין כל Workspace; רק ה-bindings משתנים.

## מה יש בפרויקט

project של Apps Script מסוג bound מכיל קבצים משלושה סוגים:

| סוג | סיומת | מה זה |
|---|---|---|
| Server JS | `.gs` | JavaScript שרץ על שרתי Google. רוב הקוד שלכם. |
| HTML | `.html` | תוכן sidebar ו-dialog. נרנדר בתוך ה-UI של Sheets. שיעור 9 מכסה את זה לעומק. |
| JSON manifest | `appsscript.json` | הגדרות הפרויקט: timezone, oauthScopes, runtime version, dependencies. תמיד קובץ אחד בלבד בשם הזה. |

עץ הקבצים מציג קבצים לפי סדר היצירה. גוררים כדי לשנות סדר. **אין מבנה של תיקיות, projects שטוחים.** זה תופס מפתחים מכל ecosystem אחר לא מוכן. אי אפשר ליצור תיקיית `lib/`. כדי לארגן פרויקט שגדל, נותנים שמות עם prefix: `lib_Dates.gs`, `lib_Strings.gs`, `triggers_Daily.gs`, `triggers_OnEdit.gs`, `ui_Sidebar.gs`. העורך ממיין לפי אלפבית וה-prefix מקבץ קבצים קשורים. זו המוסכמה של הצוות; ל-runtime לא אכפת.

### מה "Server JS" באמת אומר

תוכן של קובץ `.gs` הוא JavaScript רגיל, אבל ה-runtime **אינו** דפדפן. אין `window`, אין `document`, אין `localStorage`, אין `fetch` (התפקיד הזה ממולא על ידי `UrlFetchApp` במקום, מכוסה בשיעור 11). אין גם `require` בסגנון Node ואין npm. כל dependency מגיע או משירותים מובנים של Apps Script או מספרייה מיובאת דרך ה-manifest (שיעור 12). הקוד רץ על תשתית של Google עם תקציב ביצוע של 6 דקות לכל ריצה, אותו דבר בחשבונות consumer ו-Workspace.

כל function declaration ברמת ה-top של כל קובץ `.gs` קריא מה-Run dropdown של העורך, מפריט תפריט, מ-trigger, או (אם הוא מתאים לחוקי custom function משיעור 3) מתא. אין `main()`, אין רישום ב-manifest פר-function. ההצהרה לבדה מספיקה.

## ה-manifest ניתן לעריכה

קובץ ה-manifest `appsscript.json` מוסתר בדרך כלל. מפעילים אותו: **Project Settings → Show "appsscript.json" manifest file in editor**. תצטרכו לערוך אותו עבור triggers, OAuth scopes, advanced services, library dependencies, ו-add-on manifests. ההסתרה כברירת מחדל מגנה על מתחילים מלשבור את הפרויקט עם typo; ברגע שתגיעו לשיעור 6 (macros) או שיעור 12 (libraries) תערכו אותו שבועית.

manifest מייצג:

```json
{
  "timeZone": "America/New_York",
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "oauthScopes": [
    "https://www.googleapis.com/auth/spreadsheets.currentonly",
    "https://www.googleapis.com/auth/script.container.ui"
  ]
}
```

השדות:

| שדה | טיפוס | מה זה עושה |
|---|---|---|
| `timeZone` | מחרוזת IANA zone | איך הפרויקט מפרש תאריכים ובאיזה timezone `new Date()` פועל. ה-manifest של הקורס משתמש ב-`America/New_York` (תואם לדוחות של Taboola). מגדירים ל-`Asia/Jerusalem` עבור projects ש-triggers שלהם צריכים לפעול בשעון ישראל. |
| `exceptionLogging` | `"STACKDRIVER"` או `"NONE"` | מנתב שגיאות ל-Cloud Logging או בולע אותן. כמעט תמיד `"STACKDRIVER"`. שיעור 14 מכסה את Cloud Logging מקצה לקצה. |
| `runtimeVersion` | `"V8"` או (מורשת) `"DEPRECATED_ES5"` | בוחר את מנוע ה-JavaScript. **`"V8"` הוא הבחירה היחידה;** Rhino (הערך `DEPRECATED_ES5`) הפסיק להריץ קוד ב-31 בינואר 2026. שיעור 2 מכסה את ה-sunset. |
| `oauthScopes` | מערך של scope URLs | הרשימה המפורשת של הרשאות שהפרויקט צריך. Apps Script מזהה אותן אוטומטית בהרצה הראשונה כשהשדה ריק; הצהרה מפורשת היא תרגול עדיף. |
| `dependencies` | object | imports של ספריות והפעלות של advanced services. שיעור 12 מכסה libraries; שיעור 17 מכסה advanced services. |
| `sheets.macros` | מערך | רישומי המאקרו שעולים תחת Tools → Macros. שיעור 6 מכסה את השדה הזה בפירוט. |

### למה הצהרת scopes מפורשת חשובה

Apps Script יכול לזהות את ה-scopes שפרויקט צריך על ידי סריקת הקוד לקריאות שירות (`MailApp.sendEmail` ← scope של mail-send, `UrlFetchApp.fetch` ← scope של external-request, וכו'). הוא ימלא את ה-auth prompt בהתאם בהרצה הראשונה. אז למה להצהיר?

שתי סיבות. ראשית, מערך `oauthScopes` מפורש מתעד במה הפרויקט נוגע, במקום אחד, בקובץ שנמצא ב-diff של היסטוריית ה-workbook של הצוות. שנית, זיהוי אוטומטי מרחיב בשקט את סט ה-scopes בכל פעם שמוסיפים קריאת שירות חדשה, מה שאומר שחבר צוות נתקל ב-prompt חדש של "האם אתם מקבלים את ההרשאות האלה?" בזמנים אקראיים בלי להבין למה. הצהרה מפורשת מקבעת את חוזה ה-scope; scopes חדשים נכנסים ל-prompt רק כשמכניסים אותם ל-manifest בכוונה.

## שמירה, הרצה ופריסה

עריכת קובץ נשמרת אוטומטית ל-draft המקומי של העורך, אבל היא לא מתחייבת לפרויקט עד שלוחצים **Save project** (Ctrl/Cmd+S, או אייקון הדיסקט). אחרי שמירה:

- **קבצי `.gs`** הופכים מיד לקריאים מתאים כ-custom functions ומהתפריט כ-macros.
- **קבצי HTML** מתעדכנים בפתיחה הבאה של ה-sidebar.
- **ה-manifest** נכנס לתוקף בהרצה הבאה; אם שיניתם `oauthScopes`, ההרצה הבאה תבקש מהמשתמש לאשר את סט ה-scopes החדש.

ה-dropdown של Run בראש העורך מאפשר לבחור כל function בפרויקט ולהריץ אותה פעם אחת לצורכי דיבאג. משתמשים בזה כדי להריץ function של setup ידנית לפני שמחברים אותה ל-trigger, או כדי לבדוק custom function מתוך העורך בלי לעבור דרך תא.

### Save מול Deploy

נקודת בלבול נפוצה: **Save זה לא Deploy.** Save מתחייב את העריכות שלכם ל-HEAD revision של הפרויקט; העורך והתאים המקושרים רואים מיד את הקוד החדש. **Deploy** (Deploy → New deployment או Manage deployments) מקפיא snapshot תחת מספר version, וזו הדרך שבה libraries (שיעור 12) ו-web apps (שיעור 13) מקבלים משטח יציב מול הצרכן. עבור script bound טיפוסי שרץ רק מתפריטים ו-triggers באותו workbook, ייתכן שלעולם לא תפרסו: Save מספיק.

## עכשיו לעבודה אמיתית

ל-project המקושר של השיעור הזה יש קובץ `Lesson.gs` עם stub של `projectName()`. שתי משימות:

1. פותחים **Extensions → Apps Script** ועורכים את `Lesson.gs`. מחליפים את `return null;` ב-`return SpreadsheetApp.getActiveSpreadsheet().getName();`. שומרים את הפרויקט.
2. חוזרים ל-spreadsheet, בתא **A1**, מקלידים `=projectName()`. התא צריך להציג את שם ה-workbook הזה.

תופיע פעם אחת auth prompt בפעם הראשונה שהתא יבצע הערכה, Apps Script צריך הרשאה לקרוא את ה-spreadsheet בשמכם. מאשרים; הרצות הבאות משתמשות באותו אישור.

## נפוץ בשטח

ל-project המקושר של workbook של צוות יש בדרך כלל רשימה שטוחה של קבצים מקובצים לפי prefix. snapshot מציאותי מ-workbook האגרגטור האדטק:

| קובץ | מטרה |
|---|---|
| `appsscript` | Manifest. מגדיר את ה-timezone של הצוות (`America/New_York`), מצהיר על כל ה-scopes הנחוצים, מפרט את ארבעת המאקרו שעולים תחת Tools → Macros, ומקבע את `SheetsLib` כ-dependency של library. |
| `Code` (נקודת כניסה) | בונה התפריט המותאם, נקרא מ-`onOpen`. שלושה תפריטים: Reports, Buyers, Cleanup. כל פריט מאציל ל-handler בקובץ `triggers_*` או `actions_*`. |
| `lib_dates.gs` | עוזרי תאריך: ניתוח של מחרוזות `YYYY-MM-DD` של הצוות, חישוב יום העסקים הקודם, פורמט לתצוגה. |
| `lib_verticals.gs` | מנרמל שמות vertical (מבטיח סופית ` PR`), והחיפוש של רשימת ה-buyer הקנונית. |
| `triggers_nightly.gs` | האגרגטור הלילי שמושך שורות raw של Taboola, Outbrain, MediaGo, TikTok וכותב אותן ל-tab של Aggregator. שיעור 8 מכסה איך ה-trigger נרשם. |
| `triggers_onedit.gs` | ה-handler של on-edit שמחתים אוטומטית את כתובת המייל של העורך כשתא Spend משונה. שיעור 7 מכסה את גרסת ה-simple-trigger. |
| `actions_bulk.gs` | ה-handlers של "Mark dead campaigns" ו-"Archive month" מחוברים לפריטי תפריט. |
| `ui_sidebar.html` | ה-sidebar של בונה הקמפיינים שמלווה buyer דרך מתן שם והפעלה של קמפיין חדש. שיעור 9 מכסה את HtmlService. |

חלוקה לפי prefix היא המוסכמה של הצוות. אף כלי לא אוכף את זה; זו פשוט הרגל שהופך project של שלושים קבצים לניתן לניווט. שימו לב שאין `main.gs`: נקודת הכניסה היא מתקין התפריט ב-`Code.gs`, והקליק הראשון של המשתמש על פריט תפריט הוא מה שמתחיל עבודה אמיתית.

## מלכודות מקצועיות

- **Bound vs standalone.** מחזור החיים של script bound הוא של ה-spreadsheet. אם מוחקים את ה-spreadsheet, ה-script הולך איתו. צריכים אותה לוגיקה בכמה workbooks? בונים standalone script ומושכים אותו כספרייה (שיעור 12).
- **ה-dashboard ב-script.google.com.** scripts מסוג bound לא מופיעים ברשימת "My projects" שלכם ב-script.google.com. כדי למצוא אותם, פותחים את ה-workbook והולכים ל-Extensions → Apps Script. זו נקודת הכניסה היחידה. חברי צוות שמאבדים מעקב אחרי "באיזה workbook היה ה-script הזה" עורכים ביקורת על כל workbook משותף אחד-אחד.
- **שינוי שם של `Code.gs`.** טכנית לא שובר כלום. ל-runtime של Apps Script לא אכפת איך הקובץ נקרא. אבל כל מי שיפתח את הפרויקט יחפש קודם את `Code.gs` מתוך הרגל, אז משאירים את קובץ נקודת הכניסה בשם הזה.
- **עריכת שני tabs של אותו project בו-זמנית.** עורך Apps Script לא מציג אזהרות conflict בזמן אמת. שני tabs פתוחים על אותו project ידרסו זה את זה בשקט בשמירה. אם עוברים בין מחשבים, סוגרים tab אחד לפני שפותחים בשני.
- **גרסאות של Apps Script.** כל שמירה יוצרת HEAD revision חדש, אבל רק deployments עם version הם immutable. כדי לחזור ל-"מה שרץ אתמול", הולכים לתפריט הקובץ בעורך (זה מוסתר שתי לחיצות עמוק בעורך החדש: אייקון שמאל-עליון → File → See version history). שמרו את זה כסימנייה; תצטרכו את זה בפעם הראשונה ש"עריכה לא מזיקה" של חבר צוות תשבור את ה-trigger הלילי.
- **scopes שמזוהים אוטומטית נסחפים בכל עריכה.** אם משאירים את `oauthScopes` ריק, Apps Script מרחיב בשקט את סט ה-scopes בכל פעם שמוסיפים קריאת שירות. חברי צוות פתאום רואים הרשאות חדשות בהרצה הבאה שלהם בלי הקשר. מצהירים על scopes במפורש והחוזה נשאר יציב.
- **מלכודת שינוי שם של `appsscript.json`.** חלק מהלומדים מנסים לשנות את שם ה-manifest ל-`manifest.json` או דומה; Apps Script לא יקלוט אותו. שם הקובץ קבוע. אותו דבר עבור snapshots של `appsscript.json.bak`: ה-runtime מתעלם מכל דבר חוץ מ-`appsscript.json` המילולי.
