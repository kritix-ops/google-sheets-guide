# עורך Apps Script ומבנה הפרויקט

Apps Script הוא JavaScript שרץ בתוך Google Workspace. הוא לא plug-in, לא שפת מאקרו עם syntax משלה, ולא VBA של Excel בתחפושת. הוא JavaScript רגיל (בדיאלקט V8, שיעור 2) שרץ על השרתים של Google, עם ספרייה סטנדרטית שממופה ל-Sheets, Drive, Gmail, Calendar, Docs ועוד עשרות שירותי Workspace. אם אתם יודעים לכתוב לולאת `for` בכל קוד JavaScript אחר, אתם יודעים לכתוב Apps Script.

הקוד יושב ב-**project**: תיקייה של קבצים ש-Google מארחת, מצורפת או למסמך מסוים ("bound") או לשום דבר ("standalone"). השיעורים ב-Track הזה משתמשים כולם ב-projects מסוג bound. לכל workbook שאתם פותחים בקורס יש project מצורף תחת Extensions → Apps Script. ה-sidebar שאתם קוראים בו עכשיו הוא קובץ אחד באותו project. ה-custom functions שתכתבו בשיעור 3 יהיו קובץ נוסף. ה-triggers בשיעורים 7 ו-8 יהיו השלישי. הכל במקום אחד, עם version control של Google, נגיש רק מתוך ה-workbook.

השיעור הראשון הזה עוסק במפת השטח: איפה העורך נמצא, אילו קבצים יש בפרויקט, איך ה-manifest עובד, וסט קטן של הרגלים ששומרים על פרויקט נוח לניווט ככל שהוא גדל משלושה קבצים לשלושים. ה-APIs העמוקים יותר (`SpreadsheetApp`, triggers, libraries) מתחילים בשיעור 2.

## פותחים את העורך

מתוך Google Sheet פתוח:

1. **Extensions → Apps Script.** העורך נפתח בטאב חדש.
2. **מחכים שעץ הקבצים בצד ייטען.** הפתיחה הראשונה של project bound חדש לוקחת כמה שניות בזמן ש-Google מקצה את ה-storage.
3. **פריסת ברירת המחדל:** עץ קבצים בצד, עורך קוד במרכז, פאנל של execution log/output למטה, סרגל Run/Debug למעלה, ואייקוני הרצועה השמאלית (Files, Triggers, Executions, Project Settings, Editor, Libraries, Services) בקצה.

בפעם הראשונה שהעורך נפתח עבור workbook שלא בבעלותכם, Google עלולה לבקש שתאשרו את ה-auth scopes של הפרויקט. ה-prompt עוין בכוונה ("Sheets Guide isn't verified: proceed anyway?"). עבור ה-bound projects של הקורס, לוחצים "Advanced → Go to Sheets Guide (unsafe)". זה bound script שלכם; "unsafe" כאן רק אומר ש-Google לא סקרה אותו כי אף אחד לא מפרסם script פר-workbook.

אותה נקודת כניסה של Extensions → Apps Script עובדת גם מתוך Google Doc, Form או Slide. העורך משותף בכל Workspace; רק ה-bindings משתנים.

## מה יש בפרויקט

project של Apps Script מסוג bound מכיל קבצים משלושה סוגים:

| סוג | סיומת | מה זה |
|---|---|---|
| Server JS | `.gs` | JavaScript שרץ על שרתי Google. רוב הקוד שלכם. |
| HTML | `.html` | תוכן sidebar ו-dialog. נרנדר בתוך ה-UI של Sheets. שיעור 9 מכסה את זה לעומק. |
| JSON manifest | `appsscript.json` | הגדרות הפרויקט: timezone, oauthScopes, runtime version, dependencies. תמיד קובץ אחד בלבד בשם הזה. |

עץ הקבצים מציג את הקבצים לפי סדר היצירה. גוררים כדי לשנות את הסדר. **אין מבנה של תיקיות: projects הם שטוחים.** זה תופס לא מוכנים מפתחים שמגיעים מכל ecosystem אחר. אי אפשר ליצור תיקיית `lib/`. כדי לארגן פרויקט שגדל, נותנים שמות עם prefix: `lib_Dates.gs`, `lib_Strings.gs`, `triggers_Daily.gs`, `triggers_OnEdit.gs`, `ui_Sidebar.gs`. העורך ממיין לפי אלפבית וה-prefix מקבץ קבצים קשורים. זו המוסכמה של הצוות; ל-runtime לא אכפת.

### מה "Server JS" באמת אומר

התוכן של קובץ `.gs` הוא JavaScript רגיל, אבל ה-runtime **אינו** דפדפן. אין `window`, אין `document`, אין `localStorage`, אין `fetch` (את התפקיד הזה ממלא `UrlFetchApp` במקום, מכוסה בשיעור 11). אין גם `require` בסגנון Node ואין npm. כל dependency מגיע או משירותים מובנים של Apps Script או מספרייה שמיובאת דרך ה-manifest (שיעור 12). הקוד רץ על התשתית של Google עם תקציב ביצוע של 6 דקות לכל ריצה, אותו דבר בחשבונות consumer ו-Workspace.

כל function declaration ברמת ה-top של כל קובץ `.gs` ניתן לקריאה מה-Run dropdown של העורך, מפריט תפריט, מ-trigger, או (אם הוא מתאים לחוקי custom function משיעור 3) מתא. אין `main()`, אין רישום ב-manifest פר-function: ההצהרה לבדה מספיקה.

## ה-manifest ניתן לעריכה

קובץ ה-manifest `appsscript.json` מוסתר בדרך כלל. מפעילים אותו דרך: **Project Settings → Show "appsscript.json" manifest file in editor**. תצטרכו לערוך אותו עבור triggers, OAuth scopes, advanced services, library dependencies ו-add-on manifests. ההסתרה כברירת מחדל מגנה על מתחילים מלשבור את הפרויקט עם typo; ברגע שתגיעו לשיעור 6 (macros) או לשיעור 12 (libraries) תערכו אותו כל שבוע.

manifest לדוגמה:

```json
{
  "timeZone": "America/New_York",
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "oauthScopes": [
    "https://www.googleapis.com/auth/spreadsheets.currentonly",
    "https://www.googleapis.com/auth/script.container.ui"
  ]
}
```

השדות:

| שדה | טיפוס | מה זה עושה |
|---|---|---|
| `timeZone` | מחרוזת IANA zone | איך הפרויקט מפרש תאריכים ובאיזה timezone `new Date()` פועל. ה-manifest של הקורס משתמש ב-`America/New_York` (תואם לדוחות Taboola של הצוות). מגדירים ל-`Asia/Jerusalem` עבור projects ש-triggers שלהם אמורים לפעול בשעון ישראל. |
| `exceptionLogging` | `"STACKDRIVER"` או `"NONE"` | מנתב שגיאות ל-Cloud Logging או בולע אותן. כמעט תמיד `"STACKDRIVER"`. שיעור 14 מכסה את Cloud Logging מקצה לקצה. |
| `runtimeVersion` | `"V8"` או (legacy) `"DEPRECATED_ES5"` | בוחר את מנוע ה-JavaScript. **`"V8"` הוא הבחירה היחידה;** Rhino (הערך `DEPRECATED_ES5`) הפסיק להריץ קוד ב-31 בינואר 2026. שיעור 2 מכסה את ה-sunset. |
| `oauthScopes` | מערך של scope URLs | הרשימה המפורשת של ההרשאות שהפרויקט צריך. Apps Script מזהה אותן אוטומטית בהרצה הראשונה כשהשדה ריק; הצהרה מפורשת היא הנוהג הנכון יותר. |
| `dependencies` | object | imports של ספריות והפעלות של advanced services. שיעור 12 מכסה libraries; שיעור 17 מכסה advanced services. |
| `sheets.macros` | מערך | רישומי המאקרו שצצים תחת Tools → Macros. שיעור 6 מכסה את השדה הזה בפירוט. |

### למה הצהרת scopes מפורשת חשובה

Apps Script יכול לזהות את ה-scopes שפרויקט צריך על ידי סריקת הקוד לקריאות שירות (`MailApp.sendEmail` ← scope של mail-send, `UrlFetchApp.fetch` ← scope של external-request, וכו'). הוא ימלא את ה-auth prompt בהתאם בהרצה הראשונה. אז למה בכלל להצהיר?

שתי סיבות. ראשית, מערך `oauthScopes` מפורש מתעד במה הפרויקט נוגע, במקום אחד, בקובץ שנמצא ב-diff של היסטוריית ה-workbook של הצוות. שנית, הזיהוי האוטומטי מרחיב בשקט את סט ה-scopes בכל פעם שמוסיפים קריאת שירות חדשה, מה שאומר שחבר צוות נתקל ב-prompt חדש של "האם אתם מאשרים את ההרשאות האלה?" בזמנים אקראיים בלי להבין למה. הצהרה מפורשת מקבעת את חוזה ה-scope; scopes חדשים נכנסים ל-prompt רק כשמכניסים אותם ל-manifest בכוונה.

| אפשרות | יוצר | מתי משתמשים |
|---|---|---|
| Script | קובץ `.gs` | server JavaScript. רוב השיעורים משתמשים בזה. |

| Apps Script Project | רשומת ספרייה ב-manifest | ייבוא של פונקציות מ-project אחר (שיעור 12). |

## שמירה, הרצה ופריסה

עריכת קובץ נשמרת אוטומטית ל-draft המקומי של העורך, אבל היא לא נכנסת לפרויקט עד שלוחצים **Save project** (Ctrl/Cmd+S, או אייקון הדיסקט). אחרי שמירה:

- **קבצי `.gs`** הופכים מיד לקריאים מתאים כ-custom functions ומהתפריט כ-macros.
- **קבצי HTML** מתעדכנים בפתיחה הבאה של ה-sidebar.
- **ה-manifest** נכנס לתוקף בהרצה הבאה; אם שיניתם `oauthScopes`, ההרצה הבאה תבקש מהמשתמש לאשר את סט ה-scopes החדש.

ה-dropdown של Run בראש העורך מאפשר לבחור כל function בפרויקט ולהריץ אותה פעם אחת לצורכי דיבאג. משתמשים בזה כדי להריץ ידנית function של setup לפני שמחברים אותה ל-trigger, או כדי לבדוק custom function מתוך העורך בלי לעבור דרך תא.

### Save מול Deploy

נקודת בלבול נפוצה: **Save זה לא Deploy.** Save מכניס את העריכות שלכם ל-HEAD revision של הפרויקט; העורך והתאים המקושרים רואים מיד את הקוד החדש. **Deploy** (Deploy → New deployment או Manage deployments) מקפיא snapshot תחת מספר version, וזו הדרך שבה libraries (שיעור 12) ו-web apps (שיעור 13) מקבלים משטח יציב מול הצרכן. עבור script bound טיפוסי שרץ רק מתפריטים ו-triggers באותו workbook, ייתכן שלעולם לא תפרסו: Save מספיק.

## עכשיו לעבודה אמיתית

ל-project המקושר של השיעור הזה יש קובץ `Lesson.gs` עם stub של `projectName()`. שתי משימות:

1. פותחים **Extensions → Apps Script** ועורכים את `Lesson.gs`. מחליפים את `return null;` ב-`return SpreadsheetApp.getActiveSpreadsheet().getName();`. שומרים את הפרויקט.
2. חוזרים ל-spreadsheet, בתא **A1**, מקלידים `=projectName()`. התא אמור להציג את שם ה-workbook הזה.

יקפוץ auth prompt פעם אחת בפעם הראשונה שהתא יחושב: Apps Script צריך הרשאה לקרוא את ה-spreadsheet בשמכם. מאשרים; הרצות הבאות משתמשות באותו אישור.

## נפוץ בשטח

ל-project המקושר של workbook של צוות יש בדרך כלל רשימה שטוחה של קבצים מקובצים לפי prefix. snapshot מציאותי מ-workbook האגרגטור של האדטק:

| קובץ | מטרה |
|---|---|
| `appsscript` | Manifest. מגדיר את ה-timezone של הצוות (`America/New_York`), מצהיר על כל ה-scopes הנחוצים, מפרט את ארבעת המאקרו שצצים תחת Tools → Macros, ומקבע את `SheetsLib` כ-dependency של library. |
| `Code` (נקודת כניסה) | בונה התפריט המותאם, נקרא מ-`onOpen`. שלושה תפריטים: Reports, Buyers, Cleanup. כל פריט מאציל ל-handler בקובץ `triggers_*` או `actions_*`. |
| `lib_dates.gs` | helpers של תאריכים: פענוח של מחרוזות `YYYY-MM-DD` של הצוות, חישוב יום העסקים הקודם, פורמט לתצוגה. |
| `lib_verticals.gs` | נרמול שמות vertical (מוודא סיומת ` PR`), והחיפוש של רשימת ה-buyers הקנונית. |
| `triggers_nightly.gs` | האגרגטור הלילי שמושך שורות raw של Taboola, Outbrain, MediaGo, TikTok וכותב אותן ל-tab של Aggregator. שיעור 8 מכסה איך ה-trigger נרשם. |
| `triggers_onedit.gs` | ה-handler של on-edit שמחתים אוטומטית את כתובת המייל של העורך כשתא Spend משתנה. שיעור 7 מכסה את גרסת ה-simple-trigger. |
| `actions_bulk.gs` | ה-handlers של "Mark dead campaigns" ו-"Archive month" שמחוברים לפריטי תפריט. |
| `ui_sidebar.html` | ה-sidebar של בונה הקמפיינים שמלווה את ה-buyer דרך מתן שם והפעלה של קמפיין חדש. שיעור 9 מכסה את HtmlService. |

חלוקה לפי prefix היא המוסכמה של הצוות. אף כלי לא אוכף את זה; זה פשוט הרגל שהופך project של שלושים קבצים לכזה שאפשר לנווט בו. שימו לב שאין `main.gs`: נקודת הכניסה היא מתקין התפריט ב-`Code.gs`, והקליק הראשון של המשתמש על פריט תפריט הוא מה שמתחיל את העבודה האמיתית.

## מלכודות מקצועיות

- **Bound לעומת standalone.** מחזור החיים של script bound הוא של ה-spreadsheet. אם מוחקים את ה-spreadsheet, ה-script הולך איתו. צריכים את אותה לוגיקה בכמה workbooks? בונים standalone script ומושכים אותו כספרייה (שיעור 12).
- **ה-dashboard ב-script.google.com.** scripts מסוג bound לא מופיעים ברשימת "My projects" שלכם ב-script.google.com. כדי למצוא אותם, פותחים את ה-workbook ונכנסים ל-Extensions → Apps Script. זו נקודת הכניסה היחידה. חברי צוות שמאבדים מעקב אחרי "באיזה workbook היה ה-script הזה" סורקים כל workbook משותף אחד-אחד.
- **שינוי שם של `Code.gs`.** טכנית לא שובר כלום. ל-runtime של Apps Script לא אכפת איך הקובץ נקרא. אבל כל מי שיפתח את הפרויקט יחפש קודם את `Code.gs` מתוך הרגל, אז משאירים את קובץ נקודת הכניסה בשם הזה.
- **עריכת שני tabs של אותו project בו-זמנית.** עורך Apps Script לא מציג אזהרות conflict בזמן אמת. שני tabs פתוחים על אותו project ידרסו זה את זה בשקט בשמירה. אם אתם עוברים בין מחשבים, סוגרים tab אחד לפני שפותחים בשני.
- **גרסאות ב-Apps Script.** כל שמירה יוצרת HEAD revision חדש, אבל רק deployments עם version הם immutable. כדי לחזור ל-"מה שרץ אתמול", הולכים לתפריט הקובץ בעורך (זה מוסתר שתי לחיצות עמוק בעורך החדש: אייקון שמאל-עליון → File → See version history). שמרו את זה כסימנייה; תצטרכו אותו בפעם הראשונה ש"עריכה לא מזיקה" של חבר צוות תשבור את ה-trigger הלילי.
- **scopes שמזוהים אוטומטית ונסחפים בכל עריכה.** אם משאירים את `oauthScopes` ריק, Apps Script מרחיב בשקט את סט ה-scopes בכל פעם שמוסיפים קריאת שירות. חברי צוות פתאום רואים הרשאות חדשות בהרצה הבאה שלהם בלי הקשר. מצהירים על scopes במפורש והחוזה נשאר יציב.
- **מלכודת שינוי השם של `appsscript.json`.** חלק מהלומדים מנסים לשנות את שם ה-manifest ל-`manifest.json` או דומה; Apps Script לא יקלוט אותו. שם הקובץ קבוע. אותו דבר לגבי snapshots של `appsscript.json.bak`: ה-runtime מתעלם מכל דבר חוץ מ-`appsscript.json` המילולי.
