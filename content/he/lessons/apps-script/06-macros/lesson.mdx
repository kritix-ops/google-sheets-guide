# Macros: הקלטה, עריכה, שיתוף

macro ב-Google Sheets היא פשוט function רגילה ב-Apps Script ש**רשומה במניפסט** כך שהיא צצה תחת Tools then Macros עם קיצור מקלדת אופציונלי. אין שום קסם ב-function עצמה; היא משתמשת באותן קריאות `SpreadsheetApp` ו-`Range` משני השיעורים הקודמים. החלק החדש הוא הרישום: זה מה שהופך את ה-function לנגישה מתפריט Tools במקום רק מ-Run dropdown של עורך Apps Script.

מאקרו הוא איך שצוות הופך פעולות ידניות של one-shot לחוזרות: פורמט ל-tab של החודש החדש, ארכוב נתונים של חודש שעבר, סימון אצווה של קמפיינים כמתים. ה-buyer שצריך את הפעולה לא צריך לדעת כלום Apps Script; הוא בוחר את המאקרו מהתפריט וזה רץ. ה-recorder גם מאפשר ל-non-programmer לתפוס workflow שהוא עשה ידנית ולנגן אותו, מה ששימושי אבל לא איך שמאקרו של production נראים אחרי שהצוות התיישב.

## מוקלט מול כתוב ביד

ל-Sheets יש תכונת Record Macro (Extensions then Macros then Record macro). הזרימה היא בדיוק איך שזה נשמע: מתחילים להקליט, עושים רצף של עריכות ב-UI, מפסיקים להקליט, ו-Sheets כותב את ה-function של Apps Script שמשחזר את העריכות האלה. זה נראה אטרקטיבי (אין קוד לכתוב) ואז קוראים מה זה הפיק:

```js
function MyMacro() {
  var spreadsheet = SpreadsheetApp.getActive();
  spreadsheet.getCurrentCell().setNumberFormat('$#,##0.00');
  spreadsheet.getActiveRangeList().setFontWeight('bold');
};
```

שתי בעיות:

1. **זה משתמש ב-`getCurrentCell()` וב-`getActiveRangeList()`.** אלה קוראים את התא שעליו המשתמש במקרה נמצא כשהמאקרו רץ. המאקרו שעבד מצוין כשהקלטתם אותו על F2 עכשיו מפרמט את התא הלא נכון כשחבר צוות מריץ אותו מ-D17.
2. **אין error handling, אין logging, אין constants.** אם משהו נשבר ב-runtime (ה-sheet שונה שם, ה-range נמחק), המאקרו נכשל בשקט או עם הודעה לא מועילה.

מאקרו מוקלט הוא נקודת התחלה, לא יעד. המאקרו האמיתי של הצוות נכתב ביד. הם נראים כמו הדוגמאות של שיעור 4 / שיעור 5: `getSheetByName` מפורש, ranges A1 מפורשים, מבנה מכוון.

## רישום המאקרו

function מופיעה תחת Tools then Macros רק ברגע שהיא מופיעה ברשימת `sheets.macros` של ה-manifest `appsscript.json` של הפרויקט:

```json
{
  "timeZone": "America/New_York",
  "sheets": {
    "macros": [
      {
        "menuName": "Format new month",
        "functionName": "formatNewMonth",
        "defaultShortcut": "Ctrl+Alt+Shift+1"
      }
    ]
  }
}
```

שלושת השדות:

| שדה | מה זה עושה |
|---|---|
| `menuName` | התווית שהמשתמש רואה תחת Tools then Macros. משאירים אותה ספציפית. "Format" לבדה דו-משמעית ליד מאקרו אחרים. |
| `functionName` | ה-JS function שהמאקרו הזה מריץ. חייב להתאים להצהרת ה-function בדיוק (case-sensitive). |
| `defaultShortcut` | אופציונלי. שילוב המקלדת שמפעיל את המאקרו. Sheets מקצה `Ctrl+Alt+Shift+1` עד `Ctrl+Alt+Shift+9` למאקרו של משתמש. |

אפשר לערוך את ה-manifest ידנית, אבל המסלול הידידותי יותר הוא **Extensions then Macros then Manage macros then Add new macro**. הוא פותח dialog קטן שבו בוחרים את ה-function והתווית, ו-Sheets כותב לכם את רשומת ה-manifest.

## במה מאקרו שונים מפריטי תפריט

`addReportsMenu` של שיעור 5 בנה תפריט מותאם בסרגל הכלים של ה-spreadsheet. מאקרו דומה אבל גר במשטח אחר:

| | פריט תפריט (שיעור 5) | מאקרו |
|---|---|---|
| איפה הוא גר | תפריט מותאם של סרגל הכלים (Reports, Buyer tools, וכו') | תפריט המשנה Tools then Macros |
| איך הוא רשום | `createMenu().addItem(...)` נקרא מ-`onOpen` | רשומה ב-`sheets.macros` של `appsscript.json` |
| קיצור מקלדת | אין כברירת מחדל | אופציונלי `Ctrl+Alt+Shift+1..9` |
| נראה למשתמשים אחרים | כן, בכל פתיחה | כן, בכל פתיחה |
| מתי להשתמש | סטים מקובצים של פעולות (תפריט Reports עם 5 פריטים) | פעולה יחידה בתדירות גבוהה שרוצים לה קיצור |

בפועל הצוות משתמש בשניהם. Reports, Buyers, Cleanup מקבלים תפריטים משלהם; פעולות one-off כמו "Format new month" או "Archive month" הופכות למאקרו כדי שיקבלו קיצור Ctrl+Alt+Shift+1.

## שיתוף מאקרו

המאקרו הוא function ב-bound Apps Script project. כל מי שיש לו גישת עריכה ל-spreadsheet יש לו את המאקרו זמין; הוא לא צריך להתקין כלום, והוא לא צריך גישה לעורך Apps Script אלא אם הוא רוצה לשנות את ה-function. בפעם הראשונה שמישהו מריץ אותה הוא מקבל OAuth consent prompt; אחרי זה זה פשוט עובד.

ה-catch בשיתוף: **קיצור המקלדת הוא פר-משתמש, פר-spreadsheet.** ה-buyer שפתח את ה-spreadsheet בפעם הראשונה צריך ללכת ל-Tools then Macros then Manage macros ולהקצות קיצור משלו. ברירת המחדל ב-manifest היא מה שכל משתמש חדש מתחיל ממנה, אבל הוא יכול לעקוף אותה מקומית.

הקובץ ההתחלתי `Lesson.gs` מצהיר על `function formatSpendColumn()` עם TODO. שלושה צעדים:

1. מקבלים את ה-sheet של Campaigns דרך `SpreadsheetApp.getActiveSpreadsheet().getSheetByName("Campaigns")`.

## נפוץ בשטח

המאקרו "Format new month" של הצוות הוא המקרה הקנוני. בתחילת כל חודש מוסיפים tab חדש עם אותה צורת עמודה כמו של החודש הקודם. המאקרו מיישם:

| עמודה | פורמט |
|---|---|
| A (Date) | `yyyy-mm-dd` |
| F (Spend), G (Revenue) | `$#,##0.00` |
| עמודת ROI (מחושבת) | `0.00` (מספר עם שני מקומות עשרוניים) |
| כל תאי הכותרת | מודגש, רקע אפור בהיר |

מאקרו אחד, Ctrl+Alt+Shift+1 אחד, אפס לחיצות מעבר לזה. בלי המאקרו ה-buyer היה מבלה עשר דקות בפורמט של tab חדש כל חודש. עם המאקרו זה שתי שניות.

מאקרו אחרים ב-workbooks של הצוות:

- **"Archive month"** מעתיק את ה-tab של Aggregator הנוכחי ל-sheet גיבוי מתויג בתאריך ומנקה את המקור.
- **"Mark dead campaigns"** מציב את ה-kill switch על כל שורה שבה ROI ירד מתחת ל-0.5 שלושה ימים רצופים.
- **"Recompute ROI column"** מריץ recalc מכוון של עמודה H (ROI) כשהעמודה נערכה ביד וצריך recalc טרי.
- **"Snap aggregator to staging"** מעתיק את ה-tab של Aggregator ל-tab Staging כדי שה-buyer יסקור לפני הכתיבה ל-production. רצף מאקרו של שני צעדים (snap, review, commit) הוא רשת הביטחון של הצוות לפעולות batch הרסניות.

## מלכודות מקצועיות

- **מאקרו מוקלטים שמשתמשים ב-`getCurrentCell()`.** הם מפרמטים את התא שהמשתמש במקרה נמצא עליו. מחליפים את `spreadsheet.getCurrentCell()` ב-`sheet.getRange("F2:F61")` (או כל מה שהמאקרו באמת אמורה לכוון אליו) ברגע שהמאקרו מוקלטת.
- **מאקרו שמקודדים A1 references שנשברים כשמוסיפים עמודות.** מאקרו שמכוונת ל-`F2:F61` תמשיך לכוון ל-F2:F61 גם אחרי שהצוות מוסיף עמודת "Country" בין E ל-F, ועכשיו המאקרו מפרמטת את העמודה הלא נכונה. או שמשתמשים בשם העמודה במקום (מחפשים אותה לפי טקסט כותרת) או משתמשים ב-named ranges שזזות עם הוספות.
- **מאקרו שלא ניתנות לביטול נקי.** כתיבות Apps Script אינן ב-stack של ה-undo. מאקרו שדורסת את ה-range הלא נכון משאירה את המשתמש בלי מוצא חוץ מ-File then Version history. שמים gate על מאקרו הרסניות עם `ui.alert(..., ui.ButtonSet.YES_NO)`.
- **מאקרו שלוקחות יותר מ-30 שניות.** simple triggers (כולל מאקרו שמופעלות מתפריט Tools) יש להן timeout רך של 30 שניות בחלק מההקשרים ו-timeout קשה של 6 דקות באחרים. מאקרו שמתבצעת לולאה תא-תא על 50,000 שורות תפגע במגבלה. batch reads עם `getValues()` ו-batch writes עם `setValues()` (ה-pattern של שיעור 4) שומרים את רוב המאקרו בקלות מתחת לשנייה.
- **`menuName` ו-`functionName` שמתפצלים זה מזה.** ה-`functionName` ברשומת ה-manifest ושם ה-JS function בפועל מותאמים לפי מחרוזת. שינוי שם של ה-JS function בלי לעדכן את ה-manifest משאיר את Tools then Macros מציג את השם הישן אבל מצביע ללא כלום; לחיצה ושום דבר לא קורה.
- **קיצור מקלדת שמתנגש עם קיצור דפדפן.** `Ctrl+Alt+Shift+1` ברובו בטוח אבל Sheets מציגה לפעמים קיצורים פנימיים חדשים. אם קיצור מאקרו מפסיק לעבוד, בודקים Tools then Macros then Manage macros כדי לאשר שהוא עדיין ממופה, ובוחרים שילוב אחר אם צריך.
- **מאקרו שנוגעות ב-workbooks אחרים.** מאקרו שנקראת מ-Tools רצה עם ה-scope של auth של ה-workbook, שכברירת מחדל הוא `spreadsheets.currentonly`. ניסיון לעשות `SpreadsheetApp.openById(...)` של קובץ אחר ממאקרו ייכשל עד שמרחיבים את ה-scope ב-manifest. או מרחיבים את ה-scope בכוונה או מעבירים את העבודה בין workbooks ל-trigger מבוסס-זמן שיש לו scope משלו (רחב יותר).
- **מאקרו שתלויות ב-active sheet.** מאקרו שקוראת ל-`getActiveSheet().getRange(...)` תשתמש ב-tab שהמשתמש במקרה מסתכל עליו. תמיד משתמשים ב-`getSheetByName("Campaigns")` גם אם המשתמש "תמיד" מריץ את המאקרו מה-tab של Campaigns; ביום שהוא ירוץ אותה מ-"Drafts" המאקרו תפרמט בשקט את ה-tab הלא נכון.
