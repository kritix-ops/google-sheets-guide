# Pivot tables לעומק: filters, multi-value, calculated fields

לסון 2.2 כיסה את ארבעת הסלוטים ב-Pivot editor: Rows, Columns, Values, Filters. זה מספיק ל-dashboards הפשוטים ביותר. ברגע שצריך לצמצם pivot למדינה אחת, לערום שלושה מספרים בכל תא, או לקבץ תאריכים לרבעונים, חורגים מהבסיס. השיעור הזה הוא השאר ממה ש-media buyer עובד משתמש בו ב-spreadsheet אמיתי כל יום.

הרף שכדאי לכוון אליו: בסוף השיעור, אתם אמורים להיות מסוגלים להסתכל על כל pivot של dashboard צוותי ולעשות לו reverse-engineering. טווח מקור, Rows, Columns, Values (עם פונקציות הסיכום שלהם), Filters, וכל calculated fields. ברגע שיודעים לקרוא pivots, לבנות אותם זה בעיקר זיכרון שרירי.

## Filters: לפי ערכים לעומת לפי תנאי

הסלוט Filters מצמצם את המקור לפני שה-pivot עושה אגרגציה. שני סוגים:

| סוג | מה הוא עושה | מתי לבחור בו |
|---|---|---|
| **Filter by values** | רשימת הרשאה מפורשת של פריטים נראים | אתם יודעים את הסט המדויק: `Country in {DE, UK}`, `Platform in {Google, Facebook}` |
| **Filter by condition** | תנאי שכל שורת מקור חייבת לקיים | `Spend > 200`, `Vertical contains "PR"`, `Date is after 2026-04-15` |

By-values מופיע ב-Sheets API כרשימת `visibleValues`. By-condition מופיע כ-`BooleanCondition` עם סוג (`NUMBER_GREATER`, `TEXT_CONTAINS`, `DATE_AFTER`, `CUSTOM_FORMULA`, ...) ו-`conditionValues` תואמים. שניהם מתחברים לעמודת מקור אחת בכל פעם. ה-grader של השיעור הזה קורא את צורת ה-by-values.

הבחירה המקצועית ביניהם: **by-values** לרשימה יציבה (מדינות שבאמת רצים בהן, ארבעת ה-buyers של הצוות), **by-condition** לכל דבר דינמי (טווח תאריכים של החודש הזה, ספי ROI, חיפושי טקסט אד-הוק). לא לבזבז by-values filter על רשימה שגדלה כל שבוע.

## Slicers: filters עם משטח UI

slicer הוא pivot filter עטוף בקונטרול על הגיליון. אותה השפעה על ה-pivot, השפעה שונה לגמרי על הצוות. עורכים עם גישת filter משנים את הסלוט Filters של ה-pivot בתוך ה-editor; viewers לא יכולים. slicer מציג dropdown ישירות על הגיליון, אז viewer שיכול רק לקרוא את ה-workbook עדיין יכול ללחוץ "Country: DE" ולראות את ה-pivot מחושב מחדש.

מכניסים slicer עם `Data → Slicer`, מצביעים על טווח המקור של ה-pivot, ובוחרים עמודה. הבחירה של ה-slicer היא state משלה, נפרד מהסלוט Filters של ה-pivot. כששניהם מוגדרים, הם נחתכים.

מתי להוסיף slicer: כל dashboard ש-stakeholder יסתכל עליו, שבו אתם רוצים שהוא יחליף את המדינה, ה-buyer, או הפלטפורמה בלי ללמוד את ה-editor. לא להוסיף slicer ל-pivot שרק אתם נוגעים בו. זה רק עומס על הגיליון.

## Pivots מרובי-ערכים: עירום SUM, AVERAGE, COUNTA

הסלוט Values מקבל יותר מערך אחד. עורמים `SUM Spend`, `SUM Revenue`, `COUNTA Date` (ספירת קמפיינים), `AVERAGE ROI` באותו pivot, וכל תא `Row × Column` מציג את כולם זה לצד זה, או מעורמים, תלוי ב-`valueLayout`.

שני layouts:

- **HORIZONTAL** (ברירת מחדל). כל value מקבל עמודה משלו תחת כל קבוצת Column. עם קבוצת Column אחת "Platform" (7 פלטפורמות) ושלושה values, מקבלים 21 עמודות תוצאה. נסבל. עם שתי קבוצות Columns זה מתפוצץ.
- **VERTICAL**. ה-values נערמים כשורות תחת כל קבוצת Row. עם Buyer ב-Rows ושלושה values, כל buyer מקבל שלוש שורות, והעמודות נשארות צרות.

ברירת המחדל של הצוות ל-**3 ערכים או יותר היא VERTICAL**. ה-pivot נקרא מלמעלה למטה כמו דוח רגיל, וספירת העמודות מפסיקה להתפוצץ כשמוסיפים ערך רביעי.

## Calculated fields, לעומק

לסון 2.2 הציג את ה-calculated fields כפתח המילוט כשאף פונקציית הסיכום הסטנדרטית לא מכסה את מה שצריך. ה-syntax המלא: סלוט Values שה-summarize שלו הוא `CUSTOM`, עם מחרוזת `formula` שמפנה לכותרות מקור במירכאות בודדות:

```
= ('Revenue' - 'Spend') / 'Spend'
```

שתי צורות מייצרות את אותו ROI:

```
= ('Revenue' - 'Spend') / 'Spend'
= 'Revenue' / 'Spend' - 1
```

ה-grader של השיעור הזה מקבל את שתיהן, על ידי בדיקה שהנוסחה מכילה גם את `'Revenue'` וגם את `'Spend'`.

המלכודת: שמות עמודות **רגישים לאותיות גדולות וקטנות** וחייבים להתאים בדיוק לטקסט כותרת המקור. `'revenue'` (אותיות קטנות) ייכשל בשקט. `'Total Spend'` הוא שם אחר מ-`'Total spend'`. אם calculated field מחזיר `#REF!` או ריק, הפניית העמודה היא הדבר הראשון לבדוק.

המלכודת השנייה: הנוסחה מחושבת אחרי ה-SUM המשתמע כברירת מחדל, אז `'Revenue' / 'Spend'` לכל תא הוא `SUM(Revenue) / SUM(Spend)` עבור השורות באותו תא, שזה היחס של ה-**portfolio**. כמעט תמיד זה מה שרוצים ל-ROI, ROAS, או CPC משוקלל. אם דווקא רוצים את הממוצע של יחסי-שורה, מחשבים את היחס בעמודת מקור ומצרפים את זה.

## נפוץ בשטח

ב-spreadsheets האמיתיים של הצוות:

- **ה-pivot של ה-dashboard המצומצם לפי מדינה**: slicer על Country בראש הגיליון, pivot מתחת עם SUM Spend, SUM Revenue, calculated ROI על Rows = Buyer. ה-viewer הופך DE → UK → US וה-pivot מחושב מחדש. ל-pivot עצמו אין סלוט Filters מוגדר; ה-slicer הוא ה-filter היחיד, אז עורכים יכולים לשנות אותו בלי לגעת ב-config של ה-pivot.
- **ה-buyer scoreboard**: Rows = Buyer, Values = SUM Spend, SUM Revenue, COUNTA Date, calculated ROI, calculated `'Revenue' - 'Spend'` לרווח portfolio. חמישה ערכים, VERTICAL layout, מסך אחד.
- **התצוגה הגיאוגרפית הרבעונית**: Rows = Country, Columns = Date מקובץ ב-year-quarter, Values = SUM Spend. הקצאה גיאוגרפית רבעונית לפיננסים, ב-pivot אחד, בלי עמודות עזר.

## מלכודות מקצועיות

- **Filters שזזים כשעמודות מקור מוכנסות או מוסרות.** ה-`sourceColumn` של ה-filter הוא offset לתוך טווח המקור, לא שם של header. הוסיפו עמודה באמצע המקור וכל filter אחרי נקודת ההכנסה זז בשקט לעמודה הלא נכונה. אותה מלכודת ל-calculated fields שמפנים לכותרות עמודה אם גם משנים את שם הכותרת.
- **Calculated fields עם header מקור ששמו שונה.** משנים את `Revenue` ל-`Revenue (USD)` בשורה 1, וכל calculated field שמפנה ל-`'Revenue'` מחזיר `#REF!` עד שעורכים גם את הנוסחה. אין rename-propagation.
- **VERTICAL layout בלי "Show totals".** ה-pivot נקרא מלמעלה למטה אבל אם ה-totals כבויים, לעין אין שורת עוגן לכל buyer. הופכים את Rows → Show totals למופעל ל-pivots מקובצים; שורת ה-totals היא מה שעושה את ה-layout קריא.
- **Slicers שלא נראים ל-viewers.** slicer הוא אובייקט צף על הגיליון. אם ה-pivot נכנס ל-frame משובץ קטן, ה-slicer נגלל מחוץ למסך ו-viewers רואים pivot סטטי שהם לא יכולים לשנות. ממקמים את ה-slicer מעל או לצד ה-pivot, אף פעם לא מתחתיו.
- **סינון by condition עם ערך שלא רלוונטי.** filter "Date is after 2026-04-15" בסדר באפריל. שישה חודשים אחר כך הוא עדיין אומר 2026-04-15 וה-pivot בשקט לא מוציא כלום. לתאריכים דינמיים, השתמשו ב-filter CUSTOM_FORMULA שמפנה ל-`TODAY()`, או העבירו את טווח התאריך ל-slicer שהצוות באמת מתחזק.
