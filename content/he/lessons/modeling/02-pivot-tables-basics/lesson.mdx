# Pivot tables: rows, columns, values, calculated fields

pivot table לוקח לוג ארוך וצר והופך אותו לסיכום קצר ורחב. אותם נתונים, צורה אחרת. ברגע שיודעים לקרוא pivot, חצי מעבודת ה-dashboard באדטק היא "מה ה-pivot הנכון לשאלה הזו". השיעור הזה מלמד את ארבעת הסלוטים ב-Pivot editor, Rows, Columns, Values, Filters, ואת פתח המילוט של calculated fields כשארבעת הסלוטים לא מספיקים.

## המודל המנטלי

ל-pivot יש טווח מקור אחד וארבעה סלוטים של תצורה. המקור הוא תמיד מלבן של שורות גולמיות עם שורת כותרת אחת בראש (תבנית "המלבן הגולמי" של שיעור 1 היא מה שמזין pivots בצורה נקייה).

| סלוט | מה הוא עושה | דוגמה |
|---|---|---|
| **Rows** | מקבץ שורות, שורת תוצאה אחת לכל ערך מובחן | שם media buyer |
| **Columns** | מקבץ עמודות, עמודת תוצאה אחת לכל ערך מובחן | פלטפורמה |
| **Values** | מבצע אגרגציה בתוך כל תא Row × Column | SUM של Revenue |
| **Filters** | פוסל שורות מקור לפני שהאגרגציה רצה | Country = "DE" |

הפלט של ה-pivot הוא רשת Rows × Columns עם ה-Values מסוכמים בתוך כל תא. עם Buyer ב-Rows, Platform ב-Columns, ו-SUM(Revenue) כ-value, מקבלים מטריצת revenue של media buyer מול פלטפורמה. זאת הצורה הכי שכיחה ב-dashboards של אדטק.

## עיגון של pivot

`Insert → Pivot table` פותח את הדיאלוג. בוחרים "Existing sheet" ובוחרים תא ריק (אנחנו משתמשים ב-K1 בשיעור הזה) כדי שה-pivot יישב ליד הלוג הגולמי בלי לדרוס אותו. התא שבוחרים הופך ל-**עוגן**, הפינה השמאלית-עליונה של ה-pivot, וה-pivot גדל למטה ולימין משם.

עוגן ה-pivot מיוחד: התא עצמו מחזיק את הגדרת ה-pivot, לא ערך. קריאה של K1 מ-script מחזירה את ה-config של ה-pivot, לא את המספר המוצג. שאר התאים שה-pivot ממלא (K2, K3, L1, L2…) מחזיקים את ה-`effectiveValue`-ים המחושבים שאפשר לקרוא כמו כל תא רגיל.

## פונקציות summarize

הסלוט Values לא מקבל רק עמודה, הוא מקבל עמודה **בנוסף** לפונקציה. הפונקציה קובעת מה כל תא מציג. האפשרויות הראשיות:

| פונקציה | מה היא עושה | מתי מושיטים יד |
|---|---|---|
| `SUM` | מחבר את הערכים | סך spend, סך revenue, סך clicks |
| `COUNTA` | סופר תאים לא ריקים | מספר קמפיינים לכל media buyer |
| `COUNTUNIQUE` | סופר ערכים מובחנים | מספר verticals מובחנים לכל פלטפורמה |
| `AVERAGE` | ממוצע | CPC ממוצע על פני הריצות של media buyer |
| `MIN` / `MAX` | הערך הקטן/גדול ביותר | spend של היום הגרוע, revenue של היום הטוב |
| `MEDIAN` | הערך האמצעי | revenue "טיפוסי" עמיד (מתעלם מ-outliers, בניגוד לממוצע) |

המהלך המקצועי: **`MEDIAN` במקום `AVERAGE` לכל מטריקה עם זנב ארוך של outliers**. יום אחד של בלוקבסטר מושך את הממוצע למעלה, ה-median לא זז. התפלגויות ROI במיוחד מספיק עקומות בשביל שהממוצע יטעה.

## Calculated fields: פתח המילוט

כשסלוט Values צריך יחס של שתי עמודות מקור (ROI, ROAS, CPC, מרג'ין), ארבעת הסלוטים הסטנדרטיים לא מכסים את זה. calculated fields כן. ב-Pivot editor, לוחצים על `Values → Add → Calculated field`, וכותבים נוסחה כמו:

```
= 'Revenue' / 'Spend'
```

שמות בגרשיים יחידים מפנים לכותרות עמודות מקור (case-sensitive). הנוסחה מוערכת **בתוך** האגרגציה של ה-pivot, אז calculated field עבור `'Revenue' / 'Spend'` מחלק את ה-revenue ה**מסוכם** ב-spend ה**מסוכם** לכל תא, וזה מה שרוצים עבור ROI של פורטפוליו לכל צירוף buyer-platform, לא הממוצע של ROI-ים פר-שורה (שהיה מוטה לכיוון שורות עם spend קטן).

המלכודת: calculated fields משתמשים ב-SUM כברירת מחדל. אם צריך אגרגציה אחרת בתוך ה-calculated field, כותבים אותה במפורש: `=SUMIF('Country','DE','Revenue') / SUMIF('Country','DE','Spend')`. רוב הזמן, ברירת המחדל של SUM-של-הנוסחה היא מה שרוצים, ואפשר להשאיר את הנוסחה פשוטה.

## נפוץ בשטח

ב-spreadsheets האמיתיים של הצוות:

- **ה-pivot הפותח של כל סקירה שבועית**: Rows = Buyer, Columns = Platform, Values = SUM Revenue. מבט אחד אומר מי רץ איפה ובאיזה סקייל.
- **ה-pivot של תמהיל verticals**: Rows = Vertical, Values = SUM Spend, COUNTA Campaigns, AVERAGE ROI. שלושה values נערמים ב-pivot אחד. אומר "לאן הכסף הולך, וזה עובד".
- **ה-pivot לפי מדינה לתקצוב**: Rows = Country, Columns = Quarter (calculated field שמקבץ את עמודת ה-Date), Values = SUM Spend. הקצאת geo רבעונית בצורה אחת.

## מלכודות מקצועיות

- **מקור pivot שמצביע על עמודה מלאה** (`Campaigns!A:G`). ה-pivot מחשב מחדש על פני מיליון שורות ריקות בכל עריכה. חוסמים את המקור: `A1:G61`, `A1:G500`, מה שמתאים לנתונים בפועל.
- **עריכה של הלוג הגולמי תחת pivot חי** מסדרת מחדש את הקיבוצים של ה-pivot. שמות media buyer חדשים מופיעים כשורות חדשות, פלטפורמות חדשות מופיעות כעמודות חדשות. זה בדרך כלל טוב, אבל אם ה-pivot הוא הבסיס לדוח יציב במורד הזרם, מקפיאים את טווח המקור או מעתיקים את פלט ה-pivot לטווח סטטי.
- **calculated fields שמפנים לכותרת עמודה עם רווח** חייבים להשתמש באיות וב-case בדיוק. `'Total Spend'` שונה מ-`'Total spend'`.
- **`AVERAGE` של יחס הוא לא היחס של ממוצעים**. calculated `'Revenue'/'Spend'` מחזיר SUM(Revenue) / SUM(Spend) לכל תא, וזה היחס של הפורטפוליו. אם רוצים את הממוצע של יחסי פר-שורה, מחשבים את היחס בעמודת מקור קודם, ואז SUM או AVERAGE אותו.
- **Pivots לא שורדים copy-paste בצורה נקייה**. העתקה של טווח שמכיל תאי פלט של pivot מדביקה ערכים סטטיים, ה-pivot לא נעגן מחדש ביעד. כדי לשכפל pivot, יוצרים אותו מחדש מהמקור.
