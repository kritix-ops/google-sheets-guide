# FILTER, SORT, UNIQUE

QUERY חזק, אבל התחביר שלו בסגנון SQL כבד מדי לפעולות פשוטות. `FILTER`, `SORT`, ו-`UNIQUE` הם קיצורי דרך ישירים וברורים לצרכים היומיומיים של "תן לי רק את השורות האלו", "מיין את זה", "הוצא כפילויות מהעמודה הזו". שלושתם מודעים למערך בעצמם, אין צורך בעטיפת `ARRAYFORMULA`.

## FILTER: שמירה על שורות שעומדות בתנאי

`FILTER(range, condition1, [condition2, ...])` מחזיר את השורות של `range` שבהן כל תנאי הוא `TRUE`. התנאים הם מערכים באותו אורך כמו הטווח.

<FunctionRef name="FILTER" />

```
=FILTER(A2:F13, B2:B13 = "Yoav Cohen")
```

זה מחזיר כל עמודה לכל שורה שבה ה-buyer הוא Yoav. משלבים מספר תנאים עם פסיק (סגנון AND):

```
=FILTER(A2:F13, B2:B13 = "Yoav Cohen", F2:F13 > 400)
```

ללוגיקת OR, משתמשים ב-`+` בין מערכי boolean: `FILTER(A2:F13, (B2:B13 = "Yoav") + (B2:B13 = "Sarah"))`.

  caption="יומן הקמפיינים."
/>

<TryIt
  data={CAMPAIGNS}
  inputCell="H1"
  expectedFormula='=FILTER(A2:F13,B2:B13="Yoav Cohen")'
  task={<>סננו את יומן הקמפיינים כדי להציג רק את הקמפיינים של Yoav Cohen. השתמשו ב-<code>FILTER</code>.</>}
  hint={<>שני ארגומנטים: הטווח להחזיר, ותנאי boolean באותו אורך כמו מספר השורות בטווח.</>}

## SORT: מיון לפי עמודה אחת או יותר

`SORT(range, sort_column, ascending, [sort_column2, ascending2, ...])` מחזיר את הטווח ממוין. ה-sort_column הוא **מספר עמודה בתוך הטווח**, ספירה שמתחילה ב-1.

<FunctionRef name="SORT" />

```
=SORT(A2:F13, 6, FALSE)
```

ממיין לפי עמודה 6 (Revenue), בסדר יורד. למיון לפי מספר עמודות, מוסיפים עוד זוגות.

<TryIt
  data={CAMPAIGNS}
  inputCell="H1"
  expectedFormula="=SORT(A2:F13,6,FALSE)"
  task={<>מיינו את כל יומן הקמפיינים לפי revenue (עמודה 6 בתוך הטווח) בסדר יורד.</>}
  hint={<>שלושה ארגומנטים: טווח, מספר עמודה, ו-boolean של עולה. עמודה 6 היא Revenue (F). מעבירים FALSE לסדר יורד.</>}
  answer={<>SORT שומר על כל העמודות וממיין מחדש את השורות. עמודה 6 היא העמודה השישית של הטווח A2:F13, כלומר עמודה F, Revenue. הארגומנט ה-boolean: TRUE לסדר עולה, FALSE לסדר יורד. SORT מקבל גם קריטריון מיון שני או שלישי לשבירת תיקו. SORT מהיר על טווחים קטנים. ל-ORDER BY של QUERY עדיף לפנות לכל דבר מתוחכם יותר כמו מיון לפי שדה מחושב.</>}
/>

## UNIQUE: הסרת כפילויות מעמודה או משורות

`UNIQUE(range)` מחזיר את הערכים השונים. על עמודה אחת, מקבלים את הערכים הייחודיים. על מספר עמודות, מקבלים את צירופי השורות הייחודיים.

<FunctionRef name="UNIQUE" />

```
=UNIQUE(C2:C13)
```

מחזיר את שמות ה-verticals הייחודיים. בשילוב עם COUNTIF או SORT לרשימות ייחודיות מדורגות.

  answer={<>UNIQUE מחזיר שורה אחת לכל ערך שונה, בסדר ההופעה הראשונה. חלק מה-verticals מופיעים פעמיים (Used Cars PR, Mortgage Refinance PR מורצים על ידי media buyers שונים). ## איך בוחרים

| צורך | מה לבחור |
|---|---|
| סינון שורות לפי תנאי, בלי הקרנה | `FILTER` |
| סינון שורות וגם הקרנה של עמודות ספציפיות | `QUERY` |
| מיון לפי עמודה אחת או שתיים | `SORT` |
| מיון עם ביטויי SQL (מיון מחושב) | `QUERY ... ORDER BY` |
| הסרת כפילויות מעמודה או מצירופי שורות | `UNIQUE` |
| ערכים שונים יחד עם ספירות | `QUERY ... GROUP BY ... COUNT(...)` |

`FILTER`, `SORT`, `UNIQUE` מנצחים בתמציתיות ובבהירות בזמן קריאה. QUERY מנצח כשצריך הקרנה, אגרגציה, לוגיקה מרובת תנאים שנעשית מכוערת ב-FILTER, או כשרוצים ביטוי אחד במקום קריאות מקוננות.

## נפוץ בשטח

- **תצוגות מסוננות חיות לפי media buyer.** תא dropdown שמחזיק שם של media buyer, FILTER מושך רק את הקמפיינים של אותו buyer. משנים את ה-dropdown, התצוגה מתעדכנת.
- **רשימות Top-N.** SORT עם חיתוך מערך: `=ARRAY_CONSTRAIN(SORT(A2:F13, 6, FALSE), 5, 6)` ל-top 5.
- **Dropdowns של verticals או buyers בלי כפילויות.** UNIQUE על עמודת המקור מזין dropdown של Data Validation במקום אחר.
- **Spend לפי vertical כשנוספים verticals חדשים.** UNIQUE על עמודת ה-vertical, SUMIFS על כל ערך ייחודי, ויש טבלת revenue פר vertical שמתעדכנת אוטומטית.

## מלכודות מקצועיות

- **FILTER מחזיר `#N/A` כשאין שורות שמתאימות.** עוטפים ב-IFERROR/IFNA עם נפילה רכה לבטיחות מול תוצאה ריקה.
- **אינדקס העמודה של SORT הוא בתוך הטווח.** מעבירים `SORT(B2:F13, 5, FALSE)` והמשמעות של "5" היא העמודה החמישית של B:F, כלומר עמודה F. קל לטעות בספירה.
- **UNIQUE שומר על whitespace ועל case.** "Yoav " (רווח בסוף) ו-"Yoav" הם שתי רשומות שונות. TRIM/LOWER לפני.
- **שלושתן נועלות תאים סביבן.** פלט שמתפרס נכשל ב-`#REF!` אם משהו מפריע.
- **FILTER עם טווחים רבי עמודות ותנאים מורכבים יכול להיות איטי.** מעבר לכמה אלפי שורות, QUERY נוטה להיות מהיר יותר.
