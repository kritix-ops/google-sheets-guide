# הפונקציה QUERY: יסודות SQL בתוך Sheets

`QUERY` מאפשרת לסנן, למיין, ולהשליך נתונים תוך שימוש במחרוזת בסגנון SQL. זאת הפונקציה היחידה החזקה ביותר ב-Sheets, וסוס העבודה של כל dashboard באדטק. QUERY אחת יכולה להחליף תריסר SUMIFS או שרשרת של FILTER+SORT, ובניגוד אליהן, התוצאה מתעדכנת אוטומטית כשהמקור משתנה.

הניב הוא **Google Visualization API Query Language**, דומה ל-SQL סטנדרטי אבל עם קפריזות: אותיות עמודה כמזהים, אין JOIN, UPDATE/DELETE מוגבלים (כלל לא בהקשר של Sheets), וכמה הבדלים בפונקציות.

## תחביר בסיסי

```
=QUERY(range, "SELECT clause WHERE clause ORDER BY clause LIMIT n", [headers])
```

הארגומנט השלישי אומר ל-QUERY כמה שורות כותרת יש ב-`range`. מעבירים `1` אם הטווח כולל שורת כותרת, `0` אם לא. אם משמיטים, Sheets מנחש (בדרך כלל נכון, לפעמים לא).

מחרוזת ה-query היא מחרוזת מצוטטת אחת. הפניות לעמודות משתמשות באותיות: `A`, `B`, `C`, ... אבל הן מתייחסות לעמודות בתוך הטווח שהעברתם, **לא** לגיליון. אם מעבירים `B2:F13`, אז עמודה `A` של ה-query היא עמודה `B` של הגיליון.

## SELECT

## WHERE: סינון שורות

הסעיף WHERE מסנן אילו שורות עוברות.

```
=QUERY(A1:F13, "SELECT * WHERE B = 'Yoav Cohen'", 1)
```

ליטרלים של מחרוזות במחרוזת ה-query משתמשים ב**גרשיים בודדים** (כי ה-query כולה עטופה בגרשיים כפולים). השוואות מספריות לא צריכות גרשיים: `WHERE F > 400`. השוואות תאריכים משתמשות ב-`date 'YYYY-MM-DD'`: `WHERE A >= date '2026-05-05'`.

משלבים תנאים עם `AND` ו-`OR`: `WHERE B = 'Yoav Cohen' AND F > 400`.

## ORDER BY ו-LIMIT

`ORDER BY column` ממיין בסדר עולה; `ORDER BY column DESC` בסדר יורד. `LIMIT n` שומר רק את n השורות הראשונות. `OFFSET n` מדלג על n השורות הראשונות.

תבנית נפוצה באדטק: 5 הקמפיינים המובילים לפי revenue.

```
=QUERY(A1:F13, "SELECT B, C, F ORDER BY F DESC LIMIT 5", 1)
```

## נפוץ בשטח

QUERY מופיעה בכל מקום ב-dashboards של הצוות. התבניות:

- **דוחות קמפיינים מסוננים.** "תראו לי את כל הקמפיינים של Yoav מהשבוע שעבר עם ROI < 1.0." WHERE עם שלושה תנאים, ORDER BY אחד, לעיתים קרובות LIMIT.
- **לוחות מובילים Top-N.** "10 ה-verticals המובילים לפי סך spend." (משתמשים ב-GROUP BY, מכוסה בשיעור 13.)
- **סיכומים מוגבלי תאריכים.** "כל הקמפיינים שבהם launch_date BETWEEN start AND end." תחביר השוואת התאריכים עדין, ראו מלכודות.
- **Dashboards משותפי תצוגה.** בונים טאב מקור-אמת אחד עם נתונים גולמיים; משתמשים ב-QUERY בכל טאב תלוי. עריכת המקור מעדכנת כל dashboard.

## מלכודות מקצועיות

- **אותיות עמודה מתייחסות לטווח, לא לגיליון.** אם מעבירים `C2:G13`, עמודה `A` של ה-query היא עמודה `C` של הגיליון. קל לשכוח כשמעתיקים queries בין גיליונות.
- **ליטרלים של מחרוזות צריכים גרשיים בודדים בתוך ה-query.** `WHERE B = "Yoav"` נותן שגיאה כי הגרש הכפול מסיים את מחרוזת ה-JS. תמיד גרשיים בודדים בתוך מחרוזת ה-query.
- **השוואות תאריכים צריכות `date 'YYYY-MM-DD'`.** `WHERE A >= '2026-05-01'` מתייחס למחרוזת כטקסט ומשווה לקסיקוגרפית. לפעמים עובד, לעיתים קרובות לא. תמיד: `WHERE A >= date '2026-05-01'`.
- **`SELECT *` יחד עם `GROUP BY` נותן שגיאה.** GROUP BY (שיעור 13) דורש מ-SELECT לפרט עמודות. אי אפשר ש-`SELECT *` ואגרגציה יהיו ב-query אחד.
- **QUERY מול נתוני IMPORTRANGE צריכה את ארגומנט הכותרת מפורש.** השתמשו ב-`QUERY(IMPORTRANGE(...), "SELECT ...", 1)` ובדקו שוב את אותיות העמודות. עמודות IMPORTRANGE הן מיקומיות מהטווח שייבאתם, לא מגיליון המקור.
- **טווחים בלי כותרת מחליפים את מזהי העמודות מ-`A/B/C` ל-`Col1/Col2/Col3`.** העבירו `A1:F13` עם `headers=1` ותוכלו לכתוב `WHERE B = 'Yoav'`. העבירו `A2:F13` עם `headers=0` (או עטפו `IMPORTRANGE` שמגיע חסר-כותרת) ואותו query חייב לומר `WHERE Col2 = 'Yoav'`. ערבוב של השניים הוא שגיאת ה-parsing הנפוצה ביותר ב-QUERY. (מזהי העמודות עצמם לא רגישים ל-case; `b` קטנה עובדת בכל מקום ש-`B` גדולה עובדת.)
