# Named functions: בניית אוצר המילים של הצוות

**Named function** הוא `LAMBDA` (שיעור 1.18) ששמור לחוברת עם שם, תיאור, ותיעוד parameters. אחרי שמגדירים אותו, כל מי שמשתמש בחוברת יכול לקרוא לו כמו לפונקציה מובנית: `=ROI(E2, F2)` במקום `(F2-E2)/E2` inline, `=BUYER_TIER(buyer)` במקום שלושה `IF` מקוננים, `=NORMALIZE_PLATFORM(raw)` במקום שרשרת של קריאות `SUBSTITUTE`. הגדרת הפונקציה חיה במקום אחד; כל נוסחה שמשתמשת בה נשארת עקבית.

לצוות שמריץ דאשבורדים רבים על אותם נתונים, זה המהלך עם המינוף הגבוה ביותר בכל מסלול הנוסחאות. אתם מפסיקים להעתיק-להדביק ביטויים מסובכים על פני לשוניות. אתם מפסיקים לחפש "איפה הגדרנו את התאמת העמלה?" כשהתעריף משתנה. אתם מפסיקים לתקן את אותו באג בשבע-עשרה מקומות כשהגדרת מטריקה זזה. אוצר המילים של הצוות עובר מידע שבטי בראשי האנשים לפונקציות אמיתיות שניתנות לקריאה בחוברת.

## מה צריך לפני השיעור הזה

הגוף של כל named function הוא `LAMBDA`. שיעור 1.18 מכסה את התחביר של `LAMBDA` לעומק; שיעור 1.19 מכסה את משפחת `MAP`/`REDUCE`/`SCAN`/`BYROW`/`BYCOL` שלעיתים קרובות מתחברת ל-named functions. אם לא עשיתם את אלה, השיעור הזה ייקרא כמרק של תחביר; תעשו אותם קודם.

## יצירת named function

תהליך העבודה:

1. **Data ← Named functions.** פותח את לוח הצד.
2. לוחצים על **Add new function**.
3. ממלאים:
   - **Name**: אותיות גדולות, ללא רווחים. קונבנציה: `ROI`, `EFFECTIVE_CPC`, `BUYER_TIER`.
   - **Description**: מה הפונקציה עושה. מופיע ב-autocomplete ובעוזר הפונקציות.
   - **Argument placeholders**: שורה אחת לכל parameter, עם שם ותיאור.
   - **Formula definition**: הגוף, נכתב בדיוק כמו גוף `LAMBDA` אבל מפנה לשמות ה-parameters ישירות (ללא עטיפת `LAMBDA(...)`).
4. לוחצים על **Next ← Create**.

הפונקציה זמינה עכשיו בחוברת. הקלידו `=ROI(` ו-Sheets ישלים אותה כמו כל מובנית.

### דוגמה 1: הגדרת `ROI`

Argument placeholders: `spend`, `revenue`. Formula definition: `(revenue - spend) / spend`. זאת כל הפונקציה.

מנוע ה-sandbox בשיעור הזה לא יכול לפענח named functions ברמת חוברת, אז ההדגמה האינטראקטיבית משתמשת בצורת ה-`LAMBDA + LET` המקבילה inline (שיעור 1.18). ברגע שתעלו גיליון אמיתי בסוף השיעור, תיצרו את ה-named function בפועל ותכתבו `=ROI(E2, F2)` ישירות.

## רקורסיה

Named functions יכולים לקרוא לעצמם בשם. הדוגמה הקלאסית היא עצרת:

```
FACT(n) = IF(n <= 1, 1, n * FACT(n - 1))
```

באדטק, רקורסיה נדירה אבל שימושית ל-lookups היררכיים: "מצא את חשבון האב במעלה עץ הארגון", "לך על שרשרת הורים עד שאתה פוגע בעלה". פשוט תזכרו את תקרת העומק (Sheets חותך רקורסיה אחרי כמה מאות רמות כדי למנוע נוסחאות בורחות).

## ייבוא named functions בין חוברות

Named functions מוגדרים בתחום של חוברת אחת. כדי להשתמש בפונקציה שמוגדרת בגיליון אחר:

1. פותחים את הגיליון היעד.
2. **Data ← Named functions ← Import function.**
3. בוחרים את חוברת המקור ואת הפונקציות לייבוא.

ככה הצוות מתחזק חוברת "הגדרות". מגדירים `ROI`, `ROAS`, `BLENDED_CPM`, `MARGIN`, `BUYER_TIER` בחוברת אחת; מייבאים לכל דאשבורד. המלכודת: **ייבואים לא מתעדכנים אוטומטית.** משנים את הגדרת המקור והייבואים הקיימים שומרים על הלוגיקה הישנה עד שמישהו מייבא מחדש. זה במתכוון (שינויים drive-by להגדרה משותפת יכולים לשבור גיליונות תלויים בשקט) אבל זה מפיל אנשים.

ההרגל של הצוות: כשפונקציה משותפת משתנה, שולחים שורה אחת ב-Slack כדי שהתלויים ידעו לייבא מחדש.

## מתי לקדם `LAMBDA` ל-named function

חוקי האצבע של חמש שניות:

- אותו `LAMBDA` מופיע בשלושה תאים או יותר, או ב-`MAP` על טווח ארוך. תקדמו.
- הגוף ארוך מ-80 תווים בערך. תקדמו.
- כמה אנשים בצוות צריכים להשתמש באותו חישוב. תקדמו.
- החישוב עשוי להשתנות לאורך זמן (מבנה עמלה, הגדרת ROI, סף). תקדמו.
- זה חישוב חד-פעמי בתא בודד. אל תקדמו: שמרו אותו inline עם `LET + LAMBDA` (שיעור 1.20).

## נפוץ בשטח

- **ספריית KPI של הצוות.** מגדירים `ROI`, `ROAS`, `MARGIN`, `BLENDED_CPM`, `EFFECTIVE_CPC`, `BUYER_TIER`, `IS_PROFITABLE` פעם אחת. מייבאים לכל דאשבורד. אוצר המילים של הצוות חי בנוסחאות, לא בידע שבטי.
- **Validators מותאמים.** `IS_VALID_CAMPAIGN_CODE(code)` עוטף `REGEXMATCH` מול קונבנציית השמות של הצוות (שיעור 1.16). שימוש חוזר בעיצוב מותנה, ב-`QUERY` filters, בבדיקות דאשבורד.
- **Normalizers חוצי-פלטפורמות.** `NORMALIZE_PLATFORM(raw)` ממפה את `"TBL"`, `"Taboola"`, `"taboola_native"` כולם ל-`"Taboola"`. פונקציה אחת, בשימוש בכל מקום שיש שמות פלטפורמה מבולגנים.
- **Lookups מודעי-תקופה.** `MTD_SPEND(buyer)` מחזיר spend מתחילת החודש ל-buyer. עוטף את ה-`SUMIFS` + חישוב תאריך כך שדאשבורדים לא ממציאים מחדש את לוגיקת התאריכים בכל פעם.
- **סיווגי tier.** `BUYER_TIER(spend)` מחזיר `"T1"` / `"T2"` / `"T3"` בהתבסס על spend מתגלגל. הספים חיים בהגדרת הפונקציה; משנים את הספים פעם אחת, כל דאשבורד מתעדכן.

## מלכודות מקצועיות

- **Named functions לא עוברים לחוברות אחרות אוטומטית.** או מגדירים מחדש או מייבאים. אין namespace "גלובלי".
- **פונקציות מיובאות לא מתעדכנות אוטומטית.** מייבאים מחדש כדי לתפוס שינויים מהמקור. בנו הרגל: כשאתם משנים פונקציה משותפת, פינגו את הצוות לייבא מחדש.
- **אין arguments אופציונליים, אין ערכי ברירת מחדל.** כל argument חייב להיות מועבר. עוקפים: השתמשו ב-sentinel כמו `0` או `""` וטפלו בו בתוך הגוף עם `IF`.
- **אין בדיקת סוגים.** פונקציה שמצפה למספר תקבל טקסט וגם תפיק תשובה שגויה או `#VALUE!`. אין אכיפת חתימה. תעדו סוגי parameters בתיאור כדי שמי שקורא ידע מה להעביר.
- **עומק רקורסיה מוגבל.** Hard cap הוא כמה מאות. בסדר ל-tree walks, חסר תועלת לרקורסיה מספרית עמוקה.
- **שמות מתנגשים עם מובנות בשקט.** אם אתם מגדירים `SUM` כ-named function, ה-`SUM` שלכם מאפיל על המובנית בתוך החוברת. הימנעו מזה עם prefix (`MY_SUM`) או שמות מובחנים.
- **עריכת פונקציה בזמן שנוסחאות מפנות אליה יכולה לשבור דברים.** Sheets מטפל בשינויי שם וחתימה על ידי כשל של נוסחאות תלויות. תכננו שינויים; אל תערכו פונקציה חיה ביום דיווח עמוס.
- **הגוף יכול להפנות לתאים ול-named ranges ישירות, אבל התייחסו לזה כ-code smell חזק.** Sheets מאפשר לגוף של named function לקרוא <code>$A$1</code>, <code>Settings!B2</code>, או named range כמו <code>fee_rate</code>, אבל לעשות את זה כובל את הפונקציה למבנה ספציפי של חוברת. ברגע שמישהו מייבא את הפונקציה לחוברת אחרת (או אפילו משנה את שם הגיליון שהפונקציה קוראת ממנו), הגוף נשבר או מחזיר מספרים שגויים בלי סיבה ברורה. העדיפו parameters: העבירו קבועי חוברת כארגומנטים כדי שהפונקציה תישאר ניידת. שלפו references מוטמעים לתאים רק כשה-named function היא ספציפית לחוברת במכוון (למשל, היא עוטפת קבוע ברמת חוברת שאין לו משמעות מחוץ לאותה חוברת), ותעדו את האילוץ הזה בתיאור של הפונקציה כדי שמייבאים עתידיים לא יתנגשו בו.
