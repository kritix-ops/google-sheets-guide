# Named functions: בניית אוצר המילים של הצוות

**Named function** הוא LAMBDA ששמור ל-spreadsheet עם שם, תיאור, ותיעוד parameters. אחרי שמגדירים אותו, כל מי שמשתמש ב-spreadsheet יכול לקרוא לו כמו לפונקציה מובנית:

```
=ROI(E2, F2)
=ROAS(SUM(Campaigns[Spend]), SUM(Campaigns[Revenue]))
=EFFECTIVE_CPC(SUM(Campaigns[Spend]), SUM(Campaigns[Clicks]))
```

זה המהלך עם מינוף הגבוה ביותר לצוות שמריץ הרבה dashboards. מגדירים את `ROI` פעם אחת, במקום אחד, עם תיעוד. כל נוסחה ב-dashboard שמשתמשת ב-`ROI` נקראת כ-`=ROI(spend, revenue)`. מפורש, עקבי, וניתן לשינוי ממקום אחד.

## יצירת named function

1. **Data → Named functions.** פותח את פאנל הצד.
2. לוחצים **Add new function**.
3. ממלאים:
   - **Name**: אותיות גדולות, ללא רווחים. מוסכמה: `ROI`, `EFFECTIVE_CPC`, `BUYER_TIER`.
   - **Description**: מה הפונקציה עושה. מוצג ב-autocomplete ובעוזר הפונקציות.
   - **Argument placeholders**: שורה לכל parameter, עם שם ותיאור.
   - **Formula definition**: הגוף, שנכתב בדיוק כמו גוף LAMBDA אבל מתייחס לשמות ה-parameters ישירות (בלי עטיפת `LAMBDA(...)`).
4. לוחצים **Next → Create**.

הפונקציה זמינה עכשיו ב-spreadsheet. מקלידים `=ROI(` ו-Sheets משלים אוטומטית כמו לכל פונקציה מובנית.

## דוגמה: הגדרת `ROI`

Argument placeholders: `spend`, `revenue`.
Formula definition: `(revenue - spend) / spend`.

זו הפונקציה כולה. עכשיו בכל מקום ב-spreadsheet:

```
=ROI(342.18, 487.30)        → 0.4241
=ROI(E2, F2)                → ROI של שורה 2
=ROI(SUM(Campaigns[Spend]), SUM(Campaigns[Revenue]))   → ROI של התיק
```

בלי ה-named function, כל נוסחה מחשבת מחדש את `(revenue - spend) / spend` inline, וכל נוסחה שרוצה להוריד עמלה צריכה להתעדכן באופן עצמאי.

## רקורסיה

Named functions יכולים לקרוא לעצמם. הדוגמה הקלאסית היא Fibonacci או עצרת:

```
FACT(n) = IF(n <= 1, 1, n * FACT(n - 1))
```

באדטק, רקורסיה נדירה, אבל היא שימושית ל-lookups היררכיים: "מצא את חשבון האב למעלה בעץ הארגון". רק זוכרים את מגבלת העומק (Sheets מגביל רקורסיה כדי למנוע נוסחאות מתפרצות).

## ייבוא של named functions בין גיליונות

Named functions תחומים ל-spreadsheet אחד. כדי להשתמש בפונקציה מ-spreadsheet אחר:

1. פותחים את ה-spreadsheet היעד.
2. Data → Named functions → **Import function**.
3. בוחרים את ה-spreadsheet המקור ואת הפונקציות לייבוא.

ככה הצוות מתחזק spreadsheet של "definitions". מגדירים את `ROI`, `ROAS`, `BLENDED_CPM`, `MARGIN`, `BUYER_TIER` במקום אחד. מייבאים לכל dashboard. כשמעדכנים את המקור, הייבואים **לא** מתעדכנים אוטומטית. צריך לייבא מחדש כדי לקלוט שינויים. זה במכוון (שינויים בהגדרה משותפת יכולים לשבור גיליונות תלויים) אבל מפיל אנשים.

## מתי לקדם LAMBDA ל-named function

- אותו LAMBDA מופיע בשלושה תאים או יותר, או ב-MAP על פני טווח ארוך. לקדם.
- הגוף ארוך מ-80 תווים בערך. לקדם.
- כמה אנשים בצוות צריכים להשתמש באותו חישוב. לקדם.
- החישוב עשוי להשתנות עם הזמן (מבנה עמלות, הגדרת ROI). לקדם.
- זה חישוב חד פעמי בתא יחיד. לא לקדם, להשאיר inline עם LET + LAMBDA.

## נפוץ בשטח

- **ספריית KPI של הצוות.** מגדירים את `ROI`, `ROAS`, `MARGIN`, `BLENDED_CPM`, `EFFECTIVE_CPC`, `BUYER_TIER`, `IS_PROFITABLE` פעם אחת. מייבאים לכל dashboard. אוצר המילים של הצוות חי בנוסחאות, לא בידע שבטי.
- **Validators מותאמים אישית.** `IS_VALID_CAMPAIGN_CODE(code)` עוטף REGEXMATCH מול מוסכמת השמות של הצוות. שימוש חוזר ב-conditional formatting, בפילטרי QUERY, בבדיקות dashboard.
- **נרמלים בין-פלטפורמות.** `NORMALIZE_PLATFORM(raw)` ממפה "TBL", "Taboola", "taboola_native" כולם ל-"Taboola". פונקציה אחת, בשימוש בכל מקום ששמות פלטפורמות מבולגנים מופיעים.
- **Lookups מודעי-תקופה.** `MTD_SPEND(buyer)` מחזיר spend מתחילת החודש לקונה. עוטף את ה-SUMIFS+חשבון-תאריכים כך ש-dashboards לא ימציאו מחדש את לוגיקת התאריכים.
- **סיווגי tier.** `BUYER_TIER(spend)` מחזיר "T1" / "T2" / "T3" בהתבסס על spend מתגלגל. הספים חיים בהגדרת הפונקציה. משנים את הספים, כל dashboard מתעדכן.

## מלכודות מקצועיות

- **Named functions לא עוברים אוטומטית בין spreadsheets אחרים.** או מגדירים מחדש או מייבאים. אין namespace "גלובלי".
- **פונקציות מיובאות לא מתעדכנות אוטומטית.** מייבאים מחדש כדי לקלוט שינויים מהמקור. בונים הרגל: כשמשנים פונקציה משותפת, מודיעים לצוות לייבא מחדש.
- **אין ארגומנטים אופציונליים, אין ערכי ברירת מחדל.** כל ארגומנט חייב להיות מועבר. דרך עקיפה: משתמשים ב-sentinel כמו `0` או `""` ומטפלים בו בתוך הגוף עם IF.
- **אין בדיקת סוגים.** פונקציה שמצפה למספר תקבל טקסט ותפיק תשובה שגויה או `#VALUE!`. אין אכיפת חתימה. מתעדים סוגי parameters בתיאור.
- **עומק רקורסיה מוגבל.** התקרה הקשיחה היא כמה מאות. מספיק להליכות עץ, חסר תועלת לרקורסיה מספרית עמוקה.
- **שמות מתנגשים עם מובנות** בשקט. אם מגדירים את `SUM` כ-named function, ה-`SUM` שלכם מסתיר את המובנה בתוך ה-spreadsheet. נמנעים מזה. משתמשים בקידומות ספציפיות (`MY_SUM`) או בשמות נפרדים.
- **עריכת פונקציה בזמן שנוסחאות מפנות אליה יכולה לשבור דברים.** Sheets מטפל בשינויי שמות וחתימה על ידי הפלת נוסחאות תלויות. מתכננים שינויים. לא עורכים בזמן אמת ביום דיווח עמוס.

## עכשיו לעבודה אמיתית
