# IMPORTRANGE ומשפחת ה-IMPORT

זה השיעור שהצוות יירצה להדפיס ולתלות על הקיר. `IMPORTRANGE` היא הנוסחה הכי בשימוש והכי שבורה ב-spreadsheets: היא מושכת נתונים מ-spreadsheet אחר, וזה הבסיס של כל dashboard חוצה צוותים. כשזה עובד, זה מרגיש קסם. כשזה נשבר, כל יום הדיווח עוצר.

`IMPORTRANGE` מופיעה בכל workbook שהצוות נוגע בו: גיליונות פר-פלטפורמה שמושכים נתונים גולמיים מכל רשת פרסום, גיליונות aggregator שמחברים הכול, dashboards שבנויים מעל ה-aggregators. ביטול הרשאות, שינוי שמות workbooks במקור, התרחבות טווחים שזזה, קוריוזי קצב refresh, ומפלי `#REF!` כשגיליון אחד למעלה נשבר. הצוות פוגש את כל זה, כל הזמן. קוראים את השיעור הזה פעמיים. ואז קוראים שוב בפעם הבאה ש-IMPORTRANGE נשבר.

## ארבע פונקציות ה-IMPORT

| פונקציה | מקור | שימוש |
|---|---|---|
| `IMPORTRANGE` | Google Sheet אחר | משיכת נתונים בין spreadsheets (95% מהשימוש) |
| `IMPORTHTML` | דף HTML (טבלה או רשימה) | scraping של טבלאות web ציבוריות |
| `IMPORTDATA` | URL שמגיש CSV/TSV | משיכת נתונים מיוצאים מ-URL ציבורי |
| `IMPORTXML` | דף XML/HTML עם XPath | scraping ממוקד עם בוררי XPath |

`IMPORTRANGE` שולטת בעבודת אדטק יומיומית. השלוש האחרות מופיעות מדי פעם לניתוחים נקודתיים. נכסה אותן בקצרה אחרי הצלילה לעומק על IMPORTRANGE.

## IMPORTRANGE: התחביר

```
=IMPORTRANGE("spreadsheet_url_or_id", "sheet_name!range")
```

שני ארגומנטים, שניהם מחרוזות:

<FunctionRef name="IMPORTRANGE" />

1. ה-URL המלא של ה-spreadsheet מקור (או רק ה-file ID, החלק שבין `/d/` ל-`/edit`).
2. הטווח, עם שם הטאב ו-`!` בקידומת. דוגמה: `"Campaigns!A1:F100"` או `"Campaigns!A:F"` לעמודות שלמות.

```
=IMPORTRANGE("https://docs.google.com/spreadsheets/d/1ABC.../edit", "Campaigns!A:F")
```

התוצאה נשפכת כמערך דו-ממדי שמתחיל בתא של הנוסחה. עם `A:F`, מקבלים את כל השורות בעמודות האלו מגיליון המקור.

## זרימת ה-auth (איפה זה תמיד נשבר)

בפעם הראשונה שמשתמשים ב-IMPORTRANGE שמצביע למקור חדש, הנוסחה מחזירה `#REF!` עם ההודעה **"You need to connect these sheets."** לוחצים על התא, לוחצים **Allow access**, ו-Sheets יוצר יחס אמון חד-כיווני מהמקור ליעד.

פרטים קריטיים על ה-auth:

- האמון הוא **לכל זוג של גיליון מקור ליעד**. חיבור מ-"dashboard" ל-"raw data" לא מחבר אוטומטית מ-"dashboard" לגיליון *אחר* של "raw data".
- רק מישהו עם **גישת עריכה** לשני הגיליונות יכול לאשר את החיבור. אם הרשאות הצוות מפוצלות, בעל ה-dashboard שאין לו עריכה על המקור לא יכול לאשר.
- ברגע שמחוברים, **כל משתמש עם גישת צפייה ליעד** יכול לראות את הנתונים המיובאים, גם אם אין לו גישה למקור. זה הפרט הקריטי שצריך לזכור כשמטפלים בנתונים רגישים: ייבוא דולף במורד הזרם.
- הסרת גישה מהמקור לא שוברת את הנוסחה מיד. Sheets שומר cache; השבירה מופיעה כשה-cache פג או כשמישהו לוחץ "refresh."

## מציאות הביצועים

`IMPORTRANGE` היא **איטית**. כל תא שמשתמש ב-IMPORTRANGE עושה network round-trip בטעינה הראשונה ובהשבתת cache. dashboard עם 50 נוסחאות IMPORTRANGE לוקח שניות (או עשרות שניות) להיטען בהפעלה קרה.

דפוסים שלא מתרחבים:

- IMPORTRANGE אחד לכל תא, נגרר לאורך עמודה. כל תא עושה בקשה משלו.
- IMPORTRANGE בתוך MAP או BYROW. נורית N פעמים.
- IMPORTRANGE בתוך פונקציה תנודתית (כמו INDIRECT, שיעור 1.25). יורית מחדש בכל חישוב מחדש.

דפוסים שכן מתרחבים:

- **IMPORTRANGE אחד לכל מקור לכל dashboard.** מושכים את כל העמודות הנדרשות, בקריאה אחת, לבלוק אחד. מפנים *לבלוק הזה* מנוסחאות במורד הזרם.
- **עוטפים ב-QUERY כדי לסנן במקור.** `=QUERY(IMPORTRANGE(...), "SELECT Col2, Col5 WHERE Col2 = 'Yoav'", 1)` מהיר יותר מלייבא הכול ולסנן במורד הזרם, כי Sheets שופך רק את התוצאה המסוננת.
- **עוטפים ב-LET** (שיעור 1.20) כך שה-import מחושב פעם אחת גם כשמשתמשים בו כמה פעמים באותה נוסחה:

```
=LET(
  data, IMPORTRANGE("...url...", "Campaigns!A:F"),
  total, SUM(INDEX(data, , 5)),
  count, ROWS(data) - 1,
  total / count
)
```

ה-`data` הוא ה-IMPORTRANGE; `total` ו-`count` שניהם מפנים אליו. בלי LET, ה-IMPORTRANGE היה רץ פעמיים.

## ה-cache וה-refresh

IMPORTRANGE שומרת תוצאות ב-cache כדי להימנע משליפה מחדש כל הזמן. ה-cache מתבטל ב:

- שינוי בנתוני המקור (Sheets צופה ודוחף עדכונים, בדרך כלל בתוך דקה).
- פתיחת spreadsheet אחרי שה-cache פג (TTL משתנה, לעיתים קרובות סביב שעה).
- refresh ידני. אין כפתור UI; הדרך היא למחוק את הנוסחה ולהקליד מחדש.

**כדי לאלץ refresh:** מבצעים עריכת no-op במקור (מקלידים ערך, undo). Sheets דוחף שוב לכל המנויים. או ביעד, עורכים ומחזירים את נוסחת ה-IMPORTRANGE.

הטיקטים של "ה-dashboard לא נכון" של הצוות הם 80% בעיות cache ישן. בונים הרגל של force-refresh לפני ציטוט מספרים בפגישה.

## IMPORTHTML, IMPORTDATA, IMPORTXML

בשימוש פחות תכוף, אבל שווה להכיר.

**IMPORTHTML** עושה scraping לטבלה או רשימה ממוספרת מדף HTML ציבורי:

```
=IMPORTHTML("https://en.wikipedia.org/wiki/...", "table", 2)
```

מושך את הטבלה השנייה מאותו דף ויקיפדיה. הארגומנט השלישי הוא האינדקס (1-based).

**IMPORTDATA** מושך CSV או TSV מ-URL:

```
=IMPORTDATA("https://example.com/data.csv")
```

שימושי כשפרטנר מפרסם נתונים יומיים כ-CSV ב-URL יציב.

**IMPORTXML** עושה scraping ממוקד עם XPath:

```
=IMPORTXML("https://example.com", "//div[@class='price']")
```

XPath מילולי אבל חזק כשצריך אלמנט בודד ולא טבלה שלמה.

שלוש אלה עובדות רק על URLs **ציבוריים** (בלי auth). למקורות נתונים פרטיים, משתמשים ב-Apps Script עם `UrlFetchApp` במקום.

## נפוץ בשטח

- **לוג קמפיינים אחד שהוא מקור אמת לכל שוק.** הצוות של כל אזור מחזיק spreadsheet אחד; כל dashboard מושך דרך IMPORTRANGE עטוף ב-QUERY כדי לסנן למטריקות שה-dashboard צריך.
- **dashboard חיובים בין חשבונות.** IMPORTRANGE מהגיליון המיוצא של כל פלטפורמה, UNION דרך ערימת סוגריים מסולסלים, נרמול שמות עמודות, הצגה בתצוגה אחת.
- **גיליון שערי המרה יומיים.** IMPORTDATA מ-FX API חינמי שמחזיר CSV; תאים מפנים אליו לנרמול מטבעות.
- **מעקב מחירי מתחרים.** IMPORTHTML מול דף תמחור ציבורי של מתחרה. לא יציב (שינויים ב-HTML שוברים אותו), אבל שימושי כשהוא עובד.
- **דפי סטטוס.** IMPORTXML עם XPath מול דף סטטוס ציבורי של פרטנר; תא קטן `=IF(IMPORTXML(...) = "operational", "OK", "DOWN")` ב-dashboard של הצוות.

## מלכודות מקצועיות

- **`#REF!` אחרי שעבד מצוין שבועות** בדרך כלל אומר שהטאב של המקור שונה בשם, עמודות זזו, או שמישהו ביטל הרשאה. הבדיקה הראשונה היא "האם גיליון המקור השתנה?"
- **`#N/A` במקום `#REF!`** יכול לומר ש-auth של החיבור בוטל. מבססים מחדש דרך ההתראה של "Allow access" בתא.
- **ייבוא טווחים ענקיים (`A:Z`) בכל נוסחה** מביא את ה-dashboard לזחילה. תמיד מייבאים את הטווח הקטן ביותר שצריך; עוד יותר טוב, עוטפים ב-QUERY כדי לסנן במקור.
- **עמודות IMPORTRANGE הן לפי מיקום, לא לפי שם.** כשמפנים לנתונים מיובאים דרך `INDEX(imported, , 3)`, אומרים "עמודה 3 של מה שייבאתי". אם המקור מוסיף עמודה במיקום 2, ה-INDEX 3 שלכם עכשיו מצביע לשדה אחר. מייבאים כותרות עמודות ומחפשים מיקומים עם MATCH (שיעור 1.4).
- **IMPORTRANGE-של-IMPORTRANGE מותר אבל מכפיל את ה-latency.** אם צריך שרשרת (גיליון A → גיליון B → גיליון C), כל קפיצה משלמת את עלות ה-round-trip. בונים מחדש כשאפשר.
- **שיתוף dashboard בהיקף רחב** עם IMPORTRANGE אומר שהנתונים של המקור נגישים מובלעת לכל מי שיש לו גישת צפייה ל-dashboard, גם אלו שאין להם גישה למקור. בודקים לפני שיתוף חיצוני.
- **`IMPORTRANGE` לא משמרת עיצוב תאים.** צבעים, פורמטים מספריים, conditional formatting, הכול נשטף. מעצבים את היעד בנפרד או מחילים conditional formatting על הטווח המיובא.
- **מעגלים רקורסיביים גורמים לשגיאת `#REF!`.** אם גיליון A מייבא מגיליון B וגיליון B מייבא מגיליון A, שניהם נשברים. Sheets מזהה את המעגל ומסרב לשניהם.
- **תאריכים מטקסט ב-`IMPORTRANGE` מגיעים כמחרוזות, לא כתאריכים.** `2026-05-11` במקור יכול לנחות ביעד כטקסט מילולי `"2026-05-11"` ולא להתאים לפילטר מבוסס `DATE()`. עוטפים ב-`DATEVALUE` או מאלצים upstream (שיעור 1.8).

## עכשיו לעבודה אמיתית

לחצו על **Start lesson** כדי להעלות גיליון עם לוג הקמפיינים. תכתבו שלוש נוסחאות שמחקות דפוסי IMPORTRANGE: IMPORTRANGE בסיסי (מול גיליון דוגמה ציבורי שמסופק על ידי המערכת), IMPORTRANGE עטוף ב-QUERY כדי לסנן במקור, ו-IMPORTRANGE מוגן ב-IFERROR עם הודעת fallback.
