# Macros: record, edit, share

A macro in Google Sheets is just a regular Apps Script function that's been **registered in the manifest** so it shows up under Tools → Macros with an optional keyboard shortcut. There's nothing magic in the function itself; it uses the same `SpreadsheetApp` and `Range` calls from the last two lessons. The new piece is the registration: that's what makes the function reachable from the Tools menu instead of only from the Apps Script editor's Run dropdown.

Macros are how a team makes one-shot manual operations repeatable: format the new month's tab, archive last month's data, mark a batch of campaigns as dead. The buyer who needs the action doesn't have to know any Apps Script; they pick the macro from the menu and it runs.

## Recorded vs hand-written

Sheets has a Record Macro feature (Extensions → Macros → Record macro). The flow is exactly what it sounds like: you start recording, you do a sequence of edits in the UI, you stop recording, and Sheets writes the Apps Script function that reproduces those edits. It looks attractive (no code to write) and then you read what it produced:

```js
function MyMacro() {
  var spreadsheet = SpreadsheetApp.getActive();
  spreadsheet.getCurrentCell().setNumberFormat('$#,##0.00');
  spreadsheet.getActiveRangeList().setFontWeight('bold');
};
```

Two problems:

1. **It uses `getCurrentCell()` and `getActiveRangeList()`.** These read whatever cell the user happens to be on when the macro runs. The macro that worked perfectly when you recorded it on F2 now formats the wrong cell when a teammate runs it from D17.
2. **There's no error handling, no logging, no constants.** If anything breaks at runtime (the sheet was renamed, the range was deleted), the macro fails silently or with an unhelpful message.

Recorded macros are a starting point, not a destination. The team's actual macros are hand-written. They look like the lesson 4 / lesson 5 examples: explicit `getSheetByName`, explicit A1 ranges, intentional structure.

```js
function formatNewMonth() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName("Campaigns");
  sheet.getRange("F2:F61").setNumberFormat("$#,##0.00");
  sheet.getRange("G2:G61").setNumberFormat("$#,##0.00");
  sheet.setFrozenRows(1);
}
```

The function name is the macro name. The body is just regular `SpreadsheetApp` code.

## Registering the macro

A function only shows up under Tools → Macros once it's listed in the project's `appsscript.json` manifest under `sheets.macros`:

```json
{
  "timeZone": "America/New_York",
  "sheets": {
    "macros": [
      {
        "menuName": "Format new month",
        "functionName": "formatNewMonth",
        "defaultShortcut": "Ctrl+Alt+Shift+1"
      }
    ]
  }
}
```

The three fields:

| Field | What it does |
|---|---|
| `menuName` | The label the user sees under Tools → Macros. Keep it specific. "Format" alone is ambiguous next to other macros. |
| `functionName` | The JS function this macro runs. Must match the function declaration exactly (case-sensitive). |
| `defaultShortcut` | Optional. The keyboard combo that fires the macro. Sheets allocates `Ctrl+Alt+Shift+1` through `Ctrl+Alt+Shift+9` for user macros. |

You can hand-edit the manifest, but the friendlier path is **Extensions → Macros → Manage macros → Add new macro**. It opens a small dialog where you pick the function and label, and Sheets writes the manifest entry for you.

## Where macros differ from menu items

Lesson 5's `addReportsMenu` built a custom menu in the spreadsheet toolbar. A macro is similar but lives in a different surface:

| | Menu item (lesson 5) | Macro |
|---|---|---|
| Where it lives | Custom toolbar menu (Reports, Buyer tools, etc.) | Tools → Macros submenu |
| How it's registered | `createMenu().addItem(...)` called from `onOpen` | An entry in `appsscript.json`'s `sheets.macros` |
| Keyboard shortcut | None by default | Optional `Ctrl+Alt+Shift+1..9` |
| Visible to other users | Yes, on every open | Yes, on every open |
| When to use | Grouped sets of actions (Reports menu with 5 items) | Single high-frequency action you want a shortcut for |

In practice the team uses both. Reports, Buyers, Cleanup get their own menus; one-off actions like "Format new month" or "Archive month" become macros so they get a Ctrl+Alt+Shift+1 shortcut.

## Sharing a macro

The macro is a function in the bound Apps Script project. Anyone with edit access to the spreadsheet has the macro available; they don't need to install anything, and they don't need access to the Apps Script editor unless they want to modify the function. The first time someone runs it they get the OAuth consent prompt; after that it just works.

The catch when sharing: **the keyboard shortcut is per-user, per-spreadsheet.** The buyer who opened the spreadsheet for the first time has to go to Tools → Macros → Manage macros and assign their own shortcut. The default in the manifest is what each new user starts from, but they can override it locally.

## Apps Script writes are NOT undoable

This is the most painful surprise in any macro. **Ctrl+Z does not undo what a macro did.** Apps Script writes go through a different API path than user edits, and the undo stack is for user edits only. A macro that overwrites 500 rows with the wrong data leaves the buyer with no way back except restoring from version history (File → Version history → See version history).

Two consequences for how you write macros:

1. **Confirm before any destructive change.** A `ui.alert("This will overwrite the Aggregator tab. Continue?", ui.ButtonSet.YES_NO)` gate before a `setValues` that overwrites 500 rows is mandatory, not optional.
2. **Snapshot before mutating.** A macro that mutates rows in place can start by copying the original range to a hidden "Backup" tab. Cheap insurance.

The starter file `Lesson.gs` declares `function formatSpendColumn()` with a TODO. Three steps:

1. Get the Campaigns sheet via `SpreadsheetApp.getActiveSpreadsheet().getSheetByName("Campaigns")`.
2. Apply the currency format to F2:F61: `sheet.getRange("F2:F61").setNumberFormat("$#,##0.00")`. The pattern uses `#` for optional digits, `0` for required digits, the comma for thousands grouping, the period and `00` for two-decimal precision, and `$` for the literal currency symbol.
3. Freeze the header row: `sheet.setFrozenRows(1)`. Now row 1 stays visible while scrolling, essential when the sheet grows past one screen.

Run the function once from the Apps Script editor's Run dropdown. F2:F61 renders as `$412.50`, `$285.30`, etc. Row 1 stays pinned when you scroll.

In a real workbook you'd then register this as a macro via Extensions → Macros → Manage macros so it shows up under Tools → Macros with a shortcut.

## Used in the wild

The team's "Format new month" macro is the canonical case. At the start of each month a new tab is added with the same column shape as the previous month's. The macro applies:

| Column | Format |
|---|---|
| A (Date) | `yyyy-mm-dd` |
| F (Spend), G (Revenue) | `$#,##0.00` |
| ROI column (computed) | `0.00` (two-decimal number) |
| All header cells | bold, light-gray background |

One macro, one Ctrl+Alt+Shift+1, zero clicks beyond that. Without the macro the buyer would spend ten minutes formatting a new tab every month. With the macro it's two seconds.

Other macros in the team's workbooks:

- **"Archive month"** copies the current Aggregator tab to a date-stamped backup sheet and clears the source.
- **"Mark dead campaigns"** sets the kill switch on every row where ROI dropped below 0.5 for three consecutive days.
- **"Recompute ROI column"** runs a deliberate recalc of column H (ROI) when the column has been edited by hand and a fresh recalc is needed.

## Pro pitfalls

- **Recorded macros that use `getCurrentCell()`.** They format whichever cell the user happens to be on. Replace `spreadsheet.getCurrentCell()` with `sheet.getRange("F2:F61")` (or whatever the macro is actually meant to target) the moment after the macro is recorded.
- **Macros that hardcode A1 references that break when columns are inserted.** A macro that targets `F2:F61` will keep targeting F2:F61 even after the team inserts a "Country" column between E and F, and now the macro formats the wrong column. Either name the column instead (look it up by header text) or use named ranges that move with insertions.
- **Macros that don't undo cleanly.** Apps Script writes are not in the undo stack. A macro that overwrites the wrong range leaves the user with no recourse except File → Version history. Gate destructive macros with `ui.alert(..., ui.ButtonSet.YES_NO)`.
- **Macros that take more than 30 seconds.** Simple triggers (including macros run from the Tools menu) have a 30-second soft timeout in some contexts and the 6-minute hard timeout in others. A macro that loops cell-by-cell over 50,000 rows will hit the limit. Batch reads with `getValues()` and batch writes with `setValues()` (the lesson 4 pattern) keep most macros well under a second.
- **`menuName` and `functionName` drifting apart.** The manifest entry's `functionName` and the actual JS function name are matched by string. Renaming the JS function without updating the manifest leaves Tools → Macros showing the old name but pointing at nothing; click and nothing happens.
- **A keyboard shortcut that collides with a browser shortcut.** `Ctrl+Alt+Shift+1` is mostly safe but Sheets occasionally introduces new internal shortcuts. If a macro shortcut stops working, check Tools → Macros → Manage macros to confirm it's still mapped, and pick a different combination if needed.
