# The execution model: V8, services, quotas, scopes

Apps Script looks like JavaScript and most of it is. What is different is the runtime environment: the engine that runs the code, the libraries it exposes, the limits it enforces, and the permission system that gates everything. Get a feel for this in lesson 2 and the rest of the track stops surprising you.

The mental model worth holding in your head from the start: when you press Run in the editor, your code does not execute in your browser. It is shipped to a Google data center, executed there by the Apps Script runtime, and the result is sent back. Every call to a Sheets, Drive, Gmail, or any other Workspace service is another network hop **inside** that data center, but a hop nonetheless. The two consequences (latency and quota) shape the way every realistic Apps Script function is written. Lesson 16 builds on this with the full batching playbook; this lesson is about why batching matters in the first place.

## V8 is the runtime (Rhino is gone)

Apps Script ran on two engines over its lifetime:

| Runtime | Era | What you get |
|---|---|---|
| Rhino | 2009-2026 | An old ECMAScript 5.x dialect. No `let`/`const`, no arrow functions, no template literals, no destructuring, no `async`/`await`. Deprecated Feb 20, 2025; **scripts on Rhino stopped executing on January 31, 2026** ([migration guide](https://developers.google.com/apps-script/guides/v8-runtime/migration)). |
| V8 | 2020-today | The same engine that runs Chrome. Modern ECMAScript with everything the rest of the JavaScript ecosystem assumes. The only runtime now. |

The manifest's `runtimeVersion` field reads `"V8"` on every live project. **V8 is the only choice, full stop.** If you open an old workbook whose manifest still lists `"DEPRECATED_ES5"`, those triggers no longer fire as of January 31, 2026: the editor accepts the value but the runtime refuses to execute. Switching is one manifest edit (`"runtimeVersion": "V8"`) plus testing: the rare incompatibility is around `this` binding inside callbacks and a few legacy global symbols that Rhino exposed (`importPackage`, etc.).

In practice, V8 means you write Apps Script with the same JavaScript you write everywhere else:

```js
// Template literals, destructuring, optional chaining, all native:
function summarize(campaign) {
  const { buyer, vertical, spend } = campaign;
  return `${buyer} on ${vertical}: $${spend?.toFixed(2) ?? "0.00"}`;
}
```

A small but useful inventory of what V8 unlocks that Rhino did not:

| V8 feature | Rhino equivalent |
|---|---|
| `let`, `const`, block scope | only `var`, function scope |
| Arrow functions | `function(){}` expressions |
| Template literals `` `${x}` `` | string concatenation with `+` |
| Destructuring `const { a, b } = obj` | `var a = obj.a; var b = obj.b;` |
| Default parameters | manual `if (x === undefined) x = ...` |
| `for...of` over arrays | classic `for (var i = 0; ...)` |
| `Array.from`, `Array.of`, spread `...` | `Array.prototype.slice.call(...)` tricks |
| Classes | constructor functions + prototype |
| Optional chaining `a?.b` | `a && a.b` |
| Nullish coalescing `x ?? y` | `(x === null \|\| x === undefined) ? y : x` |
| `async/await` | callback chains |

This lesson's assignment makes you use a template literal explicitly: that is the modern-syntax feature most likely to bite you if you inherit an old Rhino-era project whose manifest still names `DEPRECATED_ES5` (those triggers no longer execute after Jan 31, 2026, but the manifest value lingers and gets pasted around).

## Services

Apps Script's standard library is organized into **services**: top-level objects you call methods on. The ones a typical adtech workbook uses:

| Service | Used for |
|---|---|
| `SpreadsheetApp` | Reading and writing cells, ranges, sheets. The most-touched service. Lesson 4 covers this in depth. |
| `DriveApp` | Listing, creating, moving, sharing files. The way you find sheets to IMPORTRANGE into. Lesson 10 covers this. |
| `UrlFetchApp` | Outbound HTTP. How nightly Taboola/Outbrain pulls happen (the script-side alternative to the live `IMPORTRANGE` flow from lesson 1.27). Lesson 11 covers this. |
| `MailApp` / `GmailApp` | Sending email. The "spend exceeded budget" alert mailer. Lesson 10. |
| `CalendarApp` | Reading and writing calendar events. Less common in adtech. Lesson 10. |
| `ScriptApp` | Trigger management, deployments, the script's own metadata. Lesson 8. |
| `Session` | The active user. `Session.getActiveUser().getEmail()` returns who is running this. |
| `Utilities` | Date formatting, base64, blob handling, sleep. Helpers that do not fit anywhere else. |
| `CacheService` / `PropertiesService` | Per-script key/value storage. Cache is short-lived; Properties is persistent. Lesson 15. |
| `LockService` | Mutex when two trigger runs could race. Mandatory for nightly batch jobs. |
| `HtmlService` | Sidebar and dialog rendering. Lesson 9. |
| `ContentService` | Plain-text and JSON responses from web apps. Lesson 13. |
| `UserService` | Deprecated. Do not use. |

There are more (the "Advanced services" you enable in Resources let you call the Sheets API at a lower level, the BigQuery API, the Admin SDK; lesson 17 covers Sheets advanced service in detail). For 90% of workbook code you live in the table above.

Calling a service is a method-chain:

```js
const sheet = SpreadsheetApp.getActiveSpreadsheet()
  .getSheetByName("Aggregator");
const lastRow = sheet.getLastRow();
const data = sheet.getRange(2, 1, lastRow - 1, 7).getValues();
```

Each method call is a round-trip to Google's servers. The lesson on `SpreadsheetApp` (lesson 4) covers how to batch reads and writes so you do not pay the round-trip per cell. Lesson 16 covers batching across services.

## Quotas

Apps Script enforces three kinds of limit:

**Per-execution timeout.** A single script run cannot last forever:

| Account type | Maximum execution time |
|---|---|
| Consumer (gmail.com) | 6 minutes |
| Workspace | 6 minutes |

The 30-minute Workspace tier some older guides mention was retired; Google's current quotas page lists 6 minutes per execution for both account types. A script that hits this gets killed mid-write. The fix is to break long jobs into chunks and re-trigger via `ScriptApp.newTrigger(...).timeBased().at(...)` (covered in lesson 8): the recipe for processing 200,000 campaign rows is a 20,000-row chunk on a trigger that re-arms itself.

**Daily quotas per service.** Each service has its own daily cap. The ones that hurt most:

| Service | Free quota | Workspace quota |
|---|---|---|
| `UrlFetchApp` | 20,000/day | 100,000/day |
| `MailApp.sendEmail` | 100/day | 1,500/day |
| Trigger total runtime | 90 min/day | 6 hours/day |
| Sheets API custom function calls | 30,000/day | 30,000/day (same) |

The numbers shift over time; the current ones live at `developers.google.com/apps-script/guides/services/quotas`. Two relevant patterns:

- **One nightly trigger doing 20,000 UrlFetchApp calls saturates the free quota.** If you need more, parallelize across multiple Apps Script projects (each gets its own quota bucket) or move to a paid Workspace account.
- **MailApp's 100/day limit is per script, not per user.** A single script that emails every team member daily about their campaigns saturates fast. Use `GmailApp.sendEmail` (1,500/day on free, 10,000 on Workspace) for higher-volume mailing.

**Per-minute rate limits.** `UrlFetchApp` has a documented daily call limit (20,000/day consumer, 100,000/day Workspace) but no documented per-minute throttle. Community reports suggest a soft throttle around a few hundred per minute under sustained load; treat sustained rates above ~300/min as a risk and prefer `fetchAll` with batched payloads. Hit the throttle and you get a `Service invoked too many times in a short time` exception. The Apps Script wisdom is `Utilities.sleep(100)` between calls in a batch: cheap insurance.

## OAuth scopes

Every service call requires a permission grant. The manifest declares scopes explicitly:

```json
"oauthScopes": [
  "https://www.googleapis.com/auth/spreadsheets.currentonly",
  "https://www.googleapis.com/auth/script.container.ui",
  "https://www.googleapis.com/auth/script.external_request"
]
```

| Scope | What it unlocks |
|---|---|
| `spreadsheets.currentonly` | Read/write the active spreadsheet only. The narrowest useful scope. |
| `spreadsheets` | Read/write any spreadsheet the user can access. |
| `drive.file` | Read/write files this app created or that the user explicitly opened with it. |
| `drive` | Full Drive access. The scariest scope to ask for. |
| `script.container.ui` | Show sidebars, dialogs, custom menus. |
| `script.external_request` | Call `UrlFetchApp`. |
| `script.send_mail` | Call `MailApp.sendEmail`. Send only, no inbox access. |
| `gmail.modify` | Call `GmailApp.*`. Includes reading and modifying threads. |
| `calendar` | Full Calendar read/write. |
| `userinfo.email` | Read the active user's email. |
| `script.scriptapp` | Register and delete triggers (lesson 8). |

**Always prefer narrow scopes.** A bound script that only needs the active workbook should use `spreadsheets.currentonly`, never `spreadsheets`. Two reasons:

1. **The auth prompt looks less scary.** Users abandon scripts that ask for "Manage your spreadsheets in Drive" when "Manage just this spreadsheet" is what they actually do.
2. **Damage if the script is compromised is bounded.** A script with `drive` scope that gets hijacked can exfiltrate every file. A script with `drive.file` can only touch files it created.

On the first run, the user sees a consent screen listing every scope. They accept or refuse. Add a new service call later? Apps Script auto-expands the scope list, the next run prompts again. This is annoying for the user but it is how the permission contract stays explicit.

## Now do it for real

The bound project for this lesson has a `Lesson.gs` file with a `quotaSummary(perDay, perMinute)` stub. Two tasks:

1. Edit the body to return the template literal `` `${perDay} per day, ${perMinute} per minute` ``. Template literals are V8-only: that is the lesson hook.
2. In cell **A1**, call `=quotaSummary(20000, 300)`. The first number is UrlFetchApp's documented consumer-account daily quota; the second is the safe per-minute target the team designs nightly pulls around (Google does not publish a per-minute number, so the team treats ~300/min as the ceiling and uses `fetchAll` past that).

## Used in the wild

Real Apps Script projects in the team's workbooks:

- **`appsscript.json` carries 4-6 scopes maximum.** Anything more is either overscoping or doing too many things in one project: split into a script per concern.
- **`Utilities.sleep(100)` between every `UrlFetchApp.fetch`.** Belt and suspenders against the per-minute throttle.
- **A nightly summary mailer that is split into two functions.** One queries the workbook for the data; the other formats and sends. Quota for `MailApp.sendEmail` is checked at the start of the second function: if exhausted, log it to the Aggregator and skip mailing for the night.
- **A daily Drive cleanup that uses `DriveApp.searchFiles` once and processes the result in memory.** The naive version would call `getFileById` per row of a candidate-list sheet; the team's version reads all candidates in one query and joins them against the sheet in JavaScript. Saves about 200 round-trips per run.
- **`UrlFetchApp.fetchAll` for any pull that hits more than a handful of endpoints.** Lesson 11 covers the shape; the punchline is that fetchAll runs requests in parallel from one Apps Script call, which both saves quota and finishes 5x to 10x faster than a serial loop.

## Pro pitfalls

- **"My script ran yesterday but today it asks for permission again."** You added a new service call that needs a new scope. Apps Script auto-expanded the scope set; the next run re-prompts. The fix is either to declare scopes explicitly in the manifest (so additions are intentional) or to warn the team before each rollout that they will see one fresh prompt.
- **The 6-minute timeout that hides behind triggers.** A nightly trigger that succeeds for months on small data silently starts failing the day the data grows past the limit. Log the start time at the top of every long-running function and the end time at the bottom; when the gap creeps toward 5 minutes, you know to refactor.
- **`UrlFetchApp.fetch` returning the same response twice.** The cache for `muteHttpExceptions: false` calls is aggressive. Pass `muteHttpExceptions: true` and read the response code yourself, or append a cache-busting parameter to the URL.
- **A custom function consuming UrlFetchApp quota.** Lesson 3 covers caching from the cell side; here is the quota side. Every distinct argument tuple to `=fetchSomething(x, y)` is one call. A spreadsheet with 50,000 cells calling a `UrlFetchApp`-based custom function will saturate the daily quota in one open.
- **Multiple triggers racing on the same data.** Sunday-night trigger A re-runs because the previous run crashed; manual run B fires on Monday morning to backfill. Both write to the Aggregator simultaneously. Use `LockService.getScriptLock().tryLock(30 * 1000)` at the top of any trigger that mutates shared state.
- **Per-execution timeout interacting with `fetchAll`.** A `fetchAll` batch of 100 requests blocks on the slowest one. If one endpoint is having a bad minute, the whole batch waits. Split into per-service batches; that way one slow service does not block fast ones.
- **Rhino-style code accidentally pasted into a V8 project.** A teammate copies a 2014 Stack Overflow answer with `var` and `Array.prototype.forEach.call(...)`. Now that Rhino itself was retired Jan 31, 2026, those snippets still run under V8, but they get weird around `this` binding and get in the way of grep-able patterns the rest of the codebase uses. Standardize on `const`/`let`, arrow callbacks, and the modern array methods.
- **Auto-scope expansion as the silent breaker.** Adding `GmailApp.search` to a script previously authorized only for `spreadsheets.currentonly` does not throw; it expands the scope set and the next run shows a new auth prompt. The teammate who runs it before the rollout email arrives sees an unexplained re-prompt and gets nervous.
