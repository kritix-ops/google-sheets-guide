# Advanced lookups: two-way, dynamic, and beyond VLOOKUP

Lesson 1.4 covered `VLOOKUP`, `INDEX`/`MATCH`, and `XLOOKUP` for the ordinary "find this value in a table" case. This lesson goes after the messier real-world variants: two-way lookups (the cell at row X *and* column Y), dynamic column selection (the column changes based on a dropdown), approximate/range matching for tier classifications, and the patterns that survive when the lookup table arrives via `IMPORTRANGE`.

In adtech work these come up constantly. A pivot-style "buyers × verticals → revenue" report needs two-way lookup. A dashboard with a metric dropdown needs dynamic column selection. A buyer-tier classifier needs range matching. And almost everything sooner or later involves `IMPORTRANGE`. By the end of the lesson, you should be able to pick the right tool for each shape without falling back on copy-pasted Stack Overflow.

## Two-way lookups: INDEX(MATCH, MATCH)

A pivot has buyers down the rows and verticals across the columns. To find "Yoav Cohen's spend on Car Deals PR" you need to look up *both* the row (by buyer name) and the column (by vertical name) and return the cell at their intersection.

```
=INDEX($B$2:$F$10, MATCH("Yoav Cohen", $A$2:$A$10, 0), MATCH("Car Deals PR", $B$1:$F$1, 0))
```

Three pieces:

1. **Data array**: `$B$2:$F$10` (the body of the pivot, no headers).
2. **Row index**: `MATCH("Yoav Cohen", $A$2:$A$10, 0)` finds Yoav's row in the buyer column.
3. **Column index**: `MATCH("Car Deals PR", $B$1:$F$1, 0)` finds the vertical's column in the header row.

`INDEX` returns the cell at that intersection. The `0` in each `MATCH` means exact match (covered in lesson 1.4). This pattern is the workhorse of every pivot-vs-pivot comparison report the team builds.

## XLOOKUP-of-XLOOKUP: the modern two-way

`XLOOKUP` can return a whole row or column, not just a single cell. Compose two `XLOOKUP`s to get a two-way lookup that reads like English:

```
=XLOOKUP("Car Deals PR", $B$1:$F$1, XLOOKUP("Yoav Cohen", $A$2:$A$10, $B$2:$F$10))
```

The inner `XLOOKUP` finds Yoav's row and returns the entire row as an array. The outer `XLOOKUP` looks for "Car Deals PR" in the column headers and picks the value from that row.

Functionally identical to `INDEX/MATCH/MATCH`. Slightly more readable because each step is a "look up" rather than position math. The team mostly uses XLOOKUP-of-XLOOKUP in new sheets and keeps INDEX/MATCH/MATCH in legacy ones.

## Dynamic column selection: VLOOKUP + MATCH

A common adtech case: a dropdown lets the user pick which metric to show (Spend, Revenue, ROI). `VLOOKUP` needs a column index, but the index changes with the dropdown.

```
=VLOOKUP($A2, $A$2:$F$13, MATCH($G$1, $A$1:$F$1, 0), FALSE)
```

The third argument (`MATCH($G$1, ...)`) computes the column index dynamically. If `G1` says "Revenue", `MATCH` returns 6 and `VLOOKUP` returns the Revenue column. If `G1` changes to "Spend", `MATCH` returns 5 and `VLOOKUP` automatically returns Spend.

Without this trick, you would write `=IF(G1="Spend", VLOOKUP(...,5,...), IF(G1="Revenue", VLOOKUP(...,6,...), ...))`: a nested `IF` that grows every time a new column is added. With `MATCH`, one formula handles all metrics, including new ones added later.

## Approximate and range matching

`XLOOKUP` and `MATCH` support a fourth argument for match mode. The big use case in adtech is tier classification.

Define tier thresholds in a small table:

| Min Spend | Tier |
|---|---|
| 0 | T3 |
| 1000 | T2 |
| 5000 | T1 |
| 25000 | Whale |

To classify a buyer with `$3,400` rolling spend:

```
=XLOOKUP(3400, A2:A5, B2:B5, "n/a", -1)
```

The `-1` match mode is "exact match or next smaller item": finds `1000` and returns `T2`. With `1` it would find next larger; with `2` it does wildcard matching (a separate use case).

The same with `VLOOKUP` works if you pass `TRUE` (or omit) as the fourth argument **and** ensure the lookup column is sorted ascending. **`VLOOKUP` with `TRUE` requires sorted data; `XLOOKUP` with `-1` does not.** That is one reason `XLOOKUP` is now the default recommendation.

## Lookups against IMPORTRANGE

`IMPORTRANGE` returns a 2D range from another sheet. You can wrap it in any lookup:

```
=XLOOKUP(A2, IMPORTRANGE("...", "campaigns!B:B"), IMPORTRANGE("...", "campaigns!F:F"), "Not found")
```

Two `IMPORTRANGE`s on every recalc, each one a network round-trip. Bad for performance, and the two imports can technically return different snapshots if the source is being edited mid-recalc.

**Wrap them in a single `LET`** (lesson 1.20) so the import resolves once:

```
=LET(
  imported, IMPORTRANGE("...", "campaigns!A:F"),
  XLOOKUP(A2, INDEX(imported, , 2), INDEX(imported, , 6), "Not found")
)
```

One import, sliced into columns with `INDEX(imported, , 2)` and `INDEX(imported, , 6)`. Half the network calls and a consistent snapshot. This is the canonical pattern any time a sheet looks up against `IMPORTRANGE`'d data more than once.

## Used in the wild

- **Pivot drill-downs.** "Buyers × Verticals → revenue" pivots are everywhere; `INDEX/MATCH/MATCH` or `XLOOKUP-of-XLOOKUP` picks any cell from any pivot.
- **Dropdown-driven dashboards.** A single lookup formula whose return column is selected by a dropdown: change the dropdown, change the metric, no formula edits.
- **Tier classifications.** Spend → tier, ROI → verdict band, days-since-launch → cohort. Range-mode lookups against small threshold tables.
- **Cross-sheet "as-of" lookups.** `XLOOKUP` into a periods sheet to fetch the latest exchange rate, the latest budget, the latest goal. Often combined with sorting the periods sheet descending and using `1` for "first match" to get the most-recent value.
- **Two-way reconciliations.** Compare "what we tracked" vs "what the platform reported." Two pivots, `INDEX/MATCH/MATCH` on each, subtract.

## Pro pitfalls

- **Lock the lookup ranges with `$`.** `INDEX($B$2:$F$10, ...)` fills cleanly across rows and columns; `INDEX(B2:F10, ...)` shifts when you fill, breaking the lookup silently after the first row.
- **`MATCH` returns `#N/A` if not found.** Wrap in `IFNA(MATCH(...), "Unknown")` or `IFERROR` (lesson 1.9), and check that you actually want a fallback, not a silent failure.
- **`MATCH(value, range, 0)` is exact-match.** Forgetting the third argument defaults to `1` (approximate), which silently returns the wrong row when data is not sorted.
- **`VLOOKUP` requires the lookup column to be the first column of the range.** `XLOOKUP` and `INDEX/MATCH` have no such restriction. If you find yourself rearranging columns to make `VLOOKUP` work, switch to `XLOOKUP`.
- **`XLOOKUP`'s `if_not_found` is silent on type mismatches.** Looking up a number against a column of text-formatted numbers (`"0042"` vs `42`) returns the not-found sentinel instead of erroring. Coerce types upfront with `VALUE()` or `TEXT()`.
- **Wildcard matching (`MATCH(..., ..., 2)`) treats `*` and `?` as wildcards.** Surprising when your lookup value contains a literal `*` (a campaign code with an asterisk, say). Escape with `~*`.
- **Two-way lookups cannot easily handle "any row, any column."** If both axes can be fuzzy, `INDEX/MATCH/MATCH` gets ugly fast. At that point, consider a `QUERY` (lesson 1.12) or melting the pivot into a long table first.
- **`IMPORTRANGE` filled-down lookups burn IMPORTRANGE traffic.** Wrap with `LET` to compute the import once; hoist into a single helper cell if you need many lookups against the same source.
