# IMPORTRANGE and the IMPORT family

This is the lesson the team is going to want printed out and pinned to the wall. `IMPORTRANGE` is the most-used and most-broken formula in the workbooks: it pulls data from another spreadsheet, which is *the* foundation of every cross-team dashboard. When it works, it feels like magic. When it breaks, the whole reporting day stops.

Read this twice. Then read it again next time IMPORTRANGE breaks.

## The four IMPORT functions

| Function | Source | Use |
|---|---|---|
| `IMPORTRANGE` | Another Google Sheet | Cross-workbook data pull (95% of usage) |
| `IMPORTHTML` | HTML page (table or list) | Scraping public web tables |
| `IMPORTDATA` | URL serving CSV/TSV | Pulling exported data from a public URL |
| `IMPORTXML` | XML/HTML page with XPath | Targeted scraping with XPath selectors |

`IMPORTRANGE` dominates day-to-day adtech work. The other three show up occasionally for one-off analyses. We'll cover them briefly after the deep dive on IMPORTRANGE.

## IMPORTRANGE: the syntax

```
=IMPORTRANGE("spreadsheet_url_or_id", "sheet_name!range")
```

Two arguments, both strings:

<FunctionRef name="IMPORTRANGE" />

1. The full URL of the source spreadsheet (or just the file ID, the part between `/d/` and `/edit`).
2. The range, prefixed by the tab name and `!`. Example: `"Campaigns!A1:F100"` or `"Campaigns!A:F"` for the whole columns.

```
=IMPORTRANGE("https://docs.google.com/spreadsheets/d/1ABC.../edit", "Campaigns!A:F")
```

The result spills as a 2D array starting at the formula cell. With `A:F`, you get all rows in those columns from the source sheet.

## The auth flow (where it always breaks)

The first time you use IMPORTRANGE pointing at a new source, the formula returns `#REF!` with the message **"You need to connect these sheets."** You click the cell, click **Allow access**, and Sheets establishes a one-way trust relationship from the source to the destination.

**Critical details about the auth:**

- The trust is **per source sheet → destination sheet pair**. Connecting from "dashboard" to "raw data" doesn't auto-connect from "dashboard" to a *different* "raw data" sheet.
- Only someone with **edit access** to both sheets can authorize the connection. If your team's permissions are split, the dashboard owner who lacks edit on the source can't approve.
- Once connected, **any user with view access to the destination** can see the imported data, even if they don't have access to the source. This is the load-bearing detail to remember when handling sensitive data: importing leaks downstream.
- Removing access from the source doesn't break the formula immediately: Sheets caches; the break shows up when the cache expires or someone hits "refresh."

## The performance reality

`IMPORTRANGE` is **slow**. Every cell that uses IMPORTRANGE makes a network round-trip on first load and on cache invalidation. A dashboard with 50 IMPORTRANGE formulas takes seconds (or tens of seconds) to load on a cold start.

**Patterns that don't scale:**

- One IMPORTRANGE per cell, dragged across a column. Each cell makes its own request.
- IMPORTRANGE inside a MAP or BYROW: fires N times.
- IMPORTRANGE inside a volatile function (like INDIRECT): refires on every recalc.

**Patterns that do scale:**

- **One IMPORTRANGE per source per dashboard.** Pull all the columns you need, in one call, into one block. Reference *that block* from downstream formulas.
- **Wrap with QUERY to filter at the source.** `=QUERY(IMPORTRANGE(...), "SELECT Col2, Col5 WHERE Col2 = 'Yoav'", 1)` is faster than importing everything and filtering downstream because Sheets only spills the filtered result.
- **Wrap with LET** (lesson 20) so the import is computed once even when used multiple times in the same formula:

```
=LET(
  data, IMPORTRANGE("...url...", "Campaigns!A:F"),
  total, SUM(INDEX(data, , 5)),
  count, ROWS(data) - 1,
  total / count
)
```

The `data` is the IMPORTRANGE; `total` and `count` both reference it. Without LET, you'd run the IMPORTRANGE twice.

## The cache and refresh

IMPORTRANGE caches results to avoid re-fetching constantly. The cache invalidates on:

- A change in the source data (Sheets watches and pushes updates, usually within a minute).
- A workbook open after the cache expires (TTL is variable, often around an hour).
- Manual refresh: there's no UI button; the workaround is to delete the formula and retype it.

**To force-refresh:** make a no-op edit to the source (type a value, undo): Sheets re-pushes to all subscribers. Or in the destination, edit and revert the IMPORTRANGE formula.

The team's "the dashboard is wrong" tickets are 80% stale-cache issues. Build a habit of force-refreshing before quoting numbers in a meeting.

## Defensive patterns

```
=IFERROR(
  IMPORTRANGE("https://...", "Campaigns!A:F"),
  "Source unavailable - check connection"
)
```

Wrap every load-bearing IMPORTRANGE in IFERROR (lesson 9). The fallback message tells the next person what's wrong, instead of showing a bare `#REF!`.

```
=LET(
  data, IFERROR(IMPORTRANGE("...", "Campaigns!A:F"), {""}),
  IF(ROWS(data) < 2, "No data: check source", QUERY(data, "SELECT ...", 1))
)
```

Belt-and-suspenders: catch the import error, then check the result is non-empty before running QUERY. This is the pattern for dashboards that get screen-shared to leadership: never show `#REF!` to a CEO.

## IMPORTHTML, IMPORTDATA, IMPORTXML

Used less often, but worth knowing.

**IMPORTHTML** scrapes a numbered table or list from a public HTML page:

```
=IMPORTHTML("https://en.wikipedia.org/wiki/...", "table", 2)
```

Pulls the 2nd table from that Wikipedia page. The third argument is the index (1-based).

**IMPORTDATA** pulls a CSV or TSV from a URL:

```
=IMPORTDATA("https://example.com/data.csv")
```

Useful when a partner publishes daily data as a CSV at a stable URL.

**IMPORTXML** does targeted scraping with XPath:

```
=IMPORTXML("https://example.com", "//div[@class='price']")
```

XPath is verbose but powerful when you need a single element rather than a whole table.

All three of these only work on **public** URLs (no auth). For private data sources, you'd use Apps Script with `UrlFetchApp` instead.

## Used in the wild

- **One source-of-truth campaign log per market.** Each region's team owns one workbook; every dashboard pulls via IMPORTRANGE wrapped in QUERY to filter to the metrics that dashboard needs.
- **Cross-account billing dashboard.** IMPORTRANGE from each platform's exported sheet, UNION via curly brace stacking, normalize column names, present in one view.
- **Daily exchange-rate sheet.** IMPORTDATA from a free FX API endpoint that returns CSV; cells reference it for currency normalization.
- **Competitor pricing tracker.** IMPORTHTML against a public competitor pricing page; spotty (HTML changes break it), but useful when it works.
- **Status pages.** IMPORTXML with XPath against a partner's public status page; a tiny `=IF(IMPORTXML(...) = "operational", "OK", "DOWN")` cell on the team dashboard.

## Pro pitfalls

- **`#REF!` after working fine for weeks** usually means the source's tab was renamed, columns shifted, or someone revoked access. First check is "did the source sheet change?"
- **`#N/A` instead of `#REF!`** can mean the connection auth was revoked. Re-establish via the cell's "Allow access" prompt.
- **Importing huge ranges (`A:Z`) on every formula** brings the dashboard to a crawl. Always import the smallest range you need; better, wrap in QUERY to filter at the source.
- **IMPORTRANGE columns are positional, not named.** When you reference imported data via `INDEX(imported, , 3)`, you're saying "column 3 of what I imported": if the source adds a column at position 2, your INDEX 3 now points to a different field. Use named columns by importing column headers and looking up positions with MATCH.
- **IMPORTRANGE-of-IMPORTRANGE is allowed but doubles the latency.** If you need a chain (sheet A → sheet B → sheet C), each hop pays the round-trip cost. Restructure when possible.
- **Sharing a dashboard widely** with IMPORTRANGE means the source data is implicitly accessible to everyone with view access on the dashboard, even those who don't have access to the source. Audit before sharing externally.
- **`IMPORTRANGE` doesn't preserve cell formatting**: colors, number formats, conditional formatting are all stripped. Format the destination separately or apply conditional formatting on the imported range.
- **Recursive cycles cause a `#REF!` error.** If sheet A imports from sheet B and sheet B imports from sheet A, both break. Sheets detects the cycle and refuses both.
