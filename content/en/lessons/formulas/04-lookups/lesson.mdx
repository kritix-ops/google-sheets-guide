# Lookups: VLOOKUP, HLOOKUP, INDEX/MATCH, XLOOKUP

Sheets has four ways to look up a value in a table. They all do roughly the same job. Three have inherited limitations from the 1980s. One is the modern winner. This lesson tells you which one to reach for and why, using the most common adtech case: matching campaign rows against a separate metadata table.

The setup: every campaign has a **vertical** (the topic, like "Car Deals PR"). A separate **Verticals** table holds the category and average CPC for each vertical. To enrich the campaign log with category info, you need a lookup.

## VLOOKUP: the legacy default

`VLOOKUP` scans the **first column** of a range, finds the first match, and returns a value from another column in the same row. It's the lookup function nearly everyone learns first: spreadsheets shipped with it for decades, and most workbooks the team inherits still rely on it. Knowing how it works is half about using it and half about reading what it did when something breaks.

The four arguments are `search_key`, `range`, `index`, `[is_sorted]`. The `is_sorted` flag should almost always be `FALSE` for an exact match; the default `TRUE` silently assumes a sorted first column and is the source of the classic "wrong row returned" bug we'll see below.

The biggest VLOOKUP trap: it can **only** read columns to the right of the lookup column. If your lookup column is to the right of the column you want to return, VLOOKUP can't help. Real adtech case: the verticals sheet has columns Vertical, Category, Avg CPC. To find which vertical has a given Avg CPC, VLOOKUP can't do it because Avg CPC is to the right of Vertical.

## HLOOKUP: VLOOKUP rotated 90 degrees

`HLOOKUP` scans the **first row** of a range and returns a value from another row in the same column. Same argument layout as VLOOKUP, but oriented horizontally. You'll rarely need it because tables are almost always vertical. The one place it shows up in adtech: quarterly summary boards where months sit across columns and you want to look up a metric by month name. Even there, `INDEX/MATCH` or `XLOOKUP` (with the transposed data shape) usually wins.

## INDEX/MATCH: the flexible classic

The INDEX/MATCH combo splits the lookup into two functions. `MATCH(search_key, range)` returns the **position** of the match. `INDEX(range, position)` returns the value at that position. Combine them and you have a lookup that doesn't care about column order. For a decade this was the "right" answer in serious workbooks, because unlike VLOOKUP it survives column inserts and works left-to-right or right-to-left.

The price is verbosity: two function calls where XLOOKUP needs one. Modern Sheets workbooks default to XLOOKUP for new formulas; INDEX/MATCH still shows up where legacy compatibility matters or in formulas you're maintaining rather than rewriting.

## XLOOKUP: the modern winner

`XLOOKUP` shipped to Sheets in 2022 and is now the default lookup function for every new workbook the team starts. One function, no column-index quirks, works in any direction, and has a built-in not-found branch. The full spec lives in lesson 2 where we first met it; the focus here is how it slots into the lookup family and beats the others on every axis that matters for production sheets.

## When each one wins

| Situation | Reach for |
|---|---|
| New formula in a new sheet | **XLOOKUP** |
| Lookup column is to the right of the return column | XLOOKUP or INDEX/MATCH |
| Sheet shared with people on Excel 2019 or older | INDEX/MATCH (XLOOKUP shipped to Excel in 2020) |
| Maintaining old formulas | Whatever's there. Don't rewrite VLOOKUP into XLOOKUP unless something else is changing |
| Quick disposable lookup | XLOOKUP |
| Horizontal table | HLOOKUP, or transpose the data first |

## Used in the wild

In the team's actual workbooks, lookups appear constantly: and they're constantly breaking. The patterns:

- **Vertical → category enrichment.** Every campaign sheet has an XLOOKUP column joining to a central Verticals tab via IMPORTRANGE.
- **Buyer → team enrichment.** Same shape: XLOOKUP from the campaign log into a Buyers reference table.
- **Lookup the current period.** A single named cell holding "current_period" (e.g., "2026-05") is XLOOKUP'd from a Periods table to get start/end dates that filter every dashboard.

## Pro pitfalls

- **VLOOKUP's column-index argument is brittle.** If someone inserts a column inside your lookup range, the column number now points at different data: and your formula returns wrong values without erroring. XLOOKUP avoids this by referencing return columns by range, not by number.
- **INDIRECT/IMPORTRANGE'd lookup tables can return text instead of numbers.** If a CPC comes back as "1.42" (string) instead of 1.42 (number), XLOOKUP comparison still works for exact match but math on the result breaks. Coerce with `VALUE()` or `*1`.
- **IMPORTRANGE permission revoked.** When the source workbook owner revokes editor access on the destination workbook, every IMPORTRANGE-fed lookup returns `#REF!`. The fix is to re-grant permission, but the symptom (cascade of #REF! across many formulas) looks scary. Track 4 covers diagnosing this.
- **Trailing whitespace or case differences in the lookup key cause silent #N/A.** Wrap both sides in `TRIM(LOWER(...))` if your data is from disparate sources.
