# FILTER, SORT, UNIQUE

QUERY is powerful but its SQL-style syntax is heavy for simple operations. `FILTER`, `SORT`, and `UNIQUE` are direct, expressive shortcuts for the everyday "give me just these rows", "sort this", "deduplicate this column" needs. All three are array-aware on their own: no `ARRAYFORMULA` wrapper needed.

## FILTER: keep rows that match a condition

`FILTER(range, condition1, [condition2, ...])` returns the rows of `range` where every condition is `TRUE`. Conditions are arrays the same length as the range.

```
=FILTER(A2:F13, B2:B13 = "Yoav Cohen")
```

This returns every column for every row where the buyer is Yoav. Combine multiple conditions with comma (which is AND-style):

```
=FILTER(A2:F13, B2:B13 = "Yoav Cohen", F2:F13 > 400)
```

For OR logic, use `+` between boolean arrays: `FILTER(A2:F13, (B2:B13 = "Yoav") + (B2:B13 = "Sarah"))`.

## SORT: sort by one or more columns

`SORT(range, sort_column, ascending, [sort_column2, ascending2, ...])` returns the range sorted. The sort_column is a column **number within the range**, 1-indexed.

```
=SORT(A2:F13, 6, FALSE)
```

Sorts by column 6 (Revenue), descending. To sort by multiple columns, add more pairs.

## UNIQUE: dedupe a column or rows

`UNIQUE(range)` returns the distinct values. On a single column, you get the unique values. On multiple columns, you get the unique row combinations.

```
=UNIQUE(C2:C13)
```

Returns the unique vertical names. Combined with COUNTIF or SORT for ranked unique lists.

## When to choose which

| Need | Reach for |
|---|---|
| Filter rows by condition, no projection | `FILTER` |
| Filter rows AND project specific columns | `QUERY` |
| Sort by one or two columns | `SORT` |
| Sort with SQL expressions (computed sort) | `QUERY ... ORDER BY` |
| Dedupe a column or row combinations | `UNIQUE` |
| Distinct values WITH counts | `QUERY ... GROUP BY ... COUNT(...)` |

`FILTER`, `SORT`, `UNIQUE` win on conciseness and read-time clarity. QUERY wins when you need projection, aggregation, multi-condition logic that gets ugly in FILTER, or when you want one expression instead of nested calls.

## Used in the wild

- **Live filtered views per buyer.** A dropdown cell holding a buyer name; FILTER pulls just that buyer's campaigns. Change the dropdown, the view updates.
- **Top-N lists.** SORT + array-trim: `=ARRAY_CONSTRAIN(SORT(A2:F13, 6, FALSE), 5, 6)` for top 5.
- **Dedup'd vertical or buyer dropdowns.** A UNIQUE on the source column drives a Data Validation dropdown elsewhere.
- **Spend-by-vertical for new verticals.** UNIQUE the vertical column, SUMIFS each unique value, and you've got a per-vertical revenue table that auto-updates.

## Pro pitfalls

- **FILTER returns `#N/A` when no rows match.** Wrap in IFERROR/IFNA with a fallback for empty-result safety.
- **SORT's column index is within the range.** Pass `SORT(B2:F13, 5, FALSE)` and the "5" means the 5th column of B:F: that's column F. Easy to count wrong.
- **UNIQUE preserves whitespace and case.** "Yoav " (trailing space) and "Yoav" are two distinct entries. TRIM/LOWER first.
- **All three lock surrounding cells.** Spilled output errors with `#REF!` if anything is in the way.
- **FILTER with multi-column ranges and complex conditions can be slow.** Beyond a few thousand rows, QUERY tends to be faster.
