# FILTER, SORT, UNIQUE

QUERY (lesson 1.12) is powerful, but its SQL-style syntax is heavy for everyday work. `FILTER`, `SORT`, and `UNIQUE` are the direct, expressive shortcuts for the three things you reach for constantly: "give me only these rows," "sort this," "show me each value once." Reading them out loud reads like English. The result is the most common adtech-dashboard idiom on the team.

All three are array-aware on their own (no `ARRAYFORMULA` wrapper needed) and spill into the cells below from a single formula. They compose cleanly with each other and with `SUM`, `SUMIFS`, `COUNTA`, and the rest of the aggregation family from lesson 1.6.

## FILTER: keep rows that match a condition

`FILTER(range, condition1, [condition2, ...])` returns the rows of `range` where every condition is `TRUE`. Each condition is a boolean array the same length as the range's row count. Multiple conditions are combined AND-style.

Use `*` between boolean arrays to force AND when you would otherwise express the logic with `+` or operators. Use `+` for OR. The arithmetic-on-booleans trick is how Sheets lets you build complex boolean conditions inline.

<FunctionRef name="FILTER" />

### Worked example 1: toy data

Four products with sales numbers. We want only the rows where sales beat 50. One formula in `D2`, the result spills down column D.

<RefDemo
  data={[
    ["Product", "Sales"],
    ["A", 100],
    ["B", 80],
    ["C", 60],
    ["D", 30],
  ]}
  formula="=FILTER(A2:A5, B2:B5 > 50)"
  formulaCell="D2"

### Combined example: FILTER + SUM for a buyer's total revenue

Wrap the spilled FILTER output in an aggregator and you get "Yoav's total revenue this period" in a single cell. The same trick lets you replace a `SUMIFS` when you find the criteria range easier to read as a FILTER condition.

```
=SUM(FILTER(F2:F13, B2:B13 = "Yoav Cohen"))
```

The inner `FILTER` returns just Yoav's revenue column (a 3-cell array). `SUM` adds them. Compare to `SUMIFS(F2:F13, B2:B13, "Yoav Cohen")` from lesson 1.6: same result, different readability. Use whichever matches how your brain frames the question. The FILTER form generalizes to AVERAGE, MAX, COUNTA, and friends with no rewrite.

<TryIt
  data={CAMPAIGNS}
  inputCell="H1"
  expectedFormula='=SUM(FILTER(F2:F13,B2:B13="Yoav Cohen"))'
  task={<>Compute the total revenue for Yoav Cohen's campaigns. Combine <code>FILTER</code> on the revenue column with <code>SUM</code>.</>}
  hint={<>FILTER the revenue column (F2:F13) by the buyer condition. Wrap the whole thing in SUM.</>}
  answer={<>The composition is <code>SUM(FILTER(F2:F13, B2:B13 = "Yoav Cohen"))</code>. FILTER returns Yoav's three revenue values; SUM adds them. The same shape works for AVERAGE, MAX, MIN, COUNTA: change the outer function, keep the inner FILTER. This is the most common alternative to SUMIFS on the team, and it composes more naturally when the condition gets complex.</>}

## SORT: sort by one or more columns

`SORT(range, sort_column, ascending, [sort_column2, ascending2, ...])` returns the range sorted. The sort column is a **column number within the range**, 1-indexed, not the sheet letter. This is the single biggest stumble; people pass `"F"` or `6` for the sheet's column F and forget that if the range starts at `B`, the index of `F` is `5`, not `6`.

For multi-key sorts, add more `column, ascending` pairs. The first pair is primary, the second is the tie-breaker, and so on.

<FunctionRef name="SORT" />

### Worked example 1: toy data

Three items, prices unsorted. `SORT` on the price column returns the values in ascending order.

## UNIQUE: dedupe a column or rows

`UNIQUE(range)` returns the distinct values. On one column, you get the distinct values. On multiple columns, you get the distinct row combinations.

UNIQUE is exact: it treats `"Yoav"`, `"Yoav "` (trailing space), and `"yoav"` as three different values. On dirty data, run `TRIM` and `LOWER` first (lesson 1.7 covers both) so UNIQUE collapses what you actually mean.

### Worked example 1: toy data

Five color rows with duplicates. UNIQUE collapses them to three distinct values, in the order of first appearance.

## When to choose which

| Need | Reach for |
|---|---|
| Filter rows by condition, no projection | `FILTER` |
| Filter AND project specific columns | `QUERY` |
| Sort by one or two columns | `SORT` |
| Sort with computed keys or SQL expressions | `QUERY ... ORDER BY` |
| Dedupe a column or row combinations | `UNIQUE` |
| Distinct values with their counts | `QUERY ... GROUP BY ... COUNT(...)` |

`FILTER`, `SORT`, `UNIQUE` win on conciseness and read-time clarity. `QUERY` wins when you need projection, aggregation, multi-condition logic that gets ugly in FILTER, or when you want a single expression instead of nested calls.

## Used in the wild

- **Live filtered views per buyer.** A dropdown cell holds a buyer name; `FILTER(A2:F, B2:B = dropdown_cell)` pulls just that buyer's campaigns. Change the dropdown, the view updates instantly.
- **Top-N leaderboards.** `=ARRAY_CONSTRAIN(SORT(A2:F, 6, FALSE), 5, 6)` returns the top 5 rows by revenue. The team rebuilds this pattern on every new campaign sheet.
- **Dropdown sources.** `UNIQUE(ARRAYFORMULA(TRIM(C2:C)))` on the vertical column feeds a Data Validation dropdown that auto-extends as new verticals appear.
- **Per-vertical revenue tables.** Use `UNIQUE` on the vertical column to drive the row labels, then `SUMIFS` against each vertical to build a revenue summary that needs zero maintenance.
- **Composed views.** `=SORT(FILTER(A2:F, B2:B = "Yoav"), 6, FALSE)` gives Yoav's campaigns sorted by revenue. Two functions, one cell, one line of intent.

## Pro pitfalls

- **`FILTER` returns `#N/A` when no rows match.** Wrap any user-facing FILTER in `IFERROR` or `IFNA` with a fallback. The team has shipped broken dashboards over this twice.
- **`FILTER`'s condition has to be the same length as the range.** Mix `A2:F13` with `B2:B` and you get a size-mismatch error. Either close both ranges or open both.
- **`SORT`'s column index is positional within the range, not the sheet.** `SORT(B2:F13, 6, FALSE)` errors because `B:F` has 5 columns, not 6. Count columns starting from the range's leftmost.
- **`UNIQUE` is case- and whitespace-sensitive.** Normalize with `TRIM` and `LOWER` (lesson 1.7) before deduping anything that came from human input.
- **All three spill, and anything in the destination errors them out.** `#REF!` with a spill-conflict message if a cell in the result range has a value. Clear the destination before placing the formula.
- **`FILTER` on tens of thousands of rows can be slower than `QUERY`.** If you find yourself adding more than two or three conditions, switching to a single `QUERY` is usually the right move.
- **`FILTER` over `IMPORTRANGE` inherits all of IMPORTRANGE's quirks.** Permission revoke, source rename, or row-count change in the source can break the filter silently. Lesson 1.27 covers the patterns.
