# REGEX in depth: REGEXMATCH, REGEXEXTRACT, REGEXREPLACE

When `LEFT`/`MID`/`SUBSTITUTE` (lesson 1.7) are not expressive enough, regex is what you reach for. Patterns instead of literal positions. Validation across variable text. Extraction from strings that do not have a fixed structural delimiter. The three Sheets regex functions cover the canonical three uses: match (does this fit a shape?), extract (pull a piece), and replace (rewrite parts).

Sheets uses Google's **RE2** engine. It is fast, safe (no catastrophic backtracking), and on most inputs produces results in linear time. The trade-off is that RE2 deliberately omits some PCRE features: **no lookaheads, no lookbehinds, no backreferences inside the pattern**, no recursive patterns. Almost everything else you know from JavaScript or Python regex carries over. In adtech, RE2 is more than enough for validating campaign codes, extracting platform names, normalizing the buyer/vertical text columns, and writing reliable text filters against `QUERY` results.

## The three functions

| Function | Purpose | Returns |
|---|---|---|
| `REGEXMATCH(text, pattern)` | Test whether the pattern matches | TRUE / FALSE |
| `REGEXEXTRACT(text, pattern)` | Extract the first match | The matched substring (or first capture group) |
| `REGEXREPLACE(text, pattern, replacement)` | Replace all matches | New string |

All three patterns are RE2 strings, written inside the formula as quoted JavaScript strings. **Backslashes need to be doubled**: `\\d` in the formula means `\d` (digit) in the regex, because Sheets' string parser eats the first backslash. This is the single most common stumble in the whole regex story.

## REGEXMATCH: validation

`REGEXMATCH` is the workhorse for "does this cell look right?" Returns `TRUE` or `FALSE`. Pair with conditional formatting (covered in Track 2) to highlight rows that fail the team's naming convention. Pair with `FILTER` (lesson 1.14) to pull only the rows that pass.

The single most important habit: **always anchor your validation patterns** with `^` at the start and `$` at the end. Without anchors, `REGEXMATCH` returns TRUE if the pattern matches *anywhere* in the cell, which is almost never what a validator wants.

### Worked example 2: real adtech data

Validate that a campaign code matches the team's `Platform_VerticalPR_Audience_YYYY-MM` shape. Anything that fails is either a typo or a non-conforming campaign that needs renaming.

  answer={<>Anchors are critical. <code>^</code> matches start, <code>$</code> matches end. ### Combined example: REGEXMATCH + FILTER

The validator pattern at scale. Filter the campaign log down to *only* rows whose code matches the team's convention. Anything that fails the regex gets surfaced for cleanup.

```
=FILTER(A2:F, REGEXMATCH(A2:A, "^[A-Za-z]+_[A-Za-z]+PR_[A-Za-z]+_\\d{4}-\\d{2}$"))
```

`REGEXMATCH` broadcasts cleanly inside `FILTER` because Sheets evaluates it against each row of the condition range. No `ARRAYFORMULA` wrapper needed (FILTER is already array-aware, lesson 1.14).

## REGEXEXTRACT: pull a piece

`REGEXEXTRACT` returns either the entire match or the first capture group if the pattern contains parentheses. The capture-group form is what you almost always want: it lets you say "match this structural shape, but give me back just *this* piece of it."

The single biggest convention to internalize: **use a capture group around exactly the part you want to extract, and let the rest of the pattern handle the structural anchoring.**

<FunctionRef name="REGEXEXTRACT" />

### Worked example 1: toy data

Pull the four-digit year out of an arbitrary string. The pattern says "find four digits in a row," capture them, return them.

<RefDemo
  data={[
    ["Filename", "Year"],
    ["report_2024_q4_final.pdf", ""],
    ["draft_2025_v3.docx", ""],
    ["archive_2026_05.zip", ""],
  ]}
  formula='=REGEXEXTRACT(A2, "(\\d{4})")'
  formulaCell="B2"
  fillTo="B4"
  expectedFills={['=REGEXEXTRACT(A2, "(\\d{4})")', "", ""]}
  caption="The capture group (\\d{4}) pulls out the first run of four consecutive digits in each filename. Row 1 → 2024, row 2 → 2025, row 3 → 2026."
/>

### Worked example 2: real adtech data

Extract the platform name from a campaign code. The platform is whatever comes before the first underscore.

<TryIt
  data={[
    ["Code", "Platform"],
    ["Taboola_CarDealsPR_DesktopUS_2026-05", ""],
  ]}
  inputCell="B2"
  expectedFormula='=REGEXEXTRACT(A2,"^([A-Za-z]+)_")'
  task={<>Extract just the platform name (the part before the first underscore) from the campaign code in <code>A2</code>. The result should be <code>Taboola</code>.</>}
  hint={<>Use a capture group <code>(...)</code> around what you want to extract. Anchor with <code>^</code> and follow with the literal underscore.</>}
  answer={<>The capture group <code>(...)</code> tells REGEXEXTRACT what to return. <code>^([A-Za-z]+)_</code> captures one or more letters at the start, requiring an underscore right after. The underscore is matched but not captured. Anchoring on the structural delimiter is safer than relying purely on the character class: it pins the extraction to "the segment before the first underscore" rather than "any run of letters."</>}
/>

### Combined example: REGEXEXTRACT + ARRAYFORMULA over a column

The pattern that replaces hand-typed parsing columns. Extract the platform from every row of the campaign-code column at once.

```
=ARRAYFORMULA(IFERROR(REGEXEXTRACT(A2:A, "^([A-Za-z]+)_"), ""))
```

`REGEXEXTRACT` broadcasts inside `ARRAYFORMULA` (unlike `INDEX(SPLIT(...))` from lesson 1.15, which does not broadcast cleanly). The `IFERROR` guard returns `""` for empty rows so the spilled output stops at the last real row instead of filling the sheet with `#N/A`. This is the canonical "extract one piece into its own column" pattern for any growing log.

### Easy traps: REGEXEXTRACT

## REGEXREPLACE: substitute with a pattern

`REGEXREPLACE` replaces every match in the input with a replacement string. The replacement can reference captured groups with `$1`, `$2`, etc., which lets you restructure text in one formula: strip, reorder, normalize.

It is the cleanest way to strip a known suffix, normalize separators across a messy import, or rewrite a structural pattern into a different shape. For simple literal substitutions, `SUBSTITUTE` (lesson 1.7) is lighter and faster; reach for `REGEXREPLACE` only when the pattern is variable.

<FunctionRef name="REGEXREPLACE" />

### Worked example 1: toy data

Strip a trailing version suffix from a filename. The pattern matches `_v` followed by digits at end-of-string.

<RefDemo
  data={[
    ["Filename", "Cleaned"],
    ["report_v3", ""],
    ["draft_v12", ""],
    ["final_v1", ""],
  ]}
  formula='=REGEXREPLACE(A2, "_v\\d+$", "")'
  formulaCell="B2"
  fillTo="B4"
  expectedFills={['=REGEXREPLACE(A2, "_v\\d+$", "")', "", ""]}
  caption="The pattern _v\\d+$ matches '_v' plus one-or-more digits at the end. Replacing with empty string removes the version suffix. Result: report, draft, final."
/>

### Worked example 2: real adtech data

The team's de-versioning workflow. Strip the trailing `_YYYY-MM` from a campaign code so you can group multiple months of the same campaign under one rolled-up ID.

<TryIt
  data={[
    ["Code", "Without date"],
    ["Taboola_CarDealsPR_DesktopUS_2026-05", ""],
  ]}
  inputCell="B2"
  expectedFormula='=REGEXREPLACE(A2,"_\\d{4}-\\d{2}$","")'
  task={<>Strip the trailing "_YYYY-MM" date from the campaign code in <code>A2</code>. The result should be <code>Taboola_CarDealsPR_DesktopUS</code>.</>}
  hint={<>Pattern: an underscore, four digits, a dash, two digits, end-of-string. Replace with the empty string.</>}
  answer={<>The <code>$</code> anchor at the end ensures we only match the trailing date, not a date in the middle of the string. Without it, REGEXREPLACE would also strip dates from any "_YYYY-MM" sequence earlier in the string. <code>\\d{`{4}`}</code> is exactly 4 digits; <code>\\d{`{2}`}</code> exactly 2. The replacement is the empty string, so the matched substring is removed entirely.</>}
/>

### Combined example: REGEXREPLACE for the " PR" suffix normalization

The team's verticals all end in " PR" by convention (Car Deals PR, Cruises PR, Reverse Mortgage PR). When a downstream report wants the bare vertical name without the suffix, `REGEXREPLACE` is more robust than `LEFT(text, LEN(text)-3)` because it gracefully no-ops on rows that already lost the suffix.

```
=ARRAYFORMULA(IFERROR(REGEXREPLACE(C2:C, " PR$", ""), ""))
```

`" PR$"` matches the literal " PR" only at end-of-string. Rows without the suffix pass through unchanged. The `ARRAYFORMULA` + `IFERROR` envelope mirrors the open-ended-range pattern from lesson 1.10.

## RE2 limitations

Sheets uses Google's RE2 engine, which is fast and safe but deliberately lacks some PCRE features:

- **No lookahead or lookbehind.** `(?=...)`, `(?<=...)`, `(?!...)`, `(?<!...)` are all unsupported. Most lookaround use cases can be rewritten with capture groups and selective extraction.
- **No backreferences inside the pattern.** `\\1` referring to capture group 1 inside the pattern does not work. You *can* use `$1` in the `REGEXREPLACE` *replacement* string; that is a different mechanism and it does work.
- **No recursive patterns.** No subroutines, no balanced-bracket parsing.
- **Case-insensitive flag is inline.** `(?i)pattern` makes the whole pattern case-insensitive. Use it whenever the input might mix cases.

For typical adtech work (validation, extraction, normalization), RE2 is more than enough. The few cases where you genuinely need PCRE features usually have a workaround using multiple captures or a follow-up formula.

## Used in the wild

- **Validate campaign codes match the team's naming convention.** `REGEXMATCH` in a helper column, conditional formatting (Track 2) flags any row that fails.
- **Extract dates from messy filename or campaign-name columns.** `REGEXEXTRACT` for "find the YYYY-MM-DD inside this string" when the position is not fixed.
- **Normalize separators.** `REGEXREPLACE` swaps spaces/dashes/underscores into one canonical form before joining sheets across imports.
- **Strip the " PR" suffix from verticals.** More robust than `LEFT(text, LEN(text)-3)` because it gracefully no-ops on rows that already lost the suffix.
- **Find phone numbers, emails, URLs.** Standard regex patterns inside long text fields like raw ad copy or descriptions.
- **Filtered text queries.** `=QUERY(A2:F, "SELECT * WHERE A MATCHES '...'")` uses the same regex engine inside QUERY's WHERE clause (lesson 1.13).

## Pro pitfalls

- **Backslash escaping is doubled.** `\\d` in the formula text means `\d` in the regex. One backslash gets eaten by Sheets' string parser. Forget this and validators silently match the wrong things.
- **`REGEXEXTRACT` with no match returns `#N/A`.** Wrap in `IFNA` or `IFERROR` for any user-facing cell.
- **Anchors are mandatory for validators.** `^pattern$` matches the whole cell; `pattern` alone matches *anywhere* inside the cell, which lets garbage pass.
- **Greedy quantifiers silently extract the wrong piece.** `.+` grabs as much as it can; in nested-delimiter patterns the captured segment ends up being the last possible chunk. Use negated character classes (`[^_]+`) or anchor on structural delimiters.
- **`REGEXMATCH` on numeric cells coerces to text first.** The number `2026` becomes the string `"2026"` before matching: usually fine, occasionally surprising.
- **Special characters in `REGEXREPLACE` replacements.** `$` is special (backreference); for a literal `$`, use `$$`. Same caution for `\\` in the replacement.
- **Patterns are case-sensitive by default.** `"PR"` does not match `"pr"`. Use the inline `(?i)` flag when human input varies in case.
- **RE2 has no lookarounds.** If a Stack Overflow answer uses `(?=...)` or `(?<=...)`, it will not work in Sheets. Rewrite with capture groups.
