# Named functions: build your team's vocabulary

A **named function** is a `LAMBDA` (lesson 1.18) saved to the workbook with a name, a description, and parameter docs. Once defined, anyone using the spreadsheet can call it like a built-in: `=ROI(E2, F2)` instead of an inline `(F2-E2)/E2`, `=BUYER_TIER(buyer)` instead of three nested `IF`s, `=NORMALIZE_PLATFORM(raw)` instead of a chain of `SUBSTITUTE` calls. The function definition lives in one place; every formula that uses it stays consistent.

For a team that runs many dashboards over the same data, this is the single highest-leverage move in the whole formulas track. You stop copy-pasting hairy expressions across tabs. You stop hunting "where did we define the fee adjustment?" when the rate changes. You stop fixing the same bug in seventeen places when a metric definition shifts. The team's vocabulary moves from tribal knowledge in people's heads into actual callable functions in the workbook.

## What you need before this lesson

The body of every named function is a `LAMBDA`. Lesson 1.18 covers `LAMBDA` syntax in depth; lesson 1.19 covers the `MAP`/`REDUCE`/`SCAN`/`BYROW`/`BYCOL` family that often gets composed with named functions. If you have not done those, this lesson will read as syntax soup; do them first.

## Creating a named function

The workflow:

1. **Data → Named functions.** Opens the side panel.
2. Click **Add new function**.
3. Fill in:
   - **Name**: uppercase, no spaces. Convention: `ROI`, `EFFECTIVE_CPC`, `BUYER_TIER`.
   - **Description**: what the function does. Shows up in autocomplete and the function helper.
   - **Argument placeholders**: one row per parameter, with a name and description.
   - **Formula definition**: the body, written exactly like a `LAMBDA` body but referring to parameter names directly (no `LAMBDA(...)` wrapper).
4. Click **Next → Create**.

The function is now available in the workbook. Type `=ROI(` and Sheets autocompletes it like any built-in.

### Worked example 1: defining `ROI`

Argument placeholders: `spend`, `revenue`. Formula definition: `(revenue - spend) / spend`. That is the whole function.

## Recursion

Named functions can call themselves by name. The classic example is a factorial:

```
FACT(n) = IF(n <= 1, 1, n * FACT(n - 1))
```

In adtech, recursion is rare but useful for hierarchical lookups: "find the ancestor account up the org tree," "walk a parent chain until you hit a leaf." Just remember the depth cap (Sheets caps recursion at a few hundred levels to prevent runaway formulas).

## Importing named functions across workbooks

Named functions are scoped to one workbook. To use a function defined in another sheet:

1. Open the destination sheet.
2. **Data → Named functions → Import function.**
3. Pick the source workbook and the functions to import.

This is how the team maintains a "definitions" workbook. Define `ROI`, `ROAS`, `BLENDED_CPM`, `MARGIN`, `BUYER_TIER` in one workbook; import into every dashboard. The catch: **imports do not auto-update.** Change the source definition and the existing imports keep the old logic until someone re-imports. This is intentional (drive-by changes to a shared definition could silently break dependent sheets) but it trips people up.

The team's habit: when a shared function changes, send a one-line note in Slack so dependents know to re-import.

## When to promote a `LAMBDA` to a named function

The five-second rule of thumb:

- The same `LAMBDA` appears in three or more cells, or in a `MAP` across a long range. Promote.
- The body is more than ~80 characters. Promote.
- Multiple people on the team need to use the same calculation. Promote.
- The calculation might change over time (fee structure, ROI definition, threshold). Promote.
- It is a one-shot calculation in a single cell. Do not promote: keep it inline with `LET + LAMBDA` (lesson 1.20).

## Used in the wild

- **Team KPI library.** Define `ROI`, `ROAS`, `MARGIN`, `BLENDED_CPM`, `EFFECTIVE_CPC`, `BUYER_TIER`, `IS_PROFITABLE` once. Import into every dashboard. The team's vocabulary lives in formulas, not tribal knowledge.
- **Custom validators.** `IS_VALID_CAMPAIGN_CODE(code)` wraps a `REGEXMATCH` against the team's naming convention (lesson 1.16). Reuse in conditional formatting, in `QUERY` filters, in dashboard checks.
- **Cross-platform normalizers.** `NORMALIZE_PLATFORM(raw)` maps `"TBL"`, `"Taboola"`, `"taboola_native"` all to `"Taboola"`. One function, used wherever messy platform names show up.
- **Period-aware lookups.** `MTD_SPEND(buyer)` returns month-to-date spend for a buyer. Encapsulates the `SUMIFS` + date-math so dashboards do not reinvent the date logic each time.
- **Tier classifications.** `BUYER_TIER(spend)` returns `"T1"` / `"T2"` / `"T3"` based on rolling spend. The thresholds live in the function definition; change the thresholds once, every dashboard updates.

## Pro pitfalls

- **Named functions do not carry over to other workbooks automatically.** Either re-define or import. There is no "global" namespace.
- **Imported functions do not auto-update.** Re-import to pick up changes from the source. Build a habit: when you change a shared function, ping the team to re-import.
- **No optional arguments, no default values.** Every argument must be passed. Workaround: use a sentinel like `0` or `""` and handle it inside the body with `IF`.
- **No type checking.** A function expecting a number will accept text and either produce a wrong answer or `#VALUE!`. There is no signature enforcement. Document parameter types in the description so callers know what to pass.
- **Recursion depth is limited.** Hard cap is a few hundred. Fine for tree walks, useless for deep numerical recursion.
- **Names collide with built-ins silently.** If you define `SUM` as a named function, your `SUM` shadows the built-in inside the workbook. Avoid this by using a prefix (`MY_SUM`) or distinct names.
- **Editing a function while formulas reference it can break things.** Sheets handles renames and signature changes by failing dependent formulas. Plan changes; do not edit a live function during a busy reporting day.
- **The body cannot reference cells directly.** It must work entirely from its parameters. If you want a function that depends on a workbook constant (a fee, a target ROI), pass that constant in as a parameter, or use a named range inside the body, accepting that the function is then workbook-specific.
