# SPARKLINE: charts inside cells

A working dashboard usually has one row per buyer, per vertical, or per campaign, and the eye wants a trend line for each row without opening a separate chart. `SPARKLINE` is the answer: it draws a tiny chart inside the formula cell itself. No chart object, no resizing, no separate render layer. The cell is the chart.

For a team running fifty buyers across five platforms, a sparkline column turns a wall of numbers into a one-screen visual. You see who is climbing, who is flat, who spiked on a single Tuesday. The cost is one formula per row. The payoff is that a stakeholder can scan the report in ten seconds instead of squinting at totals.

## The minimum viable sparkline

The simplest call passes a single range of numbers:

```
=SPARKLINE(B2:B8)
```

Default chart type is `line`. Row height controls vertical pixels; column width controls horizontal pixels. That is the whole formula. The interesting choices live in the second argument: the options object.

## The four chart types

| Type | Use when |
|---|---|
| `line` (default) | Trends over time, continuous data |
| `column` | Comparing discrete categories side-by-side |
| `bar` | Single-segment progress bar (one or two values) |
| `winloss` | Outcomes where direction matters more than magnitude |

```
=SPARKLINE(B2:B8, {"charttype","line"})
=SPARKLINE(B2:B8, {"charttype","column"})
=SPARKLINE(B2:B8, {"charttype","bar"})
=SPARKLINE(B2:B8, {"charttype","winloss"})
```

Pick the chart type by the *question the row is answering*. Daily revenue trend? `line`. Spend by platform? `column`. Progress to monthly goal? `bar`. Days where ROI was positive vs negative? `winloss`.

## The options object

Options come in as a 2-column array. Inside the braces, separate pairs with `;` (row separator) and the option name from its value with `,` (column separator).

```
=SPARKLINE(B2:B8, {
  "charttype", "line";
  "color", "#4285F4";
  "linewidth", 2;
  "ymin", 0
})
```

Common options:

| Option | Values | Use |
|---|---|---|
| `charttype` | line, column, bar, winloss | Pick the chart type |
| `color` | named color or hex | Line/bar/column color |
| `color1` / `color2` | colors | For winloss: positive vs negative bars |
| `linewidth` | number | Line thickness for line charts |
| `ymin` / `ymax` | numbers | Force Y-axis bounds |
| `firstcolor`, `lastcolor`, `highcolor`, `lowcolor`, `negcolor` | colors | Highlight specific points |
| `axis` | TRUE/FALSE | Show baseline at y=0 |
| `rtl` | TRUE/FALSE | Right-to-left display |

## Adtech: per-buyer revenue trend

Picture a dashboard with one row per buyer and a 7-day revenue trend in one cell. The columns to the left carry totals; the sparkline column carries shape.

| Buyer | Total revenue | 7-day trend |
|---|---|---|
| Yoav Cohen | $4,310 | (sparkline of B2:H2) |
| Sarah Levi | $3,820 | (sparkline of B3:H3) |
| David Mizrahi | $5,640 | (sparkline of B4:H4) |

The formula in the trend column, assuming each buyer's daily revenue is in a row 7 columns wide:

```
=SPARKLINE(B2:H2, {"charttype","line"; "color","#4285F4"; "linewidth",2})
```

Drag it down. At a glance you see who is trending up, who is flat, who spiked on one day. The team uses this every Monday morning to spot the buyers worth a one-on-one.

## Win/loss for ROI consistency

A winloss sparkline draws a small bar above (positive) or below (negative) the baseline for each value. Magnitude is ignored. Only direction matters.

```
=SPARKLINE(B2:H2, {"charttype","winloss"; "color1","green"; "color2","red"; "negcolor","red"})
```

For a row of daily ROIs, this becomes a "5 wins, 2 losses" bar pattern at a glance. Useful for quick consistency checks: a buyer with seven greens beats a buyer with five greens and two big reds, even if their week-total ROI is identical.

## Easy traps

The options array is where most sparkline formulas die. Two patterns the team has lost time to, side-by-side:

## Locking the Y-axis for honest comparison

A sparkline of values 95-100 looks identical to one of 5-100 because the Y-axis auto-scales to the data. Across rows in a dashboard, that auto-scaling is dishonest: a tiny drift looks the same as a tenfold spike.

```
=SPARKLINE(B2:H2, {"charttype","line"; "ymin",0; "ymax",1000})
```

With `ymin` and `ymax` set to the same bounds across all rows, the sparklines become directly comparable. Sarah's $400-500 line stays small at the bottom while David's $1,000 spike fills the cell. That is the picture you actually want stakeholders to see.

## Pro pitfalls

- **Render quirks in exports.** Sparklines render in the live grid but sometimes vanish from PDF print or screenshots taken via the Sheets API. Test the export path *before* depending on sparkline-heavy dashboards for stakeholder reports.
- **Options array uses `;` between pairs and `,` inside each pair.** Swapping them breaks the formula with a confusing parse error. The pattern is: `name, value; name, value; name, value`.
- **Non-numeric values poison the chart.** `#N/A` from a broken lookup, `"#REF!"` from a deleted range, or a text string in a numeric range will fail the whole sparkline. Wrap upstream data with `IFERROR` (lesson 9) or `IFNA` before passing it.
- **Color names are inconsistent.** `"blue"` works, `"navy blue"` does not. Hex codes (`"#4285F4"`) are safer and team-consistent.
- **Y-axis defaults to the data range.** Two sparklines with vastly different absolute values can look identical without locked `ymin`/`ymax`. For honest cross-row comparison, set the bounds explicitly.
- **No 2D data.** The data range must be a single row or column. Multiple series in one sparkline is not supported. If you need that, use a real chart object.
- **Conditional formatting does not cascade.** Sparklines render from the data range, not from cell formatting. "Color red when below threshold" has to be computed in the options object, not in the cell's CF rule.
- **Volatile data sources.** If the sparkline pulls from an `IMPORTRANGE` (lesson 1.27) that lags, the chart will lag with it. Refresh state is the upstream source's problem; the sparkline just renders whatever is there.

## Used in the wild

- **Per-buyer or per-vertical trend column.** One cell, instant visual context, dragable across the whole list. The team's Monday-morning standup dashboard relies on this.
- **ROI consistency winloss bars.** Daily ROI as a row of green/red ticks. Flags inconsistent buyers without dumping numbers into the conversation.
- **Period-over-period sparkline.** Last 30 days of spend per platform as one tiny chart per row of the platform-summary report.
- **Goal tracking bars.** A bar-type sparkline showing % progress to monthly goal, with `ymax` locked to the goal value. The bar fills as the month progresses.
- **A/B test outcome strip.** Win/loss across N test arms, color-coded green/red, in a single cell of the experiment summary table.
