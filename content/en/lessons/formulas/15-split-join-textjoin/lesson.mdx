# SPLIT, JOIN, TEXTJOIN, FLATTEN

These four are the bridge between *text data* and *column data*. `SPLIT` turns one cell into many. `JOIN` and `TEXTJOIN` go the other way: many cells into one. `FLATTEN` collapses a 2D grid into a single column so downstream functions like `UNIQUE` and `FILTER` can chew on it.

You will reach for them constantly in adtech. The team's campaign codes pack four or five pieces of metadata into one string (`Taboola_CarDealsPR_DesktopUS_2026-05`); `SPLIT` parses them out. Buyer-name lists for Slack updates get built with `TEXTJOIN`. And every time you need to dedupe values that live in a wide pivot grid, `FLATTEN` is what makes the data shape compatible with `UNIQUE`.

## SPLIT: one cell to many

`SPLIT` breaks a string into separate cells. The result spills horizontally by default. The single biggest gotcha is the `split_by_each` argument: by default, every character of the delimiter acts as its own splitter. With a one-character delimiter like `"_"` that is what you want. With a multi-character delimiter like `", "` it is almost never what you want, and that is where most SPLIT bugs come from.

Reach for SPLIT whenever a column holds packed metadata: campaign codes, comma-separated tag lists pasted from a CMS, anything with a structural separator.

### Combined example: SPLIT + INDEX to pull one piece

You rarely want all four parts. The common pattern is "give me just the vertical" or "just the platform." Wrap `SPLIT` in `INDEX` to pluck a single position from the spilled output.

```
=INDEX(SPLIT(A2, "_"), 2)
```

Returns the second piece (the vertical) from the campaign code in `A2`. Combine with `ARRAYFORMULA` (lesson 1.10) to compute it for every row of the column at once.

<TryIt
  data={[
    ["Code", "Vertical"],
    ["Taboola_CarDealsPR_DesktopUS_2026-05", ""],
    ["Outbrain_CruisesPR_MobileEU_2026-05", ""],
    ["MediaGo_SolarSystemsPanelsPR_DesktopUS_2026-05", ""],
  ]}
  inputCell="B2"
  expectedFormula='=INDEX(SPLIT(A2,"_"),2)'
  task={<>Extract just the vertical (the second piece) from the campaign code in <code>A2</code> and put it in <code>B2</code>.</>}
  hint={<>SPLIT returns a 4-cell array. <code>INDEX(array, position)</code> picks one cell. The vertical is at position 2.</>}
  answer={<>The composition <code>INDEX(SPLIT(A2, "_"), 2)</code> gives you "CarDealsPR". To run this on a whole column, wrap with <code>ARRAYFORMULA</code> and use open-ended ranges: <code>=ARRAYFORMULA(IFERROR(REGEXEXTRACT(A2:A, "^[^_]+_([^_]+)_"), ""))</code> is actually faster on large datasets because INDEX inside ARRAYFORMULA does not broadcast cleanly with SPLIT's spilled output. ## JOIN and TEXTJOIN: many cells to one

`JOIN(delimiter, range)` and `TEXTJOIN(delimiter, ignore_empty, range)` are the inverses of SPLIT. They take an array and produce a single string with a delimiter between each piece.

`TEXTJOIN` is what you reach for in production: it skips empty cells when `ignore_empty = TRUE`, and it accepts 2D ranges. `JOIN` errors on 2D ranges and includes blanks. Treat JOIN as legacy.

<FunctionRef name="TEXTJOIN" />

### Worked example 1: toy data

Three names, one comma-separated string. `TEXTJOIN` with `ignore_empty = TRUE` is robust even when the source has gaps.

## FLATTEN: a 2D grid to one column

`FLATTEN(range1, [range2, ...])` collapses a 2D range into a single column, walking the grid row by row (entire first row before the second). It exists because `UNIQUE`, `FILTER`, and `QUERY` all expect one-column inputs for many of their use cases; FLATTEN is the adapter.

In adtech work, you reach for FLATTEN when a dashboard has buyer-vertical pairs spread across a grid and you need to dedupe the lot, or when an `IMPORTRANGE` pulls back a wide block and you want to extract the union of all values.

## Used in the wild

- **Parsing campaign codes.** `SPLIT` breaks `Platform_Vertical_Audience_Period` into four columns at the top of every campaign log. The shape feeds dashboards that filter by platform or vertical.
- **Targeted extraction.** `INDEX(SPLIT(...), n)` pulls just the piece you need (vertical only, period only). For column-wise extraction over a growing log, `REGEXEXTRACT` inside `ARRAYFORMULA` (lesson 1.16) is usually faster.
- **Slack-ready buyer lists.** `TEXTJOIN(", ", TRUE, UNIQUE(B2:B))` builds a comma list of distinct buyers for status updates without manual typing.
- **CSV-style exports.** `TEXTJOIN(",", FALSE, row_range)` builds CSV rows when you need a quick paste-to-Notion or paste-to-email format.
- **Cross-column deduping.** `UNIQUE(FLATTEN(B2:D))` collapses three related columns into a single distinct list, useful for "every value that has ever appeared in any of these tag columns" reports.

## Pro pitfalls

- **`SPLIT` with default `split_by_each = TRUE` splits on every character of a multi-character delimiter.** Always pass `FALSE` for delimiters longer than one character.
- **`SPLIT` drops empty results by default.** `SPLIT(",,a", ",")` returns just `"a"` unless you pass `FALSE` for `remove_empty_text`. The team has lost rows of data this way.
- **`JOIN` errors on 2D ranges.** Use `TEXTJOIN` (which handles 2D) or wrap the range with `FLATTEN` first.
- **`TEXTJOIN` over a very large range can exceed the 50,000-character cell limit.** Anything over a few thousand rows of moderate-length strings should be chunked or piped through `QUERY`.
- **`FLATTEN` preserves blank cells.** Pair with `FILTER(FLATTEN(...), FLATTEN(...)<>"")` to drop them before deduping.
- **`SPLIT` on an `IMPORTRANGE`'d cell stays referenced to the source.** Rename the source workbook and every dependent SPLIT silently breaks. Lesson 1.27 covers the recovery patterns.
- **The output of `SPLIT` is horizontal by default.** If you need a vertical list, wrap with `TRANSPOSE` or use `REGEXEXTRACT` repeatedly.
