# Coming from Excel

Sheets and Excel are 90% the same. The 10% gotchas catch working pros in week one. The big four: arrays don't auto-spill, `XLOOKUP` works the same, Power Query has no equivalent, and the sharing model is link-based instead of file-based.

This lesson is also where you meet three of the functions you'll lean on every day in this curriculum: `ARRAYFORMULA`, `XLOOKUP`, and `QUERY`. We introduce each one with its full signature and a couple of worked examples so the syntax sticks before the dedicated deep-dive lessons (10 for arrays, 4 for lookups, 12-13 for QUERY).

## Arrays: explicit, not implicit

In Excel 365, if you type `=F2:F13` in any cell, Excel "spills" the column for you: 12 values appear, one per row, automatically. In Sheets the same formula returns just the first value, `487.3`. You get one cell, not twelve. To make a range expression spread into the cells around it, you wrap it in `ARRAYFORMULA`.

The classic adtech case: you want a Profit column (revenue minus spend) for every campaign in the log, computed by **one** formula at the top of the column. In Excel you type `=F2:F13-E2:E13` and get a spilled column for free. In Sheets you wrap it in `ARRAYFORMULA` to ask for the same behavior.

### How it evaluates, step by step

Take the math case `ARRAYFORMULA(F2:F13 - E2:E13)`. The engine doesn't run the subtraction once. It expands both ranges into 12-element arrays, lines them up row by row, subtracts each pair, and returns a 12-element array that spills into the cells below your formula cell.

          values. Both arrays have the same shape.

Same idea on the campaign log. A single `ARRAYFORMULA` at the top of column G computes profit for every campaign at once.

## XLOOKUP: same in both, finally

`XLOOKUP` shipped to Sheets in 2022. The signature is the same as Excel's, and the behavior is the same. If you use it in Excel today, you can use it in Sheets today. It's the modern replacement for the pair `VLOOKUP` + `HLOOKUP`: one function that handles both directions, with proper "not found" handling and no column-index arithmetic.

<FunctionRef name="XLOOKUP" />

### How the lookup walks the range

<StepThrough
  frames={[
    {
      caption: "Step 1: resolve search_key",
      body: (
        <>
          Read the value (e.g. <code>&quot;Yoav Cohen&quot;</code>) or
          reference (e.g. <code>B24</code>). This is the thing to look for.
        </>
      ),
    },
    {
      caption: "Step 2: scan lookup_range",
      body: (
        <>
          Walk the lookup_range row by row (or column by column, if it's a
          row). Stop at the first cell that matches per <code>match_mode</code>.
          With the default <code>0</code>, that means an exact match.
        </>
      ),
    },
    {
      caption: "Step 3: read the parallel cell from result_range",
      body: (
        <>
          Whatever position the match landed at, read the cell at the same
          position in <code>result_range</code>. If the match was in row 5 of
          lookup_range, the result is row 5 of result_range.
        </>
      ),
    },
    {
      caption: "Step 4: handle no-match",
      body: (
        <>
          If nothing matched, return <code>missing_value</code>. If you

          worth passing a friendly fallback like <code>0</code> or{" "}
          <code>&quot;not found&quot;</code>.
        </>
      ),
    },
  ]}
/>

A tiny price book. Look up "B" and get its price.

### Worked example 2: real adtech data

Find the revenue of a buyer's first campaign in the log.

<TryIt
  data={CAMPAIGNS}
  inputCell="H1"
  expectedFormula='=XLOOKUP("Yoav Cohen",B2:B13,F2:F13)'
  task={<>Use <code>XLOOKUP</code> to find the revenue of Yoav Cohen's first campaign in the log. The result in <code>H1</code> should be <code>487.3</code>.</>}
  hint={<>Three arguments: search key (<code>"Yoav Cohen"</code>), lookup range (<code>B2:B13</code>: the Buyer column), return range (<code>F2:F13</code>: Revenue).</>}
  answer={<>The lookup range and return range are passed as separate arguments. They line up row-for-row: row 1 of <code>B2:B13</code> is Yoav, row 1 of <code>F2:F13</code> is 487.3. No column-number arithmetic, no <code>FALSE</code> flag for exact match. <code>XLOOKUP</code> returns the first match by default, which here is the May 1 Car Deals PR campaign on Google. To find a specific match, add a fourth argument for a missing-value fallback, or use INDEX/MATCH (covered in lesson 4).</>}

## QUERY: the SQL-like power tool

Power Query in Excel is a UI for shaping, joining, and transforming data, with steps recorded as M code. Sheets has nothing like that out of the box, but it has something that covers most of the same ground: `QUERY`, a single function that runs SQL-like queries over a range.

<FunctionRef name="QUERY" />

### Worked example 1: filter and sort

The most common shape: pick columns, filter rows, sort. One formula, one spilled result.

<TryIt
  data={CAMPAIGNS}
  inputCell="I1"
  expectedFormula='=QUERY(A1:F13, "SELECT B, C, F WHERE F >= 400 ORDER BY F DESC")'
  task={<>Show only campaigns whose revenue (column F) is 400 or more. Return the Buyer, Vertical, and Revenue columns, sorted from highest to lowest revenue.</>}
  hint={<>Use <code>SELECT B, C, F WHERE F &gt;= 400 ORDER BY F DESC</code> as the query string. Note the headers row: passing <code>A1:F13</code> includes it; QUERY will guess.</>}
  answer={<>QUERY runs the SELECT against the data range and returns a spilled table. <code>SELECT B, C, F</code> picks columns. <code>WHERE F &gt;= 400</code> filters rows. <code>ORDER BY F DESC</code> sorts high-to-low. The result updates as the source changes: exactly what you want when the source is itself an IMPORTRANGE from a per-platform sheet.</>}
/>

### Worked example 2: group and aggregate

QUERY isn't just filter. Group rows and aggregate them in the same formula. The result is a small summary table.

<TryIt
  data={CAMPAIGNS}
  inputCell="K1"
  expectedFormula='=QUERY(A1:F13, "SELECT C, SUM(F) GROUP BY C ORDER BY SUM(F) DESC")'
  task={<>Total revenue per vertical, highest first. Two columns: the vertical name and the sum.</>}
  hint={<>The shape is <code>SELECT C, SUM(F) GROUP BY C ORDER BY SUM(F) DESC</code>. Columns in <code>SELECT</code> outside of an aggregate must appear in <code>GROUP BY</code>.</>}
  answer={<>SQL-style aggregation in one formula. The result is shaped like a pivot but it's a live formula: edit the source and the summary recomputes immediately. Slower than <code>SUMIFS</code> on very large sheets (10k+ rows) but much more expressive: you get filter + group + sort + limit in one call.</>}
/>

## Power Query: no direct equivalent, mapped

Beyond `QUERY` itself, here's the rest of the Power Query → Sheets mapping. Use this as a reach-for-this cheat sheet when you'd reach for a Power Query step in Excel.

| In Excel you'd... | In Sheets reach for... |
|---|---|
| Filter and sort with Power Query | `QUERY(range, "SELECT ... WHERE ... ORDER BY ...")` |
| Join two tables on a key | `QUERY` with multiple references, or `XLOOKUP` per row |
| Pull from another workbook | `IMPORTRANGE(url, "Sheet!A:F")` |
| Multi-step transformations | Apps Script (Track 3) |
| Pull from a database or warehouse | Connected Sheets + BigQuery (Track 4) |

`IMPORTRANGE` is how the team wires every campaign sheet to its raw-data source. It's also the most common source of broken formulas: source workbook renamed, permissions revoked, range drifted. Track 1 lesson 27 covers `IMPORTRANGE` patterns; Track 4 covers diagnosing breakage.

## The sharing model is link-based, not file-based

Excel files live in a file system; sharing is a permission attached to the storage location. Sheets workbooks live in Drive; sharing is metadata on the document, with granular roles (viewer, commenter, editor) and link-share scopes. The "save and email the file" workflow disappears, replaced by "send a link." A workbook can have hundreds of editors at once with no merge conflicts.

This shows up in adtech work in two ways:

- **Cross-workbook references via `IMPORTRANGE`.** When Sheet A imports from Sheet B, it requires explicit permission the first time. If the owner of B revokes editor access on A, the IMPORTRANGE fails silently and every dependent formula returns `#REF!`. Multiply by 10 source sheets and one breakage cascades.
- **Filter views (covered later in Track 2).** When five media buyers share a sheet, they can each apply their own filter without disturbing the others. Without filter views, one person's "show only Taboola" filter hides rows for everyone.

## A few quieter differences

- **No built-in VBA.** Apps Script (JavaScript-flavored) replaces it. Track 3 covers it.
- **`UNIQUE`, `SORT`, `FILTER` spill without `ARRAYFORMULA`.** Retrofitted to behave like Excel's spilled versions.
- **Cross-sheet references skip the file path.** `=Campaigns!E5` rather than `=[file.xlsx]Sheet1!E5`. Cross-workbook references use `IMPORTRANGE` (lesson 27).
- **`IF`, `IFS`, `SWITCH`, `LET` are aligned.** Conditional logic ports cleanly.

## Used in the wild

In the team's actual workbooks, the three functions you met today show up like this:

- **Profit, ROI, EPC, margin columns are all single `ARRAYFORMULA`s at the top.** When new campaigns are pasted into rows 14, 15, 16, the `ARRAYFORMULA` extends automatically (assuming the range was set wide enough at the start).
- **`XLOOKUP` for "give me X for buyer Y" is a daily reflex.** First campaign date, total spend this month, last vertical they ran. Often joined with cross-sheet `IMPORTRANGE` on a buyers tab. Pair it with `missing_value = 0` so dashboards don't fill with `#N/A`.
- **`QUERY` is how the dashboards get built.** `SELECT A, B, SUM(F) GROUP BY A, B` with a date filter. Slower than `SUMIFS` for huge sheets but much more expressive: filter + group + sort + limit in one formula.
