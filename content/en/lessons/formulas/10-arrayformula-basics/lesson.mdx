# Array formulas: ARRAYFORMULA basics

`ARRAYFORMULA` was introduced in lesson 2 as the Sheets workaround for Excel's auto-spilling. This lesson goes deep on when to reach for it, when not to, and how to use it without bringing your sheet to its knees on big data. In adtech work, ARRAYFORMULA is how you keep computed columns (profit, ROI, EPC, normalized names) maintainable across a dataset that grows every day: one formula at the top, no fill-down required.

The team's most painful ARRAYFORMULA bug shows up when the source range is an `IMPORTRANGE`. Imported data has no fixed row count — the source workbook can gain a row at any moment and the spill silently grows. An `ARRAYFORMULA(IMPORTRANGE(...) * 2)` over a half-million-row import melts the workbook the moment the source crosses the cell limit. Lesson 1.27 covers the `IMPORTRANGE` side; here, when we use range references like `B2:B`, picture an imported range underneath that could expand without warning. The bounded-range patterns later in this lesson are the protection.

## What it does and why you need it

In Excel 365, `=B2:B13 - A2:A13` spills into 12 cells automatically. Sheets returns only the first value. Wrapping in `ARRAYFORMULA` tells Sheets to broadcast the operation across the whole range.

## Functions that already spill

A handful of Sheets functions are array-aware on their own and don't need `ARRAYFORMULA`:

- `FILTER`, `SORT`, `UNIQUE`
- `QUERY`
- `SEQUENCE`, `RANDARRAY`
- `SPLIT`, `TRANSPOSE`, `FLATTEN`

Anything else: including basic operators (`+`, `-`, `*`, `/`), comparisons (`>`, `=`), text functions (`LEFT`, `UPPER`, `&`), and most other functions when applied to a range: needs the wrapper.

## Don't wrap what's already array-aware

Wrapping `FILTER`, `QUERY`, etc. in `ARRAYFORMULA` doesn't error: it's just redundant. But it can confuse readers and adds noise. The convention: wrap only what needs wrapping.

```
=FILTER(F2:F13, B2:B13 = "Yoav Cohen")           ✓ clean
=ARRAYFORMULA(FILTER(F2:F13, B2:B13 = "Yoav Cohen"))  ✗ noisy
```

## The "open-ended range" pattern

In real adtech work, you don't know how many campaigns will be added. Hardcoding the range to `E2:E13` works for today, but next week you'll have rows 14, 15, 16... and your ARRAYFORMULA stops covering them.

The pattern: use an open-ended range like `E2:E` (everything from E2 to the bottom of the column) or set a high upper bound like `E2:E10000`. With `ARRAYFORMULA`, this means "compute for every row that has data, and stop".

```
=ARRAYFORMULA(IF(E2:E="", "", F2:F - E2:E))
```

The `IF(E2:E="", "", ...)` guard suppresses output for empty rows. Without it, the formula spills "0" or "#DIV/0!" all the way down to row 1 million. With it, the spilled values stop where the data stops.

## ARRAYFORMULA + IF: branching across rows

`IF` works inside `ARRAYFORMULA` to apply different logic per row. The condition can be a comparison against a range, and both branches can be expressions involving other ranges.

The classic adtech use: a "Status" column that labels each campaign's profitability. One formula at the top, fills the whole column.

```
=ARRAYFORMULA(IF(F2:F-E2:E > 0, "Profit", "Loss"))
```

Same idea with IFS: bucket every row by ROI in one formula. (Note: IFS inside ARRAYFORMULA works in Sheets but can be slower than the equivalent nested IF on huge sheets.)

## Used in the wild

- **Computed columns at the top of every campaign sheet.** Profit, ROI, EPC, profit margin: each is a single ARRAYFORMULA at row 1 or 2 that fills the whole column. New campaigns paste in below and the computed columns extend automatically.
- **Normalization columns.** A clean buyer-name column built from the raw column with `ARRAYFORMULA(TRIM(LOWER(B2:B)))` so downstream lookups don't fail on whitespace or case.
- **Status flags.** "Profitable", "Star", "Loss" labels in one formula instead of one per row.
- **Cohort keys.** A single ARRAYFORMULA building "2026-05" from a launch_date column for cohort-based grouping.

## Pro pitfalls

- **Open-ended ranges (`E2:E`) without an empty-row guard fill the whole sheet.** A million rows of "#DIV/0!" or "0" will slow the sheet to a crawl. Always guard with `IF(E2:E="", "", ...)`.
- **ARRAYFORMULA can hide bugs in individual rows.** If row 50 is malformed, you'll get an error in the spilled cell but you can't fix it directly: only by editing the master formula.
- **IF inside ARRAYFORMULA evaluates BOTH branches for every row.** If one branch is expensive (an XLOOKUP, a regex), it runs even when not chosen. Cost compounds on big data.
- **Some functions DON'T work inside ARRAYFORMULA.** Aggregators like SUM, AVERAGE, COUNT: wrapping a range with SUM inside ARRAYFORMULA returns the total, not row-by-row totals. Use `SUMIFS` per row or restructure.
- **You can't edit spill cells individually.** If the team is used to overwriting a cell to manually fix a value, ARRAYFORMULA breaks that workflow. Communicate the change.
- **Spill ranges can collide.** If G1 has an ARRAYFORMULA spilling into G1:G12 and someone types in G5, the whole formula errors with `#REF!`. The error message points to G1, but the cause is wherever the conflict is.
