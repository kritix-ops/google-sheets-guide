# LAMBDA: define your own functions inside a formula

`LAMBDA` lets you define a function inline, right inside a cell. You pass it a list of parameter names and a body that uses them, and it gives you back a callable function. By itself a `LAMBDA` does not produce a value: it produces a *function*. You then either invoke it immediately, pass it to a helper like `MAP` or `REDUCE` (lesson 1.19), or save it as a **named function** for team-wide reuse (lesson 1.21).

LAMBDA is the foundation for everything in modern Sheets formula work. Once it clicks, you stop copy-pasting the same calculation across 400 cells and you stop nesting six layers of IF/SUMIFS to express "for each row, do this." Instead you write the calculator once, give it a name, and reuse it. For an adtech team that already has dozens of bespoke KPIs (ROI, ROAS, effective CPC, fee-adjusted profit), LAMBDA is the upgrade that lets every dashboard pull from a single source of truth instead of a slightly-different copy in every tab.

## The syntax

```
LAMBDA(param1, param2, ..., body)
```

Parameters first, body last. Parameter names are local to the body and they shadow any same-name named range while the body runs. The body is **one expression** (no semicolons, no statements). If you need intermediate values, nest a `LET` inside the body.

A LAMBDA on its own produces a function, not a value. Put a bare `=LAMBDA(s, r, (r-s)/s)` in a cell and Sheets shows `#CALC!` because there is nothing to display. The function exists; you just have not called it.

## LAMBDA + LET: name the function

`LET` lets you name a value or function inside a formula. Combined with `LAMBDA`, you define a calculator once and reuse it across multiple inputs in the same cell:

```
=LET(
  roi, LAMBDA(s, r, (r-s)/s),
  roi(100, 250) + roi(200, 600)
)
```

`roi` is now a callable function inside the `LET`. Three calls in, the LAMBDA-with-LET form is shorter than the inline version, and the calculator is defined in exactly one place: change the body once, every invocation updates.

This is the canonical pattern for per-formula KPI calculators. Define `cpc`, `cpm`, `roas` once inside one `LET`, then chain them however the cell needs.

### Combined example: LAMBDA + MAP for whole-column calculation

The pattern that LAMBDA really exists for. `MAP` (lesson 1.19) applies a LAMBDA to every cell of a range and spills the result. The combination replaces every "copy this formula down 1000 rows" workflow.

```
=MAP(E2:E13, F2:F13, LAMBDA(s, r, (r-s)/s))
```

`MAP` calls the LAMBDA once per row, passing it `(s, r)` from the paired columns, and spills the ROI for every campaign from one cell. No fill-down. No risk of forgetting a row. Adding rows to the source extends the output automatically when paired with open-ended ranges.

## Why bother for adtech

Three real wins:

1. **Single-formula calculators.** Instead of one cell with `=B2*0.95` and another with `=B2-fee`, define a LAMBDA in `LET` that handles the calculation in one place. Edit once, every dependent expression updates.
2. **Pass-around for `MAP`/`REDUCE`.** Lesson 1.19 (`MAP`, `REDUCE`, `SCAN`, `BYROW`, `BYCOL`, `MAKEARRAY`) is built on LAMBDA. `=MAP(A2:A100, LAMBDA(x, x*1.1))` applies a 10% markup to every value in a single formula: no fill-down, no missed rows.
3. **Named functions.** Lesson 1.21 turns LAMBDAs into reusable named functions: `=ROI(spend, revenue)` becomes a real callable in the team's workbook with documentation and parameter validation. Every dashboard then uses the same definition.

## Used in the wild

- **One-shot KPI calculators in dashboards.** `=LET(roi, LAMBDA(s,r,(r-s)/s), roi(SUM(Campaigns[Spend]), SUM(Campaigns[Revenue])))` computes overall ROI in a single cell.
- **Parameterized inline lookups.** Define `LAMBDA(buyer, vertical, SUMIFS(...))` inside a `LET`, then call it with different buyer/vertical pairs to build a small inline summary table.
- **Building blocks for `MAP`/`REDUCE`.** Almost every real use of `MAP` and `REDUCE` (lesson 1.19) takes a LAMBDA as the function argument.
- **Named functions** (lesson 1.21): the team defines `ROI(spend, revenue)`, `ROAS(spend, revenue)`, `EFFECTIVE_CPC(spend, clicks)` once and uses them everywhere. The body is always a LAMBDA.
- **Composable LET chains.** `=LET(roi, LAMBDA(s,r,(r-s)/s), fee_adjusted, LAMBDA(s,r,roi(s+s*0.05, r)), fee_adjusted(SUM(...), SUM(...)))`: a LAMBDA built on top of another LAMBDA inside one LET. Hard to read at first; powerful once you have lived with it.

## Pro pitfalls

- **A bare LAMBDA in a cell shows `#CALC!`.** It is a function, not a value. Either invoke it with `(args)` or pass it to a helper that calls it.
- **The body is one expression.** No semicolons, no statements. If you need intermediate values, nest a `LET` inside the body: `LAMBDA(x, LET(y, x*2, y+1))`.
- **Parameter names shadow named ranges inside the body.** If you have a named range called `spend` and write `LAMBDA(spend, spend*2)`, the parameter wins inside the body. Usually fine, occasionally surprising.
- **No closures over outside `LET` variables.** Inside a LAMBDA body you can reference cells (`A2`, `B5:B10`) and built-in functions, but you cannot reference variables from a surrounding LET unless you explicitly pass them in as parameters. Keep LAMBDAs closed over their parameters only.
- **Recursive LAMBDA is supported but capped.** You can call a named function from inside its own body (lesson 1.21), but recursion depth is limited to a few hundred levels to prevent runaway formulas.
- **Anonymous LAMBDAs inside `MAP` get unreadable fast.** A 200-character LAMBDA inside `MAP` is unreadable. Promote it to a named function (lesson 1.21) the moment it stops fitting comfortably on one line.
- **LAMBDA bodies do not have access to volatile spreadsheet state in a special way.** `NOW()` inside a LAMBDA still recalculates on every change, like everywhere else. Lesson 1.11 covers volatility.
