# The `=AI()` function

`=AI()` is Gemini wrapped in a cell. You give it a prompt string and an optional bounded range, you click **Generate and insert**, and a text string lands in the cell. Compared with `SUM` or `XLOOKUP` it looks tame, but it's the only function on your sheet whose output is non-deterministic, slow (seconds, not milliseconds), and billed against your Workspace plan. Two calls with the same arguments can return two different answers. Each call counts against quota. And the return type is always text, even when you wish it were a number.

Used carelessly, `AI()` fills a column with subtle wrong answers nobody catches until a dashboard contradicts itself. Used well, it carries weight: per-row sentiment, per-row classification, per-row extraction at a scale that would otherwise need a junior analyst on a salary. This lesson is how to use it well: the signature, the constrained-prompt habit, the defensive wraps, and the dragon's lair of non-determinism. Lesson 5.6 is the framework for when to leave it alone entirely.

## The signature

`AI()` has a one-or-two-argument signature: a required prompt and an optional grounding range. Output is always a text string, and the call requires a manual **Generate and insert** click in the cell before the result is committed. Eligible Workspace plans and Workspace Experiments access are prerequisites; ask your admin if the function does not appear in your environment. When you do pass a range, bound it (`A1:G61`, not `A:G`) per the discipline from lesson 2.1 (Track 4 lesson 2) so you don't ship a million empty cells of context to the model.

<FunctionRef name="AI" />

A few canonical patterns the team writes every week:

```
=AI("Categorize this campaign's risk as low, medium, or high. Spend: " & E2 & " Revenue: " & F2)
=AI("Sentiment of this customer note: " & E2)
=AI("Extract the 2-letter country code from: " & H2)
=AI("Summarize the dataset in one sentence", A1:G61)
```

The `&` is doing the heavy lifting in the first three: it concatenates the prompt instruction with the specific cell value so each row gets a row-specific question. The fourth pattern uses the range argument instead, which is what you want when you summarize a whole table.

### Worked example 1: toy data

A 6-row campaign log. One AI() call, constrained output, one cell of result. Smallest possible illustration of the syntax.

### Worked example 2: real adtech data

Same idea on the 60-row campaign log. `H2` is one row's classification:

```
=AI("Risk: low, medium, or high. Spend " & F2 & " Revenue " & G2 & " for vertical " & C2)
```

After **Generate and insert**, the cell reads `low`, `medium`, or `high`. Drag down 60 rows (one Generate per row, slow and billable) and you have a risk column ready to filter, pivot, or freeze with paste-as-values. Note that the range argument is omitted here on purpose: the per-row prompt has all the context it needs because we concatenated the specific cells in.

## Constrained vs open-ended prompts

The single most useful trick is to constrain the output space. The same row, the same data, two prompt shapes, two utility levels.

| Prompt | What you get |
|---|---|
| `=AI("How is this campaign doing? Spend: " & F2 & " Revenue: " & G2)` | A two-sentence paragraph that varies per call. Useless in a column. |
| `=AI("Categorize this campaign's risk as low, medium, or high. Spend: " & F2 & " Revenue: " & G2)` | One word from a fixed list. Usable as a filter, a pivot dimension, a conditional format trigger. |

When the output space is one of three labels, the model returns one of those labels most of the time. When the output space is "explain this", the model returns prose. Spreadsheets want labels. Write your prompts that way.

Patterns that work in production:

- **Classification**: `low, medium, high` / `win, loss, push` / `high-value, low-value, ignore`
- **Sentiment**: `positive, negative, neutral`
- **Extraction**: `Extract the country code (2 letters)` / `Return just the platform name`
- **Yes/no**: `Does this look like a tracking pixel error? Yes or no`

### Combined example: AI() with TEXT() and ARRAYFORMULA awareness

You'll often format numbers before pasting them into a prompt. `TEXT()` (Track 1 lesson 7) makes the format explicit, which helps the model read it. And note what you cannot do: `ARRAYFORMULA` (lesson 1.2 and 1.10) does not work with `AI()`. The docs say AI cannot be nested inside other functions, which means no spilling array of AI calls. You drag instead.

```
=AI("Risk: low, medium, or high. Spend " & TEXT(F2,"$#,##0") & " Revenue " & TEXT(G2,"$#,##0"))
```

`F2` is `342.18`; the model sees `$342`. The formatting wins because the prompt now matches how a human would read the number, and the model is trained on human text.

## Combining cells into a prompt

The pattern `"Classify: " & F2 & " " & G2` concatenates strings so each row sees its own row's data. Three rules:

1. **Label what each cell contains.** `"Spend: " & F2 & " Revenue: " & G2` beats `& F2 & " " & G2`. Labels help Gemini read.
2. **Don't dump too many cells in.** Five values is fine; twenty is wasted context. The model loses signal as the prompt gets longer.
3. **Format numbers if the raw value is ugly.** `& TEXT(F2, "$#,##0")` makes the dollar formatting explicit. Helpful for prompts that ask about money.

## Defensive wrapping with IFERROR

AI() can fail. The call can time out, the workbook can hit its quota, the API can throw a transient error. Without `IFERROR`, the cell shows `#ERROR!` and any downstream formula that touches it propagates the error. `IFERROR` is covered in Track 1 lesson 14; here we apply it to the one function on your sheet that has a measurable per-row failure rate.

The defensive pattern:

```
=IFERROR(AI("Categorize: " & C2), "needs review")
```

Use `"needs review"` (or similar) as the fallback string so a human knows the row hasn't been classified yet. Never use `""` as a fallback because it makes failures invisible. Make the failure obvious so it gets fixed.

## Validating AI output with a sidecar formula

`IFERROR` catches the call that failed. It does not catch the call that returned `very high` when you asked for `low / medium / high`. Hallucinated labels are the more common production problem because they look like real values to a downstream `COUNTIF`. The defense is a sidecar formula in the next column over that checks each cell against the allowed set and flags drift.

## Non-determinism in practice

Two calls of `=AI("Sentiment of: " & A1)` can return `positive` and `neutral` in succession. The model is non-deterministic by design. The implications cascade:

- **A column of AI() outputs is a snapshot, not a function.** Reload the sheet a week later and some cells will have shifted.
- **Reconciliation between two reports fails when the column was AI-generated.** A dashboard that sums "high risk" rows will report a different number on Monday than on Friday if you re-ran the AI() formulas in between.
- **The "right" answer is the answer Gemini gave the first time you trusted it.** Once you trust a column, freeze it: copy the values and paste-as-values. That's the audit trail. Lesson 5.1 covers the freeze pattern; lesson 5.6 covers why you must.

If you need reproducibility, paste-as-values is the standard fix. If you need ongoing classification, accept the drift and verify weekly. The team's working rule: live AI columns never appear in stakeholder reports; only frozen copies do.

## Used in the wild

In the team's actual aggregator:

- **The risk column is AI() with a 4-label constrained prompt.** The team reviews the column manually every Monday, freezes it with paste-as-values, and then dashboards read from the frozen copy. The next week's classification overwrites the live column.
- **Translation of customer feedback runs through AI().** `=AI("Translate to English: " & E2)` on a column of Hebrew or Spanish feedback gives consistent enough translations to triage which threads need human follow-up.
- **Every AI() column in production has an IFERROR wrap with a `"needs review"` fallback.** Fallbacks bubble up in a dashboard scorecard so an unclassified row never silently disappears.
- **Numeric columns never use AI().** ROI, CPC, EPC, profit are all `SUM` and arithmetic. AI() is reserved for fuzzy text work where the return-as-text limitation isn't a tax.

## Pro pitfalls

- **Non-deterministic outputs across calls.** Two runs, two answers. Plan for it. Freeze with paste-as-values when the column matters.
- **`=AI()` in 5,000 rows hits the quota fast.** Estimate cost before dragging. A column of 60 calls is cheap. A column of 5,000 calls during peak hours can block the team's Gemini quota for hours, and the docs cap multi-cell runs at 350 cells per generate batch anyway.
- **Prompts that work on row 2 fail on row 50.** If row 50 has an empty Vertical, your prompt reads "Sentiment of this vertical name: " with nothing after the colon, and Gemini guesses. Guard with `IF(C2<>"", AI(...), "missing vertical")`.
- **Asking AI() to return a number.** Don't. Use `SUMIFS` or `COUNTIF`. AI() returns text; even when the text looks like a number, it isn't reliably one.
- **Asking AI() for "the best campaign".** Subjective prompts produce different answers every call. Define the criterion ("highest ROI", "lowest CPC") and use a formula instead.
- **Hallucinated labels.** A prompt that says "low, medium, or high" sometimes returns "very high" or "moderate". Validate the output before trusting it. The team writes a separate `=IF(REGEXMATCH(H2, "^(low|medium|high)$"), H2, "needs review")` in column I to surface label drift.
- **Trying to nest AI() inside another function.** The docs explicitly disallow it. `ARRAYFORMULA(AI(...))`, `IF(condition, AI(...), AI(...))`, `IFERROR(AI(...), AI(...))` are all unreliable. Keep AI calls at the top level of the formula.
